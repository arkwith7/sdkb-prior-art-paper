# CR-018 · JP 청구항 원문 확보와 일본어 분해 경로 (D-05 JP 축 · CR-017 ③에서 분리)

> 제출처: `~/Dev/sdkb` · 양식: 상류 CLAUDE.md §2 **1단계 요구정의**
> 근거: [DEFECT-LEDGER.md](DEFECT-LEDGER.md) §1.5(D-05 · 2026-08-15 갱신) · 논문 §6.2f 관측 3
> 우선순위: **P1** — 판단연결 도달성의 **전부**가 여기 걸려 있다(미도달 197건 = 100 % JP)
> 선행 관계: **CR-017과 독립**(그쪽은 있는 것을 전달, 이쪽은 없는 것을 만든다) ·
> ⓒ항은 **CR-003(D-05 `@ja` 라벨)과 합류 여부를 3단계에서 판단**한다

## 왜 별도 CR인가 — CR-017에 얹으면 안 되는 이유

CR-017은 *"새로 만들 자산 0 · 있는 것을 전달 가능한 형태로 투영"* 이다. 이 CR은 **새 수집 +
새 파서 + 어휘 확장**이라 성격이 정반대다. 두 개를 묶으면 전달만 하면 되는 작업이 수집 실패에
발목을 잡힌다. **CR-017의 성공기준 ③은 이미 KR·US 모집단으로 좁혀졌고**, 이 CR이 JP를 연다.

## 무엇이 막고 있었나 — 2026-08-15 실측 셋

| | 실측 | 함의 |
|---|---|---|
| **원천에 없다** | BigQuery `patents-public-data.patents.publications` 의 JP 공개 **19,020,011건(1990–2024) 중 `claims_localized` 보유 0건** · 전 연도 0.0 (실행 2회 · 약 US$1.57) | **BigQuery 는 이 축을 열 수 없다. 다시 두드리지 않는다** |
| **개념 브리지가 일본어를 못 읽는다** | `mappings/abox_term_aliases.json` 별칭 545개 중 **가나 포함 0개**(한글 108) | 청구항을 얻어도 `featureConcept` 는 **전부 0** 이 된다 |
| **의존 파서가 일본어 참조를 못 본다** | `_PARENT` 정규식이 `제N항`·`청구항N`·`claims N` 만 본다 · **`請求項` 은 두 분해 스크립트 어디에도 없다**(grep 0) | JP 청구항이 **전부 독립항으로 분류**된다 — 종속항 added-feature 가 §29② 판단의 초점이라는 설계가 JP 에서만 깨진다 |

**Google Patents 에는 실려 있다(실증).** `patents.google.com/patent/JP2007305947A/ja` 에
`<section itemprop="claims">` 로 **일본어 원문 청구항 3건 572자**가 있다. `/en` 은 같은 원문에
**기계번역을 병기**한다(2,200자). `robots.txt` 는 `Allow: /patent/` 로 이 경로를 허용한다.
**수집기는 이미 있다** — `enrich_unresolved.py:677 resolve_google_patents` 가 JP/US 라우팅으로
쓰이는데 **meta 태그(title·abstract·date)만 긁고 본문 청구항을 건드리지 않는다.**

## 1단계 요구정의

```
목적      : 일본어 선행기술을 한정요소 수준에서 다룰 수 있게 한다.

            지금 막혀 있는 것(하류 실측):
              · 판단연결 표본 584건 중 미도달 197건 = **전량 JP**
              · 그 197건의 고유 문헌은 **164건** (한 문헌이 여러 판단에 걸린다)
              · 코퍼스의 JP 문서 887건은 본문 중앙값 **809자**(KR 2,263 · US 6,228) —
                청구항 없이 **초록만**으로 색인돼 있다

            하류: 논문 §6.2f 관측 3(자원 결손이 두 번째 병목)의 처방 하나 ·
                  CR-017 ③이 KR·US 로 좁힌 도달성의 JP 축

입력      : ⓐ Google Patents `/patent/{id}/ja` — **164건**(최소 범위)
                 대상 목록 이관: `handoff/CR-018-jp-missing-docs.txt` (164행)
                 확장 후보는 코퍼스 JP 887건 (3단계에서 판단 · 비용은 요청 수뿐)
            ⓑ 기존 분해기 `decompose_corpus.py` + `llm_claim_validate.py`
                 (Bedrock Haiku 기본 · temperature 0 · seed 0 · 캐시키에 모델 해시)
            ⓒ 어휘 — 가나 표면형. **CR-003 과 합류 여부는 3단계 결정**

출력      : (1) 수집 원문 — gitignore 경로. **공개 트리에 넣지 않는다**
                 `check_public_release.py` 허용목록 **밖**으로 유지
            (2) `data/interim/claim_features.jsonl` 에 JP 행 추가 (기존 형식 그대로)
            (3) A-Box 재빌드 — `ClaimFeature` 증가분 · 새 술어 0 · 새 클래스 0
            (4) 수집 리포트 — 문헌별 `lookup_status` · 수집일 · 출처 태그
                 `google_patents_scrape_jp` (D-25 의 교훈대로 **서지 해소와 본문
                 확보를 한 칸에 뭉치지 않는다**)

성공 기준 : ① **수집** — 164건 중 청구항 확보 **≥ 90 %**. 미확보는 사유별로
               (`not_found` / `empty_claims` / `network`) 리포트에 남긴다.

            ② **결정성** — 같은 입력 → 같은 feature. LLM 캐시 적중 시 재호출 0,
               두 번 돌려 A-Box sha256 동일.

            ③ **일본어 분해가 실제로 일본어를 읽는가** — 확보분의 종속항 비율이
               KR·US 와 **같은 자릿수**다(현재 KR·US 종속 450,593 / 독립 143,485
               = 75.8 %). `請求項` 파싱이 안 되면 이 값이 0 % 로 나오므로
               **이 기준 하나가 ⓑ를 검증한다.**

            ④ **도달성(하류가 센 수)** — 판단연결 표본 **387/584 → ≥ 540/584**
               (164건 중 90 % 확보 시의 하한). 상류 카운트가 아니라 하류 재측정값.

            ⑤ **개념 통로는 숨기지 않는다.** ⓒ를 포함하지 않으면 JP 의
               `featureConcept` 는 **0 이며, 그 사실을 리포트에 명시**한다.
               ⓒ를 포함하면 JP 문서 개념링크 보유율 **0 % → ≥ 50 %**.

            ⑥ **하류 태스크 지표(§0.1 필수 · D-23 규율).**
               코퍼스 JP 문서의 본문이 청구항을 포함하게 되고, §6.2f 의
               정답 언어별 회수를 **JP 축에서 잴 수 있게 된다.**
               ⚠ *"JP 회수가 올라간다"* 가 **아니다** — 그것은 새 사전등록 아래의
                 새 실험 결과이며 이 CR 의 승인 조건이 아니다.

비목표    : ⓐ **기계번역 텍스트를 쓰지 않는다.** `/ja` 원문만 쓴다. `/en` 을 쓰면
               JP feature 만 번역문에서 나와 KR·US 와 원문 대칭이 깨지고,
               §6.2f 의 "번역 부재" 진단이 **오염된다.**
            ⓑ **청구항 원문을 재배포하지 않는다.** CR-015 의 공개 경계 그대로 —
               공개되는 것은 구조와 개념 IRI 뿐이다(CR-017 비목표 ⓐ와 같은 규율).
            ⓒ **WO·CN·EP 는 이번 범위 밖이다.** 같은 결손이지만(청구항 0)
               판단연결 미도달에는 걸리지 않았다. 필요해지면 별도로 판단한다.
            ⓓ **검색 설정·가중·토큰화를 건드리지 않는다** — 하류 §2.1 의 조건.
            ⓔ **원고 수치를 소급 수정하지 않는다.** §6.2f 표는 구 자원에서의
               관측으로 그대로 남는다(하류 §1-3).

파급      : A-Box 증가 + 코퍼스 본문 변경 → **코퍼스 서명이 바뀐다** →
            하류 §2.1 발동(새 사전등록 아래 무정지 전량 재측정).
            어휘는 ⓒ 포함 시에만 바뀐다(그 경우 CHANGELOG · 마이너 bump).
            T-Box 불변 · 새 술어 0 · 기존 IRI 불변.
```

## 약관과 수집 예절 — 3단계에서 코드로 고정할 것

- `robots.txt` 는 `Allow: /patent/` 로 대상 경로를 **허용**한다(2026-08-15 확인).
- Google 일반 약관은 자동화 접근을 권장하지 않는다. **이 저장소는 이미 같은 페이지를
  긁고 있으므로**(meta 태그) 새로운 범주가 아니며, 대상은 **164건 · 학술 이용**이다.
  판단은 사용자 몫이고, 이 CR 은 그 판단을 **문서에 남긴다.**
- 요청 간 지연 · 연락처를 담은 User-Agent · 재시도 상한 · 캐시(같은 문헌 재요청 0)를
  3단계 설계에 **코드로** 넣는다.

## 하류가 회신할 것

- 성공기준 ④의 **하류 재측정 도달성**(상류 카운트가 아니라)
- 코퍼스 서명 변화(sha256 전후) · JP 본문 중앙 길이 전후
- ⑤의 `featureConcept` 실측 — ⓒ 포함 여부에 따른 두 값
- 새 사전등록 아래 §6.2f JP 축의 **측정 가능 여부**(판정이 아니라 가능 여부)
