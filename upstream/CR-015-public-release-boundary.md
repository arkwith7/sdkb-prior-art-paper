## 0. 한 문장

**공개 예정 리포가 재배포하고 있는 KIPRIS 원문(초록 전문 · 청구항 1항 전문 1,000건)을 메타 +
Link-Only 로 내리고, 그 자리에 재인출 스크립트를 놓는다 — 원고 §10.3 이 이미 "재배포할 수
없다"고 선언했기 때문이다.**

---

## 1. 왜 이것이 투고 게이트인가

이 CR 은 자원 품질을 다루지 않는다. 다른 살아 있는 CR 여섯(CR-001A·002·003·005·006·009)은
**온톨로지를 더 좋게 만드는 일**이고 전부 투고 후다. 이것은 다르다 — **논문이 이미 한 약속을
지키는 일**이다.

| | 원고가 쓴 것 | 리포의 실물 |
|---|---|---|
| §10.1 | 데이터셋은 `github.com/arkwith7/semiconductor-knowledge-base` 에서 **CDLA-Permissive-2.0 으로 공개**된다 | 아직 비공개(HTTP 404) · 릴리스 태그 **0개** |
| §10.3 | **KIPRIS 원문(특허 전문·서지)은 학술이용 조건상 재배포할 수 없다** | `data/patents/raw/semiconductor_industry_rejected_patents.jsonl` 이 **초록 전문 + 청구항 1항 전문 1,000건**을 담고 커밋돼 있다 |

**두 문장이 같은 리포를 가리키는데 서로 반대다.** 심사자가 §10.1 의 URL 을 눌러 확인하면
그대로 드러나고, 그 순간 문제가 되는 것은 라이선스가 아니라 **원고의 신뢰성**이다.

## 2. 법무 자문은 이 경로에서 제외한다 (2026-08-09 · 사용자 결정)

상류 `docs/project/dataset_publication_risk_review.md`(2026-05-17)와 `dataset_rejected_patents_card.md`
§6 은 **SKKU 산학협력단·법무팀 자문 후 (A)/(B)/(C) 중 택일**로 적혀 있다. **이 전제를 제거한다** —
그 검토는 다른 사업 맥락에서 진행되던 것이고 지금은 해당 사항이 없다.

**자문이 필요 없는 이유는 결정이 이미 내려져 있기 때문이다.** 원고 §10.3 이 *"재배포할 수 없다"*
고 쓴 시점에 선택지는 (B) 하나로 좁혀졌다. 리포를 그 문장에 맞추는 것은 **법적 판단이 아니라
정합성 작업**이다. 따라서 **(B) 확정**으로 바로 간다.

- ~~(A) 본 형태 그대로 학술 목적 재배포~~ — 원고 §10.3 과 충돌하므로 선택 불가
- **(B) 본문 재배포 불가 → 메타 + `ground_truth_*` + URL Link-Only** ← **확정**
- ~~(C) 초록만 공개, 청구항은 Link-Only~~ — 초록도 KIPRIS 원문이므로 §10.3 과 충돌

## 4. 이력 처리 — 되돌릴 수 없으므로 방법을 먼저 정한다

**파일을 지우는 커밋만으로는 공개되지 않는다.** 대상 파일은 커밋 2개에 걸쳐 있고, 리포가
공개되는 순간 누구나 과거 커밋에서 원문을 받을 수 있다.

| 방법 | 장점 | 대가 |
|---|---|---|
| **ⓐ history 재작성** (`git filter-repo`) — 두 커밋에서 해당 경로만 제거 | 이력의 연속성 유지 · 커밋 메시지·기여 기록 보존 | **모든 커밋 해시가 바뀐다** — 하류 `PROVENANCE.json` 의 상류 커밋 참조(`212fe62` 등)와 원고 §6·§9 의 상류 해시 인용이 **전부 무효**가 된다 |
| **ⓑ orphan 공개본** — 현 트리에서 원문을 뺀 상태로 새 루트 커밋 1개를 만들어 공개 | 기존 이력·해시 **전부 불변** · 원고 인용이 살아 있다 | 공개본에 개발 이력이 없다 |

**ⓑ 를 권고한다.** 이유는 하나다 — **ⓐ 는 원고를 깨뜨린다.** 원고와 하류 `PROVENANCE.json` 은
상류 커밋 해시를 **판정의 출처**로 인용하고 있고(§6.7 의 `39855bb`, §9.1 의 `2839afb`,
스냅샷의 `212fe62`), 해시가 바뀌면 그 인용이 전부 가리키는 곳을 잃는다. 그것은 §1-3 이 막는
"판정 기록의 소급 훼손"과 실질이 같다.

**ⓑ 를 택하면 개발 이력은 비공개 리포에 남고, 공개본은 "릴리스 vX 시점의 상태"가 된다.**
원고 §10.1 이 이미 *"논문이 명시한 릴리스 태그를 체크아웃해야 한다"* 고 쓰고 있으므로 서술도
그대로 맞는다.

### 4.1 확정 — ⓑ orphan · 그리고 **공개본은 새 리포다** (2026-08-09 · 사용자 결정)

**2단계 분석이 초판이 몰랐던 사실을 하나 찾았다 — 이력은 이미 원격에 있다.**

```
refs/heads/main                                  da745ef   ← b3969b8·4be52e1 포함
refs/heads/feat/prior-art-claim-feature-ontology 212fe62   ← 하류가 핀한 커밋
refs/heads/docs/reorg-dataset-vs-project         786218c
refs/heads/feat/sparql-ontology-matching         4cdd4a6
refs/pull/1/head                                 4cdd4a6
```

원문을 담은 커밋 둘은 **네 브랜치 전부**에 있고 전부 푸시돼 있다. 따라서 **기존 리포를 공개로
전환하면 orphan 브랜치를 만들어도 과거 커밋에서 원문을 받을 수 있다** — 성공기준 ②가 원리적으로
닫히지 않는다. `refs/pull/1/head` 는 일반적인 방법으로 지워지지도 않는다.

**결정: 공개본은 새 GitHub 리포에 orphan 루트 커밋 1개로 만든다.**
`arkwith7/semiconductor-knowledge-base`(현 origin)는 **개발용 비공개**로 남는다.

| | 귀결 |
|---|---|
| 커밋 해시 | **전량 불변** — 하류 `PROVENANCE.json`·원고 §6.7(`39855bb`)·§9.1(`2839afb`)·스냅샷(`212fe62`) 인용이 전부 살아 있다. ⓑ 를 택한 이유 그대로다 |
| 원고 §10.1 | **URL 을 새 리포로 교정해야 한다.** §10 은 태그·DOI 가 아직 `[최종 릴리스 후 기입]` 이므로 같은 편집에서 함께 닫는다 |
| 공개본 내용 기준 | **`212fe62` 트리**(사용자 결정) — 하류가 실제로 vendor 했고 원고가 인용하는 상태. main 은 14커밋 뒤에 있다 |
| 비공개 리포 | 정본 jsonl 을 **계속 추적한다**. 재배포하지 않으므로 문제가 아니고, 공개 트리는 생성기가 따로 만든다(§3 출력 (1)) |

| 원본 데이터셋과 바이트 동일 | **아니다** — sha `e1b6efab…` 대 정본 `fc142f51…` |
| `ingest_rejected_patents.py` | 완주 — meta 1,000행 · IPC 4,065 · prior-art 엣지 6,692 |
| `build_abox_patents.py` | 완주 — **33,934 트리플**(정본 33,931) · linked 977 · orphans 23 (둘 다 동일) |

**바이트 불일치의 정체(분모 1,000).** `abstract` **308**(공백 위치 245 · 본문 상이 60 ·
복원이 더 김 3) · `claim1` 13(`"1. "` 접두 4 · 기타 9) · `claims_full` 3(항 수 동일 · 본문만).
원인은 복원기가 docstring 에 **미리 적어 둔 그대로**다 — 원본은 초록을 검색 응답 `astrtCont`
에서 먼저 가져왔고 복원기는 출원번호로 서지만 조회한다. 그 차이가 개념 브리지를 타고
A-Box 에서 **+3 트리플**로 나타났다(Process +2 · Skill +1 · Device +1 · Material −1).

**이 실행이 실제로 답한 것.** *"공개본만으로 무엇이 재현되는가"* 의 경계가 처음으로 그어졌다 —
특허 층은 0.009 % 오차로 재현되고, 청구항 층은 입력이 없어 재현되지 않는다. 후자는 결함이
아니라 **KIPRIS 조건이 강제하는 구조적 한계**이며, 그래서 ③-b 를 "미달"이 아니라 **명세**로 적는다.

**이것은 D-19 계열의 일곱 번째 사례이기도 하다** — 발행한 것과 소비 가능한 것이 다르다.
다만 이번 소비자는 하류 코드가 아니라 **논문 독자**이고, 원인이 우리 실수가 아니라 라이선스다.
그래서 CR 을 새로 발행하지 않고 **명세로 싣는다**(§0.4 의 FTO 와 같은 형태).
