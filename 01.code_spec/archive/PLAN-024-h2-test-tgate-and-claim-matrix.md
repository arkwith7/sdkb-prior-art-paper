## 0. 무엇이 문제였는가

**관측 1 (2026-07-28).** 원고 §1.4 는 H2 를 **동결 테스트셋** 기준으로 사전등록했다:

> H2(승인 안전성). T-gate 가 승인한 델타는 **동결 테스트셋** Recall@100 에서 비열등하고

그런데 현존하는 유일한 판정 아티팩트 `data/processed/tgate_report.json` 은 `"split": "dev"` 다

사전등록 위반(CLAUDE.md §1-3)이다.** 표 6.3·부록 B 의 `[실험 후 기입]`·"미실험"은 정확한 기록이었다.

**관측 2.** 반면 H3·H4·H5 는 확증 분할에서 판정이 끝났는데(커밋 `5e65fa5` · §6.2–6.4)
**부록 B(`:1352–1356`)의 다섯 행은 여전히 "미실험"** 이다. 표 6.6 행만 N5e 에서 시정됐고 나머지는
남았다. 심사자가 §6 보다 먼저 보는 표가 저자 자신의 결과를 부정하고 있다.

**주장하지 않는 것 (선언).**
- **새 검색을 돌리지 않는다.** 확증 분할 run 7종은 봉인 개봉 1회(`5e65fa5`) 때 이미 산출됐다.
  이 계획은 **동결 run 재판정**이며 순위 산출·모델·임계값 재선택이 0 이다.

  W3 에서 동결됐고 호출 인자로 바꿀 수 없다(설계상 불가).
- **dev 판정을 소급 변경하지 않는다.** `tgate_report.json`(dev)은 그대로 두고 확증 판정은 별도
  경로에 쓴다. dev Accept=1 은 W3 의 기록으로 보존된다.
- **H2 판정으로 H3 의 판정을 바꾸지 않는다.** 비열등성(T1)과 우월성(H3)은 다른 기준이다.

## 1. 동결 규칙 A — 판정 대상 델타 (실행 전 고정)

확증 분할 T-gate 를 **두 델타에 대해 돌리고 둘 다 보고한다.**

| | 델타 | 지위 | 근거 |
|---|---|---|---|
| **주** | **P1 vs B3_rrf** | H2 의 판정 근거 | W3 에서 ΔG 로 동결된 델타(PLAN-019 §5). dev 판정과 같은 델타여야 dev↔test 비교가 성립한다 |
| **부수** | **P0★ vs B3_rrf** | 함께 보고 (판정에 사용하지 않음) | P0★ 는 **주 사전지정 검색 시스템**이다. 유의성(H3)에서 미달한 시스템을 게이트 판정에서만 빼면 "유리한 델타만 게이트에 걸었다"는 지적을 받는다 |

- **부수 델타의 결과가 어떻게 나오든 주 판정을 교체하지 않는다.** P0★ 가 통과하면 "비열등성은
  유의성과 다른 기준"의 예시로, 실패하면 **불리한 결과로** 보고한다(§8 · §1-2).
- 비열등성은 우월성이 아니다 — P0★ 의 test 우월성 미달(Δ+0.0319 · p=0.181)은 T1 통과와 모순되지
  않으며, 그 사실 자체를 §6.3 각주로 적는다.

## 2. 동결 규칙 B — 불리한 결과의 사전 처리

**결과를 보기 전에** 다음 세 경우의 서술을 고정한다.

| 사건 | 사전 확정 처리 |
|---|---|
| T2 하위집단이 `n ≥ 20`(T2_MIN_N) 미달로 신뢰집단이 부족 | 판정을 **"표본부족"** 으로 적고 지지로 세지 않는다. 확증 분할은 198 질의라 **충분히 예상되는 결과**다. MIN_N 을 낮춰 집단을 늘리지 않는다 |
| T1 LB95 ≤ −ε | **H2 기각**으로 적는다. ε 을 넓히지 않는다 |
| dev 는 통과인데 test 가 실패 | 두 판정을 나란히 싣고 **test 를 판정으로 삼는다**(사전등록이 test 다). dev 통과를 근거로 완화하지 않는다 |

T3 는 그래프 판정이라 분할과 무관하다 — dev 실행과 **같은 값이 나와야 하며**, 다르면 결정성 결함이므로
판정 전에 원인을 규명한다(기준 세대 `g0` · 대상 `graph_v1` · 28-CQ 체제 불변).

## 3. 동결 규칙 C — 부록 B 에는 수치를 넣지 않는다

부록 B 의 상태 열을 §6.3 수치의 **복사본**으로 채우면 같은 수가 두 표에 살게 되고, 한쪽만 갱신되는
표류 경로가 생긴다 — **N5e 에서 실제로 발생한 결함의 재현이다.**

- 부록 B 상태 열은 **판정어 + §6 참조**만 담는다(예: `기각 → 태스크 결합 (§6.3·§7.6)`).
  **새 수치를 넣지 않는다.** 수치의 집은 §6.3 하나다.
- "최종 원고에서 필요한 것" 열은 지표 이름이므로 그대로 둔다.
- **진짜 미실험 행은 미실험으로 남긴다** — `미인용 상위 후보 일부가 관련`(전문가 표본 판정)은
  N9(선택)이며 수행하지 않았다. 표를 깨끗하게 보이려고 판정을 만들지 않는다.
- §6.3 탐색적 2행(운용 효율 · 의미 도달성)의 `[실험 후 기입]` 은 **"미수행"** 으로 확정 표기한다.
  자리표시자는 "곧 채운다"는 뜻인데 채우지 않기로 했으므로 사실과 다르다.

## 4. 동결 규칙 D — 재발 차단 계약 (테스트)

N5e 가 생성기에 걸었던 계약을 부록 B 에도 건다. `tests/test_appendix_b_consistency.py` 신설:

1. **판정 있는 가설이 부록 B 에서 "미실험"이면 실패.** §6.3 판정표에서 `[지지/기각/표본부족]`
   자리표시자가 아닌 판정어를 가진 가설 라벨(H1·H1′·H1″·H2·H3·H4·H5)을 뽑아, 부록 B 의 대응 행이
   "미실험"이면 에러.
2. **부록 B 행에 소수점 수치가 있으면 실패.** 규칙 C(수치 단일 출처)를 기계로 강제한다.

테스트는 원고 파일을 읽어 판정한다 — 사람이 두 표를 눈으로 맞추는 절차를 남기지 않는다.

### 7.1 확증 분할 T-gate — H2 지지

**주 델타 P1 vs B3** (`data/processed/tgate_report_test.json` · 198질의 · boot 10000 · seed 20260726):

### 7.3 실행 중 편차 (2건)

1. **규칙 D-2 의 적용 범위를 상태 열로 좁혔다.** 동결문은 "부록 B 행에 소수점 수치가 있으면 실패"라고
   적었으나, 주장 열에는 `노드 도달성 95.3%`·`의미 도달성 54.6–70.5%` 같은 **자원 수치**가 정당하게
   들어 있다. 표류가 생기는 곳은 실험 결과를 옮겨 적는 **상태 열**이므로 검사를 그 열로 한정했다.
   추가로 `§6.3`·`표 6.6` 같은 **절 참조는 수치가 아니라 주소**이므로 검사 전에 제거한다.
   규칙의 의도(수치의 단일 출처)는 유지되며, 범위만 좁아졌다.
2. **원고 3개 문장을 함께 고쳤다** — 이 작업이 참으로 만든 문장들이다: 부록 H "개발 분할에서
   실행된다" → "개발·확증 두 분할" · 부록 H "H2 성능 주장을 기술하지 않는다" → 판정 기록 + 그때
   그렇게 적었던 이유 · §10 재현성 파일 목록에 확증 분할 아티팩트 2종 추가 · 부록 H "수치 미산출"
   행의 C3 서술. 계획에 없던 편집이나, 고치지 않으면 §6.3 과 모순된다.
