## 0. 무엇이 문제였고, 무엇을 주장하지 않는가

**관측 (2026-07-28).** CQ 러너가 읽는 그래프는 `graph_v0.ttl`(105,588 트리플) 하나이고 거기엔
청구항 인스턴스가 **0건**이다(타입별 전수 계수). 청구항 층은 존재하되 **사이드카**
`central_axis.oxstore`(11,606,318 트리플 · Claim 586,567 · ClaimFeature 1,289,300 ·
dependsOnClaim 483,390 · PriorArtJudgment 635)에만 있고, 게이트는 그것을 조회하지 않는다.

**그래서 게이트는 C2 검색 실험이 딛고 선 층을 한 번도 심문하지 않았다.** P1(FeatureCoverage)은
`featureText` 임베딩 102만 건 위에서 도는데(§6.3), 그 층의 회귀를 잡는 검사가 없다. 원고
[REF-001 §9.1]은 이 공백을 "청구항 파싱·기술적 대비 필요 — **범위 밖**"으로 정직하게 적어
두었다. 이 계획은 그 공백을 **측정으로** 닫는다.

**주장하지 않는 것 (선언).**
- **L3 감도가 오른다고 주장하지 않는다.** 결함주입기(`analysis/faults.py`)는 격리본 **TTL 하나**에
  주입하고 `run_cqs(faulted.ttl)`로 판정한다. 사이드카에는 결함이 주입되지 않으므로 청구항 CQ는
  결함주입에 **구조적으로 무반응**이다. N5d 의 원래 동기("pa 5개의 둔감함 해소")는 **달성되지 않는다.**
- **결함주입 결과를 재판정하지 않는다.** 표 6.5·6.5v2·6.5v3(H1·H1′·H1″)은 28-CQ 체제의 산출이며
  **그대로 둔다.** 같은 데이터의 4회차 판정은 신규성을 더하지 않고 p-해킹 의심만 키운다.
- 인스턴스마다 1.8GB 스토어를 격리 복제하는 설계는 **하지 않는다**(오염 규율·비용 양쪽에서 부적절).

## 1. 동결 규칙 A — 희석 금지 (사전등록 핵심)

**순진한 (a′)는 게이트를 약화시킨다.** 사이드카 CQ 는 시험 대상 그래프에 **무반응인 상수항**이다.
이것을 L3 분모에 넣으면:

```
현행:  pa 5개 중 1개 실패 → L3 통과율 0.800
순진:  pa 8개 중 1개 실패 → L3 통과율 0.875     ← 항상 통과하는 3개가 실패를 희석한다
```

**검출력이 떨어진다.** 이는 PLAN-022 §0.1 에서 층 분리를 정당화한 유일한 근거(검출력 불변량)를
정면으로 위반한다. 따라서 **동결한다:**

```python
# config.py (신설)
CQ_TARGETS = ("graph", "sidecar")   # .rq 헤더 `# target:` · 기본 graph
# L3·T3 판정 분모는 target == "graph" 인 CQ 로 한정한다 — 사이드카 CQ 는 게이트가 아니라 측정이다.
```

- **L3 분모 불변(pa 5개) · T3 분모 불변(em·tf·core 23개).** 승인식 `Accept` 는 한 글자도 바뀌지 않는다.
- 사이드카 CQ 는 **세대 아티팩트와 표 6.6 에 별도 항목**으로 보고한다(측정 운용). 이는 CLAUDE.md §5
  가 어휘 검증 커버리지를 "게이트가 아니라 측정"으로 둔 것과 같은 규율이다 — 임계값을 세우면
  통과율을 올리려고 CQ 를 지어내게 된다.
- **그럼에도 무의미하지 않다.** 사이드카는 상류 SDKB 재벤더 시 바뀔 수 있고(PROVENANCE 핀
  `d578bf3`), 그 회귀는 **세대 간 비교**로 잡힌다. 델타 단위 게이트가 아니라 **세대 단위 감시**다.

### 1.1 착수 전에 선언하는 예상 결과 (결과를 보고 고치지 않는다)

| 예상 | 근거 | 만약 빗나가면 |
|---|---|---|
| 신설 CQ 3개 전량 비공허 | 착수 전 스키마 관측: 판단 5,917 · 독립항 3,117 · 종속항 체인 12,054 (§2) | 공허하면 **그대로 보고**하고 해당 CQ 는 채택하지 않는다 |
| L3·T3 통과율 **불변** | 분모가 target=graph 로 한정됨 | 달라지면 구현 오류 — 즉시 중단 |
| 결함주입 매트릭스 불변 | 재판정하지 않음 | — |
| pa 스위트의 결함 감도 **불변** | 사이드카 무반응(§0) | 오르면 그게 오류다(결함이 사이드카에 닿았다는 뜻) |

## 2. 동결 규칙 B — 신설 CQ 3개와 도출 근거

**도출은 태스크 명세에서만 한다.** 어느 결함이 빠져나갔는지는 보지 않는다 — 결함 매트릭스에
맞춰 CQ 를 고르면 W4b 의 τ 조작과 같은 범주다. 근거는 REF-001(소부장 IP-R&D 실무 정본)이다.

| CQ | 질문 | 도출 근거 | 대상 술어 | 착수 전 관측 |
|---|---|---|---|---:|
| **CQ29** | 어느 **청구항**이 어느 선행기술로 어떤 근거에 의해 거절됐는가 | REF-001 §7.1 단계 8(핵심특허 분석) · §4 방어기법 "**심사이력 검토**". 현행 CQ09 는 **특허 수준**에서 멈춘다 | `PriorArtJudgment` → `aboutClaim`·`overPriorArt`·`onGround` | 5,917 |
| **CQ30** | 거절특허 **독립항의 한정요소**는 무엇인가 (회피설계의 출발점) | REF-001 §4 "**회피 설계**(design-around)" · §9.1 이 "범위 밖"으로 적어 둔 바로 그 항목 | `Claim[isIndependent=true]` → `hasFeature` → `featureText` | 3,117 |
| **CQ31** | 종속항 계층이 살아 있는가 (축소 실시태양 = 무효 대비 방어선) | REF-001 §4 "**비침해 논리 개발**·무효 조사" | `dependsOnClaim` 체인(rej_) | 12,054 |

- 전부 `# suite: pa` · `# target: sidecar` · `# monotone: up` · `# expect-min: 1`.
- **어휘 발명 0** — 위 술어는 전부 SDKB 실물(`sdkb-patent.ttl` TBox)에 있다(CLAUDE.md §1-6).
- **비공허 관측은 스키마 확인이지 결과 조율이 아니다.** 착수 전에 셌고 그 값을 여기 적어 둔다 —
  숨기면 "돌려보고 되는 것만 채택했다"와 구분되지 않는다.

## 3. 동결 규칙 C — 결정성·출처·실패 규율

1. **사이드카 스토어가 없으면 에러다.** 조용히 건너뛰면 분모가 소리 없이 바뀐다 — 스위트 라벨
   누락을 에러로 처리한 것과 같은 규율(`cq_runner` §판정).
2. **세대 아티팩트에 사이드카 출처를 핀한다** — `PROVENANCE.json` 의 `sdkb_commit`·source sha256 을
   기록한다. 사이드카가 바뀌었는데 세대 비교가 조용히 진행되는 일을 막는다.
3. **엔진.** 사이드카는 oxigraph 온디스크 전용이다(rdflib 는 OOM · 메모리 `central-axis-use-oxigraph-ondisk`).
   `--verify-engines` 는 target=graph CQ 만 대조하고, 사이드카 CQ 는 **"엔진 고정"으로 명시 보고**한다
   (조용히 빼지 않는다).
4. **세대 재동결.** CQ 집합이 바뀌므로 기존 아티팩트(`cq_g0.json`·`cq_graph_v1.json`)는 **덮어쓰지
   않고** 새 라벨로 동결한다 — 표 6.6 의 이력이 소급 변조되면 그 표의 존재 이유가 없어진다.
5. **읽기 전용.** 사이드카 스토어에 쓰지 않는다. 결함주입은 사이드카를 건드리지 않는다.

## 6. 실행 중 편차 기록 (2026-07-28 실행 후 기입)

1. **CQ31 의 결과행이 착수 전 관측치와 다르다 — 단위 차이다.** §2 표에 적은 12,054 는
   `dependsOnClaim` **엣지 수**이고, CQ 결과행은 **4,906**(부모 청구항으로 GROUP BY 한 행 수)이다.
   비공허 판단은 불변이나, 계획서의 숫자를 그대로 결과로 읽으면 어긋나므로 여기 남긴다.
   (CQ29 5,917 · CQ30 3,117 은 관측치와 일치.)
2. **`run_cqs(targets=...)` 인자를 신설했다** — 계획에 없던 코드 변경이다. 쓰는 곳은 둘뿐이며
   **게이트 경로는 쓰지 않는다**(분모 축소 우회로가 되므로): ① 사이드카 스토어(gitignore·1.8GB)가
   없는 환경의 테스트 ② 아래 3.
3. **`analysis/faults.py` 의 `run_cqs` 호출 4곳을 `targets=("graph",)` 로 고정했다** — 계획 §0 의
   "결함주입을 재판정하지 않는다"를 **재현성 수준에서 강제**하기 위함이다. 고정하지 않으면 CQ 를
   늘린 뒤 `make faults` 가 동결된 28-CQ 체제와 다른 분모로 돌아 표 6.5 계열이 재현되지 않는다.
   결함은 사이드카에 주입되지 않으므로 결과에는 영향이 없다.
4. **세대 라벨은 `g0_cq31`·`graph_v1_cq31`** 로 붙이고 기존 `g0`·`graph_v1` 아티팩트는 그대로 뒀다
   (계획 §3-4). 표 6.6 은 4행이 되며, 뒤 두 행이 새 그래프가 아니라 **같은 그래프의 31-CQ 재동결**
   임을 §6.6 본문에 명시했다.
