## 0. 왜 이 실험인가

W3 에서 T-gate 는 코드로 존재하게 됐고 동결 델타 하나(P1 vs B3)에서 Accept=1 을 냈다. 그러나
**초록불은 판별력의 증거가 아니다.** 게이트가 아무것도 못 잡는 게이트여도 초록불은 뜬다. H1
(게이트 판별력)은 통제된 결함을 넣어 "어느 층이 이걸 잡는가"를 봐야만 검정된다. 특히 C3 의
핵심 주장 — **교차 태스크 결함은 T3 만이 잡는다** — 은 이 실험 없이는 근거가 없다.

## 2. 동결 설계

### 2.1 결함군 12종 (원고 §4.10 표 그대로 · F15 동결)

`validate/fault_inject.py` · `--list` 로 확인. 강도 1%/5%/10%, `n = max(1, round(rate·N))`.
**하한 1** 은 Skill 12개·`hasSubprocess` 38개처럼 모수가 작은 축에서 1% 가 0 이 되어 "결함 없는
결함 주입"이 되는 것을 막는다 — 결과를 보기 전에 고정했다.

시드는 `sha256(fault|rate|rep)` 다. 파이썬 내장 `hash()` 는 프로세스마다 달라져 재현이 깨진다.

### 2.2 층별 검출 판정 (사전 정의)

| 층 | 검출 조건 |
|---|---|
| L0 | 산출물 mtime 이 입력 스냅샷보다 낡음 |
| L1 | SHACL(graph shapes) 비적합 |
| L2 | HermiT 비일관 |
| L3 | 전 스위트(pa 포함) CQ 통과 수 < 정상 그래프(27/28) |
| 누출 | 그래프 누출 표면 **G-1** 위반>0 또는 **G-3** 이 정상 기준선 초과 |
| T1 | LB₉₅(ΔR₁₀₀) ≤ −ε (ε=0.02) |
| T2 | max_s drop_s ≥ δ (δ=0.05) |
| T3 | {em,tf,core} 통과율이 g0 세대보다 하락 |

**최초 검출층** = L0→L1→L2→L3→누출→T1→T2→T3 순 첫 True.
**H1 판정** = 교차결함(F11·F12)이 T3 에서만 검출된 인스턴스 비율 + 결함 단위 대응 McNemar
(L0–L3 검출 vs T-gate 검출, 불일치쌍 <25 면 정확 이항검정).

### 2.3 누출 감사의 그래프 층 신설 (G-1·G-2·G-3)

기존 누출 감사(L-1·L-2)는 **컬럼 이름**을 본다. 그런데 F10 은 정답 간선을 개념 링크로 *위장*
하므로(`hasPriorArtExaminer` 대상을 `realizesProcess` 객체로) 이름 검사를 그대로 통과한다.
이름이 아니라 **모양**을 봐야 한다.

- **G-1** 개념 술어의 객체가 문서(Patent/RejectedPatent/CitedPatent) 타입인 건수. 정상 **0**.
- **G-2** 금지 술어가 개념 링크 술어로 쓰였는가. 구조적으로 **0**.
- **G-3** 질의의 개념 집합이 자기 정답 문서의 개념 집합을 통째로 포함하는 (질의,정답) 쌍 수.
  정상 그래프에서도 **552쌍**(우연한 포함)이라 절대 임계로 못 쓴다 — **같은 기준 그래프 대비
  증가**로만 판정한다(통계가 아니라 차분).

### 2.4 주입 범위 — 형식층은 G₀, 성능층은 합집합

**착수 후 실측으로 드러난 설계 결함과 그 수정(결과를 보기 전).** 개념 링크 81,504건 중 G₀ 는
9,184건 = **11.3%** 뿐이다. G₀ 에만 10% 를 주입하면 검색이 보는 자원의 1.1% 만 오염돼 T1 이
둔감해지고, 그 둔감함은 **게이트의 성질이 아니라 주입 범위의 산물**이 된다(실측: F05 10% 를
G₀ 에만 넣었을 때 Δ +0.0425 → 변화 없음, 합집합에 넣었을 때 **+0.0315** 로 반응).

→ 형식층(L0–L3·T3)은 G₀ 사본에서, 성능층(T1·T2)은 **G₀∪G₁∪G₂ 합집합**에서 판정한다. 결함
사양·강도·시드는 같다. 합집합 오염본은 디스크에 쓰지 않는다(인스턴스당 ~370MB × 126 = 47GB).

### 2.5 재사용하는 것과 다시 만드는 것

| 자원 | 처리 | 근거 |
|---|---|---|
| 텍스트 팔 run(B0·B2·B3)·색인·임베딩 | **동결본 재사용** | 결함군 12종 중 청구항 텍스트·임베딩을 건드리는 것이 없다. 비용 절감이자 통제(텍스트 변동이 T1 판정에 섞이지 않는다) |
| FeatureCoverage 성분 | **1회 계산 후 캐시** | `FeatureCoverageIndex` 는 인스턴스당 최대 RSS **24.8GB** — 126 인스턴스 병렬은 즉시 OOM. FC 는 결함과 무관한 상수라 재사용이 근사가 아니라 정확하다 |
| 개념·IPC·CPC·축·계층 뷰 | **매 인스턴스 재유도** | 결함이 실제로 바꾸는 것이 이것뿐이다 |

**정합성 증명:** `make faults-fc` 가 정상 뷰 + FC 캐시로 P1 을 재구성해 **동결 P1 run 과
top-100 이 197/197 질의에서 일치**함을 확인한다(불일치 1건이라도 있으면 실험 중단). 즉 실험
경로는 정본 파이프라인과 같은 것을 계산한다.

### 2.6 비용 — GPU 는 해당 없음 (사용자 질의 2026-07-28)

인스턴스당 실측: L2 HermiT 55초(지배적) · L1 SHACL 16초 · L3/T3 CQ 2.4초 · 합집합 적재 11초 ·
전체 96초 · 최대 RSS 1.57GB(FC 캐시 적용 후).

**전량 기호 추론·그래프 순회라 GPU 가속 대상이 아니다.** RTX 5090 24GB 가 있어도 붙일 곳이
없다. 유일한 지렛대는 24코어 CPU 병렬(워커 10). GPU 가 이득일 지점(임베딩·번역)은 전부
**동결된 사전등록 항목**(F12 Titan v2 · Haiku 번역)이라 교체하면 이미 산출된 C2 결과가 무효가
된다 — 비용을 아끼자고 동결을 깨지 않는다.

## 3. 오염 격리 규율 (사용자 요구 · `validate/quarantine.py`)

> "이물 주입 전 오염되지 않은 것은 안전한 곳에 보관하고, 실험용은 실험용대로 관리해 오염된
> 실험용이 향후 사용되지 않도록 하라."

| 장치 | 구현 | 파기 조건 |
|---|---|---|
| **정본 봉인** | 실험 전 정본 산출물 전량 sha256 → `data/PRISTINE.json`. 주입 대상 G₀ 는 `data/pristine_backup/` 에 **실복사** | — |
| **무결성 재검증** | 인스턴스마다 `verify_pristine(strict=True)`. 한 바이트라도 다르면 `PristineViolation` 예외로 **즉시 중단** | 오염이 한 인스턴스에 갇힌다 |
| **격리 구역** | 모든 결함 산출물은 `data/quarantine/<run>/<label>/`. 디렉터리마다 `_CONTAMINATED.json` 스탬프(결함사양·시드·커밋) | gitignore — 커밋 불가 |
| **재사용 차단** | `assert_pristine(path)` 가 격리 경로·오염 스탬프를 감지하면 `ContaminationError`. 스탬프는 **복사해 빼돌려도 따라간다**(형제 파일 검사) | 우회 인자 없음 |
| **사후 잠금** | 배치 종료 시 격리본 전량 읽기전용(0444) + `LEDGER.jsonl` 감사 기록 | 덮어써서 이력이 사라지지 않는다 |
| **복원** | `quarantine.restore(name)` — 수동 호출만(자동 복원은 사고를 숨긴다) | — |

계약은 `tests/test_fault_inject.py` 17건이 지킨다(격리 경로 판정·스탬프 전이·정본 변조 시 예외·
백업 실물 존재·정상 델타가 결함 분모에 안 섞임).

## 4. 위양성률의 분모 — 설계 중 발견한 공허성

승인안은 "실제 병합 델타(G₀→G₁)의 층화 부분델타 20개"였다. 구현 중 **T1·T2 에 대해 구조적으로
공허함**이 드러났다: 검색이 보는 뷰는 이미 G₀∪G₁∪G₂ 이고 그 트리플들은 **이미 G₁ 에 있다** —
합집합이 변하지 않으므로 성능층은 아무것도 보지 못하고 위양성률이 자동으로 0 이 된다.

→ 분모를 둘로 나눴다. **결과를 보기 전의 수정**이며 그대로 보고한다.

- **N01 실제 병합 부분델타** — 형식층(L0–L3·T3)의 위양성만 잰다. 성능층에 공허함을 명시.
- **N02 의미보존 보강** — 기존 `skos:prefLabel` 을 `altLabel` 로 복제. 합집합에도 새 트리플이라
  **T1·T2 가 실제로 판정에 참여**한다. 의미를 바꾸지 않으므로 어느 층도 거부하면 안 된다.

한계(공개 대상): N02 는 실제 보강의 한 종류일 뿐이고, 미공개 실제 보강분을 홀드아웃해 재는 것이
더 강한 설계다. 그런 홀드아웃이 없다는 것이 현재 자원의 제약이다.

## 5. 사전에 공개하는 예상 약점 (결과를 보기 전 기록)

1. **CQ 28개 중 26개가 `expect-min: 1`** — 즉 "결과행 ≥1" 존재 검사다. 결함이 CQ 를 **0행으로
   만들어야만** L3·T3 가 반응한다. 1–10% 강도에서 T3 가 아무것도 못 잡을 가능성이 높다. 그
   경우의 처방은 **CQ 세분화**(부록 F)이지 스위트 재배치가 아니다(PLAN-019 §4.1 동결).
2. **TBox 에 `owl:disjointWith`·카디널리티 제약이 0개**(실측). L2 의 검출 표면 자체가 거의
   비어 있어 F03 이 미검출로 나올 수 있다. 그것은 주입 실패가 아니라 **관측**이다.
3. **T1 의 실효 민감도.** T1 은 결함본 P1 을 정상 B3 와 비교하므로, 온톨로지 이득(+0.04)을
   전부 까먹고 추가로 ε=0.02 를 넘겨야 발화한다. 결함이 웬만큼 커도 T1 은 통과할 것이다.
4. **재랭크 천장.** 결함이 B3 풀 밖 문서에만 영향을 주면 T1 은 원리적으로 못 본다(§7.3).

이 넷은 전부 **제안법에 불리한 방향**이며, 그렇게 나오면 그렇게 보고한다(CLAUDE.md §1-2·§8).

## 8. 실측 결과 (2026-07-28 · dev · `data/processed/fault_matrix.json`)

### 8.1 H1 — 기각

| 판정 기준 | 결과 | 충족 |
|---|---|---|
| 교차결함 T3 단독검출 | **0/18** | ✗ |
| McNemar (L0–L3 vs T-gate) | b=19 · c=0 · p<.0001 · **방향이 가설의 반대** | ✗ |
| 정상 델타 위양성률 ≤5% | **0/18 = 0%** | ✓ |

검출된 결함은 4종뿐이다 — F01(L0 9/9) · F02(L1 9/9) · F09·F10(누출 9/9). 나머지 8종은
전 층 미탐지다. **T1·T2·T3 가 추가로 잡은 결함은 하나도 없다.**

### 8.2 원인 (세 층 모두 자원의 해상도 문제)

1. **L2 에 검출 표면 없음** — TBox 에 `owl:disjointWith`·카디널리티·함수적 속성 0개.
2. **L3·T3 는 존재검사** — CQ 28개 중 26개가 `expect-min: 1`.
3. **T1 마진이 넓음** — 이득 +0.042 를 전부 소진하고 ε=0.02 를 더 넘겨야 발화. 개념정렬 10%
   오류에서 실측은 +0.032 로 줄었을 뿐.

### 8.3 T3′ 진단 — 실패의 소재를 특정했다

| | T3(이진 통과) | **T3′(결과행 수)** |
|---|---:|---:|
| 결함 검출 | 0/108 | **55/108** |
| 정상 델타 오탐 | 0/18 | **0/18** |

같은 CQ·같은 결함·같은 강도인데 **판정 해상도만 바꾸면 절반 이상이 검출되고 오탐은 0**이다.
교차결함 F11(동의어 오병합)은 **전문가매칭 CQ18** 의 응답을 6/9 에서 떨어뜨린다 — §7.2 가
예상한 경로는 실재하되 이진 판정이 그것을 삼켰다. F12(계층 역전)는 T3′ 로도 미검출인데,
`hasSubprocess` 를 뒤집어도 행 수가 보존되기 때문이다(**방향성 제약의 부재** — CQ 세분화로
닫히지 않는 별개 결손).
