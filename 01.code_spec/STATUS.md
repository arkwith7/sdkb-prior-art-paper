### PLAN-009 의 결론 — H2 는 "기각"이 아니라 "**이 데이터로는 검정 불가**"다

**개념 vs 코드 부호검정은 코드 팔이 양방향으로 무효라 성립하지 않는다** (`make h2` · 여덟 셀 전부 기각 실패):

| 코드 팔 | 무효의 방향 | 증거 |
|---|---|---|
| **현재 분류** | **부당하게 이르다** (소급 재분류) | GAA 전용 코드 `H10D30/6735` 가 **2012년 출원**에 붙어 있다 — 그때 부여된 게 아니라 2021년 이후 재분류된 것이다 |
| **당시 분류** | **해상도 바닥이 2017** | BigQuery 동결 스냅샷이 2017-10 부터만 존재한다. 교정 창에서는 여섯 사례 중 **넷이 2017/2017 동률**이 된다 |

**그래서 말뭉치 밖의 준거(DART 공시)에 각 팔을 대어 잰다.** 교정 창(2005–2023) · si 정의:

| 사례 | DART 준거 | 개념(si) 탐지 | 선행 | 코드(당시 선행코드) | 선행 |

| GAA | 2020 | **2015** | **+5** | `H01L29/42392` | +5 |
| | | **4/4 선행 · 중앙 4.5년** | | **1/3 선행 · 중앙 −1년** | |

> **사례 4건이라 부호검정 최소 p = 0.0625 — α=0.05 에 도달할 수 없다.** 이 한계는 결과를 보기
> 전에 선언했다 (PLAN-009 §3-4). **검정이 아니라 서술적 타당성 점검이다.** 유의성을 주장하지 않는다.

**좌측절단이 원인이었다는 것이 실증됐다.** 정의는 한 글자도 바뀌지 않고 **창만** 바뀌었는데:

| 사례 | DART | 사전등록 창(2010–) | 교정 창(2005–) |
|---|---:|---:|---:|
| HBM | 2014 | 2016 (**2년 늦음**) | 2009 (**5년 앞섬**) |
| TSV | 2012 | 2019 (**7년 늦음**) | 2009 (**3년 앞섬**) |
| 3D NAND | 2013 | 2015 (2년 늦음) | 2009 (4년 앞섬) |

상식과의 갭(하이닉스가 2014년에 HBM 을 공시했는데 우리는 2018년에 탐지)은 **현실이 아니라
우리 측정의 좌측절단**이었다. 상대성장 규칙(θ × 직전 3년 평균)은 창이 열리는 순간 이미 정점인
기술의 부상을 **원리적으로** 볼 수 없다 — 후행창이 창 밖이라 기저가 정의되지 않는다.

### H2′ — 시점 유효한 대조군(명칭)으로 다시 세운 검정 ([PLAN-010](plans/PLAN-010-h2prime-name-baseline.md))

코드 대조군이 무효라 **명세 텍스트의 명칭**을 대조군으로 세웠다(텍스트는 소급 재작성되지 않는다).
신호 규칙은 불변 · 대조군만 교체. 교정 창 · 구조 전용 개념(대조군과 **서로소**):

| 사례 | 개념 탐지 | 명칭 탐지 | 시차 |
|---|---:|---:|---:|
| HBM | 2009 | **2020** | **+11** |
| 3D NAND | 2009 | **미탐지** | ≥+14 |
| GAA | 2015 | 2016 | +1 |
| FinFET | 2012 | 2013 | +1 |
| TSV | 2009 | 2009 | 0 (동률·제외) |
| MRAM | 2008 | 2008 | 0 (동률·제외) |

**4승 0패 — 그런데 p = 0.0625 로 α=0.05 미달.** 동률 2건이 유효쌍을 6 → 4 로 깎았고 4전 4승의
최소 p 가 0.0625 다. **"기각"이 아니라 "표본 부족"이다** — 유효쌍 4 이하면 α 도달이 구조적으로
불가능하다는 것은 PLAN-006 시점부터 `h2_cli.py` 에 적혀 있었다.

> **하지 않은 것**: 사례 추가(FOWLP 를 넣으면 7전 7승 p=0.0078) · 동률을 개념 승으로 계수
> (6전 6승 p=0.0156) · 임계값 조정. 전부 p-hacking 이다. **전승인데 유의하지 않다고 그대로 쓴다.**

**좌측절단이 여기서 두 번째로 실증된다**: 같은 정의로 창만 바꿨는데 3승 2패(p=0.5) → 4승 0패.

**HBM 이 이 논문의 그림이다** — 개념은 2009년, 명칭("HBM")은 **2020년**. 11년 차이다.
특허는 HBM 을 만들면서 그것을 HBM 이라 부르지 않았다. 3D NAND 는 명칭으로 **끝내 탐지되지 않는다.**

### H2 코드 대조군 — 네 측정 전부 기각 실패 → **현재는 가설이 아니라 진단 D1 이다** (역사 기록)

> ⚠ **이 절은 폐기된 검정 형식의 역사 기록이다 (2026-07-18 감사 정정).** 아래 네 측정은 PLAN-016
> 재설계 **이전**의 H2 이고, 지금 원고의 입장이 아니다. **현행 H2 는 지지된다** — 검정 형식은

### PLAN-004 · 신기술 인식 레이어 (H2 를 검정 가능하게 만든 작업)

신기술은 이름으로도 코드로도 잡히지 않았다 — 그것이 H2 의 장애물이자 H2 의 논지
("코드 단위는 늦다")에 대한 **관측 증거**였다. 3층 레이어로 개념을 붙잡았다.

| 개념 | 이전 | 이후 | 어떻게 |
|---|---:|---:|---|
| `device/hbm` | 0 | **235** | 2층 조합 `(H10B80 ∨ H10W90) ∧ TSV` — 이름 쓴 특허는 32건뿐 |
| `device/gaa_fet` | 0 | **153** | 1층 별칭(MBCFET·나노시트) — **전용 코드는 여전히 0건** |
| `device/finfet` | 1 | **168** | 0층 룰(135) + 1층 텍스트(36) · 교집합 **2건** |

- **정의는 시계열을 보기 전에 동결**됐다 (`mappings/emerging_concepts.csv` · `term_aliases.csv`).
  근거는 CPC 2026.01 공식 스킴 **원문 직접 파싱**과 JEDEC 표준이다 (`mappings/PROVENANCE.md`).
  민감도 변이도 사전 정의: HBM strict 74 / **base 209** / loose 1,018.
- **별칭은 `skos:altLabel`(언어 태그)로 G₁ 에 실체화**했다 — SDKB 의 라벨 설계(prefLabel@en 기준 ·
  altLabel@ko 별칭)가 신기술 개념에서만 비어 있었다. 이제 그래프에 `"고대역폭 메모리"@ko` 로
  질의하면 **235건**이 나온다(이전 0건).
- **H1 은 불변이다** — 신기술 레이어는 디바이스 축에만 링크를 더한다(회귀 테스트로 고정).
- G₁ 게이트 재통과: L1 ✅ · L2 consistent ✅ · L3 CQ 8/8 ✅. CQ06 39 → **36** · CQ07 212 → **234**.

**H2 의 사례와 대조군은 사전 고정됐다** — PLAN-006 ① 에서 **7건**으로 확장해 동결했다
(`mappings/h2_cases.csv`): HBM `H10B80/00` · GAA `H10D30/6735` · FinFET `H10D30/62` ·
3D NAND `H10B43/27` · MRAM `H10B61/00` · FOWLP `H10W70/09` · TSV `H10W20/211`.
GAA 대조군이 0건인 것은 결함이 아니라 **결과**다 — 코드 단위의 탐지 실패로 보고한다.

> **7건 중 5건은 구조적 비대칭이 있다.** GAA·FinFET·3D NAND·MRAM·TSV 는 대조 코드가 개념의
> 0층 룰 안에 있어(개념 ⊇ 코드) **개념이 늦게 탐지되는 것이 불가능**하다. 진짜 양방향 사례는
> HBM·FOWLP 둘뿐이다. `subset_flag` 로 나눠 보고하고, §4.5 에서 **대조 코드를 개념 시계열에서
> 제거한 재검정**을 사전 규정했다 (`mappings/PROVENANCE.md`).

### H1·H2 전에 반드시 반영할 사실

- **최근 연도 절단.** 2024년 3,884 → 2025년 423 은 출원 감소가 아니라 **18개월 비공개**다.
  시계열에서 절단 구간을 명시하지 않으면 모든 개념이 최근에 급락하는 그림이 나온다.
- **미매핑 10,468건(30.3%)은 병합되지 않았다.** 대부분 G11C 메모리 **회로** 코드다 —
  SDKB 에 회로 설계 축이 없다. 데이터의 한계가 아니라 온톨로지 범위의 경계이므로 §4.5 에 그렇게 쓴다.
- **G₁ 은 두 출원인이다** (사용자 결정 2026-07-13). 삼성 단독이 아니라 삼성 + SK하이닉스.
  H2 의 HBM 사례가 하이닉스 없이는 검증되지 않기 때문이다. §4.5 에서 **출원인별 분리 재검정**을
  강건성으로 보고한다. 논문 §5.3(a) 의 "단일 출원인 한계" 문구는 이제 틀렸다 — 고쳐야 한다.

> **G₀ 는 이제 동결 대상이다.** PLAN-001 이 상류 SDKB 를 마지막으로 건드렸다. 여기서부터
> SDKB 를 바꾸면 H1 의 before 가 움직인다 — 삼성 특허를 한 건이라도 본 뒤의 어휘 변경은
> 사후 조정이 되므로 금지다.
