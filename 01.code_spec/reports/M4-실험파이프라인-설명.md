# M4 선행기술검색 실험 파이프라인 설명 (예시 특허 포함)

> **목적:** 온톨로지 보강 선행기술검색 실험이 **구체적으로 어떤 과정을 거치는지** 예시와 함께 설명한다.
> 결과 해석·수치는 [M4-실험결과-1차.md] 참조. 이 문서는 "무엇을 어떻게 측정했는가"의 설명서다.
> 코드: `src/sdkb_paper/{retrieval,analysis,corpus,ontology}/` · 설계 정본: [../plans/PLAN-018-v09-retrieval-tgate-harness.md].
> 작성 2026-07-27 · 논문 미반영(1차 실험 문서화).

## 0. 한눈에 보는 전체 흐름

```
거절특허 1,000건(질의)  ─┐
심사관 인용 선행기술(정답)─┤ 0. 벤치마크 + 누출차단
                          ▼
질의 = 독립항 청구항 원문 ── 1. 질의 표현(F8 Claim-only)
                          ▼
코퍼스 ~40,000건 → 시점·패밀리·자기 제외 ── 2. 후보 풀 D_q (F10)
                          ▼
BM25(B0) + Dense(B2) → RRF 융합 B3 ── 3. 텍스트 검색(가장 강한 기준선)·질의당 상위 1,000
                          ▼
각 (질의,후보)쌍: 개념겹침·경로·IPC·한정요소 ── 4. 온톨로지 항 계산
                          ▼
(1−α)·텍스트순위 + α·온톨로지항 → 재정렬 ── 5. 재랭크(P0★·P1 = 제안법)
                          ▼
한 항씩 빼고 재랭크 ── 6. Ablation(계층별 기여 측정)
                          ▼
패밀리로 접어 top-100에 정답 몇 개 ── 7. 집계(Recall@100)
                          ▼
페어드 부트스트랩 ── 8. 통계(개선이 진짜인가)
```

**핵심 오해 교정:** 질의는 "초록 파싱·키워드 추출"이 **아니다.** 질의는 거절특허의 **독립항 청구항
원문 전체**이고, 검색은 그 문장을 BM25·임베딩으로 코퍼스와 대조한다. 개념 태그도 질의 시 뽑는 게
아니라 **SDKB 온톨로지가 각 특허에 미리 붙여둔 것**을 조인해 쓴다.

## 1. 단계별 상세

### 0단계 — 벤치마크(=라벨링)와 누출 차단
- **질의:** 거절된 한국 특허 1,000건. 이들은 심사관이 "선행기술 때문에 거절"한 특허다.
- **정답(qrel):** 각 질의에 대해 **심사관이 인용한 선행기술 특허**. 완전한 정답이 아니라 "심사관 검토에
  정박된 양성 전용 약한 적합성 판단". family 수준 고유 정답 ≈ 2,193.
- **누출 차단 3종:** ① 질의의 인용 간선(`hasPriorArt` 등) 마스킹 — 정답을 직접 가리키는 링크 제거 ·
  ② 시점유효: 후보 공개일 < 질의 출원일 · ③ 패밀리 분리: 같은 특허 패밀리 제외.
- **분할:** filingDate 순 train/dev/test = 600/200/200 (family-disjoint). **test는 봉인** — 선택·개발은
  dev로만, test는 최종 확증 1회만 개봉.

### 1단계 — 질의 표현 (`corpus/`, F8 Claim-only)
질의 = 거절특허의 **독립항 청구항 텍스트**(`claims_independent`). 불완전 시 청구항1+제목·초록 보조.
(초록+청구항 표현은 강건성 분석용 보조로만 — 주 분석은 청구항.)

### 2단계 — 후보 풀 D_q (`retrieval/candidate.py`, F10)
질의 q에 대해 허용 후보 = `{d : d≠q ∧ 공개일(d)<출원일(q) ∧ family(d)≠family(q)}`.
공개일 결측(4,492건)은 미래임을 증명 불가하므로 시점유효로 포함(recall 보수적).

### 3단계 — 텍스트 검색: 가장 강한 기준선 만들기 (`retrieval/bm25·dense·hybrid`)
- **B0 BM25:** nori 형태소분석 + SDKB 도메인 사용자사전(275 표층형)으로 토큰화한 어휘 일치.
- **B2 Dense:** Titan Embed v2(1024차원) 임베딩의 코사인 유사도(FAISS flat).
- **B3 Hybrid:** B0·B2를 RRF(c=60)로 융합 = **가장 강한 텍스트 기준선.** 질의당 상위 1,000건 순위 산출.
- **왜 B3가 기준선인가:** 온톨로지가 "텍스트만으로도 강한 시스템"을 **넘는가**가 핵심 질문이므로,
  약한 기준선이 아니라 가능한 가장 강한 텍스트 시스템을 상대로 온톨로지 이득을 잰다(정직성).

### 4단계 — 온톨로지 항 계산 (`retrieval/ontology_rerank.py`, `feature_coverage.py`)
B3 상위 풀의 각 (질의, 후보) 쌍에 대해 네 항을 [0,1]로 계산:
| 항 | 정의 | 원천 |
|---|---|---|
| **ConceptOverlap** | 공유 개념 태그 Jaccard | SDKB `concepts`(141종·`realizesProcess` 등으로 부착) |
| **PathSim** | 개념→ont:클래스 Wu-Palmer(계층 거리) | TBox subClassOf |
| **IpcSim** | 공유 IPC 접두(섹션→클래스→서브클래스→그룹) Jaccard | 특허 IPC 코드 |
| **FeatureCoverage** | 질의 독립항 한정요소 중 후보 한정요소에 코사인≥τ 매칭 비율 | claim-feature sidecar(Titan 임베딩·교차언어) |

- **누출 안전:** 전부 질의·문서의 **자기 서술**(개념·분류·자기 청구항). 정답 유래 신호 미사용.

### 5단계 — 재랭크 = 제안법 (`retrieval/systems.py`, `analysis/ontology_eval.py`)
새 점수 `S = (1−α)·T̃ext_B3 + α·[w_c·Concept + w_h·Path + w_i·Ipc (+ w_f·FeatureCov)]`.
- T̃ext_B3 = B3 순위를 질의별 [0,1]로 정규화한 값. 온톨로지 항과 가중 혼합해 **상위 1,000을 재정렬**.
- 가중치(α·w)는 **dev에서만** 격자탐색으로 선택(F18)·test 최적화 금지.
- 시스템: **P0★**(concept+ipc) · **P1**(+FeatureCoverage) · 비교용 B4(IPC 단독)·B5(개념 단독).
- **중요 성질:** 재랭크는 B3 풀(상위 1,000) **안에서만 순서를 바꾼다.** B3가 애초에 못 찾은 문서는
  못 살린다(재랭크-only 천장). 이것이 뒤의 near-miss 한계의 원인.

### 6단계 — Ablation: 계층별 기여 측정 (`analysis/ablation.py`)
제안법에서 **한 계층씩 제거**하고 재랭크 → Recall@100이 얼마나 떨어지나(제거손실). 안 떨어지면 그
계층은 기여 0. A1(IPC)·A2(공정·소자)·A3(재료·장비·고장)·A4(ClaimFeature)·A5(거절근거)·A6(경로)·
A7(전체 온톨로지)·**A8(전문가 Skill 계층 = 음성대조군)**. Holm 다중비교 보정.

### 7단계 — 집계: 주지표 family Recall@100 (`analysis/metrics.py`)
순위를 **패밀리로 접고**(같은 발명의 중복공개를 1개로), 상위 100 family 중 질의의 정답 family가
몇 개 들었나 ÷ 정답 family 수. 정답≥1 질의에 대해 평균.

### 8단계 — 통계: 개선이 진짜인가 (`analysis/bootstrap.py`)
두 시스템의 질의별 Recall@100 차이를 **페어드 부트스트랩**(10,000회·질의단위·seed 고정) → 평균차·
95% 신뢰구간·양측 p. CI가 0을 배제하면 유의. ablation은 Holm 보정.

## 2. 실제 예시 질의로 보는 작동

**질의 특허: `kr_1020170018545`** (거절된 한국 특허 · dev)

- **SDKB가 이 질의에 부착한 개념:** `clean, deposition, film_stress_control, lithography,
  mask_engineering, pvd` (박막증착·세정·노광·마스크 공정 관련)
- **질의 IPC:** `C23C_14-06/14-34/14-56`(증착), `G03F_1-50/1-66`(마스크/노광) 등
- **심사관 정답: 3건**

**검색 결과 (top-100 회수): B3(텍스트) 1건 → P0★(온톨로지) 2건 (+1)**

| 정답 특허 | 질의와 공유 개념 | B3 순위 → P0★ 순위 | 무슨 일이 |
|---|---|---|---|
| `kr_KR1020040035486A` | **5개**(clean·deposition·lithography·mask_engineering·pvd) | **148위 → 4위** | 개념 대량 공유 → 온톨로지가 크게 승격 ✅ |
| `kr_KR100208898B1` | 2개(deposition·pvd) | 82위 → 78위 | 소량 공유 → 미세 상승 |
| `jp_JP07091636B2` | **0개** | >1000위 → >1000위 | 개념 0 공유 + 일본어 → **B3가 못 찾았고 재랭크도 못 살림** ❌ |

### 이 한 예시가 보여주는 전부
1. **파이프라인 정상 작동:** 개념을 5개 공유한 정답을 148위→4위로 **정확히 끌어올렸다.** 온톨로지
   재랭크가 의도대로 동작한다는 산 증거(버그 아님).
2. **이득의 원천:** "질의와 정답이 같은 기술개념 태그를 공유할 때" 그 정답을 위로 올린다.
3. **한계 1(재랭크 천장):** 일본어 정답은 B3가 애초에 top-1000에 못 넣었고, 재랭크는 풀 밖 문서를
   못 살린다.
4. **한계 2(교차언어·near-miss):** 개념 0 공유 + 외국어 정답은 어떤 온톨로지 항도 못 잡는다 —
   이것이 진짜 어려운 케이스(진단 D3의 near-miss).

## 3. 신호가 실제로 작동하는지 검증 (양성대조군)

"온톨로지 각 항이 정답을 비정답보다 높게 점수하는가"를 직접 측정(dev·풀 내 정답 vs 비정답 평균차):

| 항 | 정답−비정답 평균차 | 양수 질의 |
|---|---:|---:|
| ConceptOverlap | **+0.2337** | 113/148 |
| PathSim | +0.1734 | 112/148 |
| IpcSim | +0.1316 | 118/148 |
| FeatureCoverage | +0.0491 | 43/148 |

- **ConceptOverlap·PathSim·IpcSim은 정답을 확실히 높게 점수** → 파이프라인이 신호를 잡는다(양성대조군
  통과). PathSim·IpcSim은 신호가 있으나 ConceptOverlap과 **공선**이라 독립 기여가 없다(그래서 재랭크
  가중이 개념에 몰림).
- **FeatureCoverage는 거의 분리 못 함**(+0.05·43/148) — 쌍의 **82%가 0**. 관련 선행기술도 청구항
  한정요소 **문구**는 서로 달라 임베딩 매칭(τ=0.7)이 안 되기 때문. → H4 기각의 실체(버그 아님·신호 부재).
