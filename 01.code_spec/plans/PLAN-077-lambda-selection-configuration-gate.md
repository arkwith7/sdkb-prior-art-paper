## 0. 한 문장

**PLAN-075 가 배선한 두 항(관계 `rel_sim` · 투영 `ProjCov`)의 가중 λ 를 dev 에서만 고르고,
그 구성을 P1 과 짝지어 원고 §3.5 의 승인식(T1·T2)을 "시스템 구성 변경"에 적용한 판정을 1회
산출한다 — 우월성은 개봉 분할이므로 탐색 판독으로만 적는다.**

**왜 필요한가.** PLAN-075 는 §7 의 일곱 기준으로 *"기제가 도달했는가"* 만 물었고 성능은 어느
자리에서도 주장하지 않았다(§14.5). 그 결과 지금 코드에는 `w_r`·`w_f2` 가 **기본값 0** 으로
배선되어 있어(`retrieval/systems.py` `OntoConfig`) 통로는 열렸으나 **한 번도 값이 흐른 적이
없다.** 후속 논문의 E2("온톨로지 대 온톨로지" · 상류 PLAN-003)는 이 항이 읽는 값 위에서
자원을 바꾸는 실험이므로, λ 가 정해지지 않으면 E2 의 기준선이 없다.

## 4. 절차 분류 — §2.1 이 아니라 §2 다 (승인 필요 ①)

O-10 과 PLAN-075 §14.5 는 이 항목을 *"§2.1 새 사전등록"* 이라 적었다. 그러나 CLAUDE.md §2.1 은
**"파이프라인 완전 동결 · 자원만 교체"** 일 때만 유효하고, *"검색 설정·가중치 ... 중 하나라도
손대면 그것은 재측정이 아니라 새 방법이고, 요구정의부터 다시 탄다"* 고 못박는다. **λ 선택은
가중치 변경이다.** 그러므로 이 계획은 **§2 의 5단계(정지 게이트 4개)** 를 타되, §2.1 에서
가져오는 것은 **"test 를 열기 전에 판정식·λ·해시를 한 파일에 적고 커밋한다"** 는 사전등록
동결 하나다. 구체적으로:

| 단계 | 내용 | 정지 |
|---|---|---|
| 1 요구정의 | **이 문서** | 🛑 |
| 2 분석 | **dev 전용 λ 격자 관찰**(§5) · `test`·`test_b` 미개봉 · 가정은 "가정"으로 | 🛑 |
| 3 설계 | λ★ 확정 · 동결 항목표(§6) 채움 · **이 커밋이 사전등록 동결 커밋** | 🛑 |
| 4 구현 | λ 격자 CLI 인자 가산(있다면) · 그 밖 `src/` 변경 0 | — |
| 5 검증 | `make lint && make test` · 사전 검사 P-1~P-8 · **test 1회 판정** · 보고 | 🛑 |

**2단계와 3단계 사이에 "이득 없음"의 출구를 둔다**(§5.4). dev 에서 어느 λ 도 λ=0 을 넘지
못하면 test 를 열지 않고 그 자리에서 종료·보고한다. 개봉 분할이라도 **관측 횟수를 늘리지
않는 것**이 §2.1 마지막 문단의 취지다.

**A5·A7 을 선택 근거에서 배제하는 이유.** 하위집단이나 특정 쌍 집단을 보고 λ 를 고르면 T2 판정을
dev 에서 미리 맞추는 것이 되고, 그것은 §1-2 의 형태다. 둘은 **해석 자료**이지 선택 함수의
입력이 아니다.

### 5.2 선택 규칙 — 결과를 보기 전에 박는다 (승인 필요 ②)

```
λ★ = argmax_λ  dev family R@100(P1 ⊕ λ)          # 주지표 하나 · nDCG 는 보고만
동률(소수 4자리) → 더 작은 λ                          # 절약 원칙 · P1 에서 덜 움직인 쪽
순서: ① λ_r 단독 → ② λ_f2 단독 → ③ 둘의 성긴 2차원
③ 은 ①·② 각각이 λ=0 을 넘을 때만 연다              # 한 항도 이득이 없으면 결합은 잡음이다
```

**λ 두 개를 한 번에 올리지 않는다**(PLAN-075 §2 규율 ③). ③ 의 결과가 ①·② 의 최선을 넘으면
λ★ 는 ③ 의 쌍이고, 넘지 못하면 **더 좋은 단독 항 하나**만 켠다.

### 5.3 예상하지 않는다 · 사전에 밝히는 것

- **dev 에서 어느 λ 도 λ=0 을 넘지 못할 수 있다.** PLAN-075 §14.2 의 비영 비율(rel 78.9 % ·
  proj 56.1 %)은 *값이 있다*는 뜻이지 *값이 옳다*는 뜻이 아니며, 원고 §6.2 가 진단한 재순위화
  상한(첫 확증 분할에서 정답 엣지의 60.3 % 만 후보 풀 안 · 원고 §6.4)은 이 항으로도 넘지 못한다.

### 6.1 판정식 — 승인식을 구성 변경에 적용한다

```
Accept(P1 → P1⊕λ★) = 𝟙[L0=L1=L2=L3=pass]                       # 자원 불변 → 구성상 pass · 산출은 하되 증거로 쓰지 않는다
                    · 𝟙[LB₉₅(ΔR₁₀₀) > −ε]                        # T1 · Δ = (P1⊕λ★) − P1
                    · 𝟙[max_s Drop_s < δ]                         # T2
                    · 𝟙[∀f∈{em,tf,core}: pass_f(new) ≥ pass_f(old)] # T3 · 자원 불변 → 항등 · 동상
```

- **T1 이 묻는 것은 저하 여부다**(원고 §3.5). 이 실험의 1차 판정은 *"두 항을 켜도 P1 이 비열등을
  잃지 않는가"* 이며, 그것이 E2 기준선 채택의 조건이다.
- **우월성은 확증하지 않는다.** test 는 개봉 표본이므로(§2.1 마지막 문단) ΔR₁₀₀ 의 점추정 · 95 % CI ·
  양측 *p* 는 **탐색 판독**으로만 적고, 서술은 §0.8 의 P0/P1 행 형식을 따른다 — *"부차 구성의
  개선이 관측됐다"* 까지이며 *"확실"* 은 쓰지 않는다(§0.3 · 5조건 중 이 실험이 채우는 것은 0).
- **누출 감사 통과가 전제다.** `make leakage` 위반이 0 이 아니면 T1 을 산출하지 않는다(§1-4).

### 6.2 분할 선택의 근거와 대안

| 선택지 | 내용 | 채택 |
|---|---|---|
| **test(A층)** | 개봉 표본 · 승인식 예행 1회차(§5.3.1)와 같은 분할 · 접근은 원장 기록 | **채택** — 예행 2회차를 같은 자리에서 한다 |
| test_b(판독 B) | 판독 B 봉인 · T4 와 패널 B 가 이미 개봉 | **불채택** — 열 때마다 허가가 필요하고, 이 판정이 그 개봉을 정당화할 만큼 크지 않다 |
| 새 봉인 분할 | 우월성 확증에 유일하게 적격 | **없다** — B층 479건은 test_b 로 소진됨. 결손으로 적는다(§9 ⑥) |

### 6.3 구성 명칭 (승인 필요 ④)

**`P2` 는 쓸 수 없다.** S5 표에서 `P2` 는 *+Ground-aware(P1 + 거절근거 호환 · 미구현)* 로 이미
등재되어 있고(`S5-submission-full-v2.md:142·160`), 원고 약어표도 `P0–P2` 를 그 뜻으로 적는다.
코드의 함수명 `rerank_p2` 는 내부 이름이라 그대로 두되, **산출물·표·보고의 구성 라벨**은 새로
정한다. 후보:

| 후보 | 뜻 | 비고 |
|---|---|---|
| `P1r` · `P1f` · `P1rf` | P1 + 관계 항 · P1 + 투영 항 · 둘 다 | 항이 이름에 보인다 · 라벨 충돌 0(grep 실측 필요) |
| `P1⊕λ` | 일반형 | 표에서 λ 값을 함께 적어야 한다 |

**권고는 `P1r`·`P1f`·`P1rf` 다** — 어느 항이 켜졌는지 이름이 말하므로 §0.8 구성 명칭 행의
*"주 시스템"* 류 오독이 생기지 않는다. **결정은 사용자에게 올린다.**
