## 0. 결론 먼저 — 무엇을 만들고 무엇을 만들지 않는가

**만든다:** 본문 그림 7종의 영문 라벨판을 **같은 그리기 코드에서** 생성하는 경로.
**만들지 않는다:** 새 그림 · 새 수치 · 영문 전용 그리기 코드.

**이 산출물이 지지하는 주장은 없다 — 기존 증거의 언어 렌더링이다.** §0 의 자문
(*"이 산출물은 C0/C1/C2/C3 중 무엇을 지지하는가"*)에 대한 정직한 답은 **"아무것도 새로
지지하지 않는다"** 이다. 그림이 담는 증거는 이미 C1·C2·C3 에 사상돼 있고, 이 작업이 바꾸는
것은 **그 증거를 읽는 사람의 언어**뿐이다. 그러므로 **수치·판정·그림 번호·라벨 기호는 하나도
바뀌지 않는다.**

## 1. 목적 · 입력 · 출력

**목적.** 영문 투고본이 인용하는 그림 7종의 텍스트가 한국어여서, 현재 상태로 투고하면
심사자가 그림을 읽을 수 없다. 이것이 A 묶음의 마지막 미완 칸이다.

**입력 (전부 이미 존재하며 이 작업으로 바뀌지 않는다).**

| 입력 | 자리 | 성질 |
|---|---|---|
| 개념 그림의 수치 | `paper/figures/data/concept_values.json` | **언어 무관** — `values` 는 수치뿐이고 한글은 그리지 않는 메타(`note`·`how`)에만 있다(실측) |
| 데이터 플롯의 수치 | `analysis/` 가 배출한 CSV | 언어 무관 |
| 그림 텍스트 | `viz/concept.py` · `viz/figures.py` 의 한글 문자열 리터럴 | **이 작업의 대상** |

**출력.** `paper/figures/en/*.svg` 7종. 한국어판 `paper/figures/*.svg` 는 **그대로 둔다** —
국문 정본과 supplementary 가 그것을 인용한다.

**논문에서의 자리.** 영문 투고본 `paper/submission/en/manuscript.md` 의 그림 1–7.

## 2. 실측 (2026-08-26 · 요구정의 시점)

| 항목 | 값 |
|---|---|
| 본문 그림 7종의 출처 | 개념 도식 **6종** = `viz/concept.py` (649행) · 데이터 플롯 **1종** = `viz/figures.py` 의 `fig_ir_metrics` |
| 영문화 대상 문자열 | `concept.py` 한글 리터럴 **183개** · `fig_ir_metrics` 한글 UI 문자열 **4개**(부제 둘 · y축 라벨 · 범례 하나) |

| `concept_values.json` | 키 2 (`note` · `values`) · `values` 는 수치만 |

아카이브 그림의 것이다 — **영문화하지 않는다**(§5 비목표).

## 3. 성공기준 — 검정 가능한 형태로

전부 기계로 확인되며, 하나라도 미달이면 미완으로 보고한다.

| # | 기준 | 확인 방법 |
|---|---|---|
| **G1** | 영문판 7종의 **렌더된 텍스트에 한글 0자** | SVG 의 `<text>` 노드를 파싱해 `[가-힣]` 계수 = 0 |
| **G2** | 한국어판 7종이 **바이트 단위로 불변** | 변경 전후 sha256 대조 (결정성 유지의 증거) |
| **G3** | 영문판의 수치가 한국어판과 **동일** | 두 판의 `<text>` 에서 수치 토큰을 뽑아 다중집합 비교 |
| **G4** | 개념 그림의 수치가 여전히 `concept_values.json` 에서만 온다 | 기존 F6 대조 assert 가 영문 경로에서도 실행 |
| **G5** | 영문 그림 텍스트가 **STYLE-EN §4 금지 판정 문구 0건** | 라벨 표를 `style_check_en` 의 `VERDICT_FORBIDDEN_EN` 로 검사 |
| **G6** | 영문 원고가 **영문 그림을 가리키고** 링크가 살아 있다 | `submission_check` 내부 링크 검사 통과 |
| **G7** | `make lint` · `make test` 통과 | 그대로 |

**G2 와 G5 가 이 계획의 방어선이다.** G2 가 없으면 영문화가 국문 그림을 조용히 바꿀 수 있고,
G5 가 없으면 **본문에서 금지한 판정 문구가 그림으로 새어 나간다**(그림 규격 F4 가 이미 요구하는
것이며, 지금까지 기계로 확인된 적이 없다).

## 4. 설계 선택지 — 3단계에서 확정할 것 (여기서는 후보만)

| | 방식 | 장점 | 대가 |
|---|---|---|---|
| **A** | **라벨 표 분리** — `viz/labels.py` 에 `{키: {"ko":…, "en":…}}` 를 두고 그리기 코드는 `L(키, lang)` 으로 읽는다 | 그리기 코드 1벌 유지 · G5 를 표 하나에 걸 수 있다 · 두 언어의 표류가 한 파일에서 보인다 | 리터럴 187개를 키로 옮기는 기계적 작업 |
| **B** | 영문 전용 모듈 복제 | 착수가 빠르다 | **그리기 코드 2벌** — 다음 재측정에서 한쪽만 갱신되어 갈린다. **권고하지 않는다** |
| **C** | SVG 후처리 치환 | 코드 변경 0 | 문자열이 도형에 얹혀 **줄바꿈·정렬이 깨진다** · §1-7 의 취지에 반한다. **권고하지 않는다** |

**권고는 A 다.** 근거는 이 저장소가 이미 같은 문제를 같은 방식으로 풀었다는 것이다 —
`build_submission_en.py` 의 `TERMS`·`CELLS`·`CAPTIONS` 가 표·캡션에 대해 하는 일을, 이
계획은 그림 텍스트에 대해 한다.

**출력 경로도 3단계에서 확정한다.** 후보는 `paper/figures/en/<같은 이름>.svg` 이며, 그러면
`build_submission_en.py` 가 `../../figures/X.svg` → `../../figures/en/X.svg` 로 바꾼다 —
**깊이 보정과 같은 자리이고 같은 이유다**(사람이 경로를 손으로 적지 않는다).

## 5. 비목표 — 하지 않는 것

| 하지 않는다 | 이유 |
|---|---|
| 본문 밖 데이터 플롯 4종과 S-시리즈 그림의 영문화 | **논문에 자리가 없다**(CLAUDE.md §6). 자리가 생기면 그때 |
| 그림의 **구성·배치·색·크기** 변경 | 이 작업은 언어 렌더링이다. 디자인 변경은 그림 규격 F-v1 의 개정이므로 별건 |
| `concept_values.json` 의 수정 | **손으로 고치지 않는다**(F6). 이 작업은 그 파일을 읽기만 한다 |
| 한국어판 그림의 교체 | 국문 정본·supplementary 가 인용한다 |
| supplementary 의 영문화 | 감사 기록이다(§8.1 적용 범위) |
