# PLAN-073 — 요구정의: 한정요소 개념 투영을 순위 함수에 배선한다 (하류 §2 1단계 🛑)

> **지위: 요구정의 · 승인 대기.** 이 문서는 [CLAUDE.md §2](../../CLAUDE.md) 5단계의 **1단계**이며,
> 승인 없이 2단계(분석)로 넘어가지 않는다. **코드 변경을 동반하므로 §2.1(자원만 교체) 경로가
> 아니다** — 정지 게이트 4개를 전부 탄다.
>
> **발단:** [D-51](../../upstream/DEFECT-LEDGER.md)(2026-08-23 · PLAN-072 실행) — 상류가 발행한
> `claim_features.parquet` 을 읽는 하류 검색 코드가 **0개**이고, 그래서 CR-020 검증기준 ⑥ 이
> **미판정**으로 끝났다. 상류 발행 ↔ 하류 미소비의 **네 번째** 사례다(D-19 · D-26 · D-27).

## 0. 한 문장

**상류가 발행한 청구항 한정요소 개념 투영(1,306,191행 · 40,187문서)을 선행기술 검색 순위
함수의 입력으로 배선하여, 지금은 원리적으로 비가시인 A-Box 층 자원 변경이 태스크 지표에
도달할 수 있게 만든다.**

---

## 1. 순서 제약 — **2×2 가름 실험을 먼저 돌린다** (이 문서의 첫째 요건)

[PLAN-071 §-1.7](PLAN-071-followup-paper-axiomatized-resource-redesign.md) 규칙 4 는
2×2 자원·점수식 가름 실험에 **`src/` 무변경**을 걸었다 — *"`src/` 를 건드리면 기존 동결
runset 과의 O/O′ 비교가 영구 실격"* 이기 때문이다. **이 배선은 정의상 `src/retrieval` ·
`src/analysis` 를 바꾼다.**

**그러므로 두 작업을 한 델타로 묶지 않는다.** 묶으면 2×2 가 성립하지 않는다.

| 순서 | 작업 | 코드 경로 | 근거 |
|---|---|---|---|
| **먼저** | 2×2 가름 실험(df 가중) | `scripts/` 만 | PLAN-071 §-1.7 규칙 4 |
| **그 뒤** | 이 배선 | `src/` | 본 문서 |

두 작업이 공유하는 것은 코드가 아니라 **방법론적 형식**이다 — PLAN-071 §-1.3(d) 가 요구한
**(i) 점수식만 신설·자원 고정 → (ii) 그 위에서 자원만 교체**. 이 배선은 (i) 에 해당하며,
(ii) 는 배선 뒤 새 스냅샷에서 §2.1 로 돈다.

> **정정.** 2026-08-23 회신에서 두 작업을 *"묶어 설계"* 하도록 권했으나, §-1.7 규칙 4 와
> 충돌한다. 묶지 않는다.

## 2. 목적 — 어느 주장을 지지하는가

| 주장 | 이 산출물의 기여 |
|---|---|
| **C1 · 자원** | §0 *표현의 세 층* 가운데 **작동 층**의 최소 조건을 만든다 — 지금 순위 함수의 *공리 유도 항*은 **0**이고 온톨로지 고유 항은 비가중 개념 Jaccard 하나다(`make concept-status`) |
| **C2 · 핵심증명의 전제** | 한정요소 층 자원이 태스크 지표에 **도달할 통로**를 연다. 통로가 없으면 자원을 개선해도 지표가 원리적으로 움직이지 않는다 |
| **C0 · 상류 환류** | D-51 의 두 갈래 가운데 ①. CR-020 ⑥ 을 판정 가능하게 만든다 |
| **C3** | 해당 없음 — 게이트 설계를 바꾸지 않는다 |

**성능 개선을 목적으로 삼지 않는다.** 목적은 **가시성**이며, 성능은 배선 뒤 새 사전등록
아래에서 따로 검정한다(DP2 — 승인은 한 층 아래에서).

## 3. 입력 — 실측으로 확인된 것만 적는다

`data/external/sdkb/claim_features.parquet`(스냅샷 `c17e33f0d594` · 상류 `48971f8`).

| 항목 | 값 |
|---|---:|
| 행(한정요소) | 1,306,191 |
| 문서 | 40,187 |
| 열 | `publication_id` · `side` · `claim_id` · `claim_number` · `is_independent` · `feature_seq` · `feature_concept` · `depends_on_claim` · `decomposition_method` |
| `side` 분포 | `g1` 833,874 · `g2` 337,086 · `cited` 99,874 · `rej` 35,357 |
| 독립항 행 | 520,125 |
| **개념 0개 비율** | **66.9 %** (CR-020 배선 후 · 이전 71.7 %) |
| 등장 고유 개념 | 122 |

**질의 측과 후보 측이 같은 파일에 있다**(`rej` = 거절특허 = 질의 · `g1`/`g2`/`cited` = 후보).
문서 수 40,187 은 코퍼스 41,223 의 **청구항 보유분**과 일치한다.

**현 순위 함수(P1)의 항 넷** — `(1−α)·text + α(w_c·개념Jaccard + w_h·PathSim + w_i·IPC +
w_f·FeatureCoverage)` · 동결 격자 `τ=0.7 · α=0.75 · w=(0.25, 0.0, 0.25, 0.5)`.
`FeatureCoverage` 는 **한정요소 원문의 Titan 임베딩 코사인**이며 개념 축을 쓰지 않는다
(`retrieval/feature_coverage.py` · sidecar 는 `featureText` 만 담는다). 개념 Jaccard 는
**문서 단위 개념 가방**이며 한정요소 구조를 쓰지 않는다.

## 4. 출력 — 논문의 어느 자리에 앉는가

**현 투고본에는 자리가 없다.** PLAN-071 §-1.2 대로 넘어오는 것은 **0건**이며, 이 작업의
산출은 다음 셋이다.

| 산출 | 자리 |
|---|---|
| 배선된 순위 항 + 결정적 산출 경로 | **후속 논문 B 2부 E2**("온톨로지 대 온톨로지")의 **전제** |
| 가시성 증거(파이프라인 서명 이동 · 항 분포) | CR-020 ⑥ 재판정의 근거 · D-51 종결 |
| (i)/(ii) 분리의 사례 | PLAN-071 §-1.3(d) 가 요구한 방법론 선례 |

**논문에 자리 없는 산출은 돌리지 않는다**(§6 집행 조항)에 걸리지 않는 이유는, 이 산출이
**후속 논문의 명시된 절(2부 E2)에 앉기 때문**이다. 그 절이 취소되면 이 작업도 취소한다.

## 5. 성공기준 — 전부 검정 가능해야 한다

**성능 기준을 여기 걸지 않는다.** 이 단계가 묻는 것은 *"기제가 도달했는가"* 하나다.

| # | 기준 | 판정 방법 | 통과선 |
|---|---|---|---|
| **①** | **도달** — 새 항이 파이프라인에 보인다 | `runset.pipeline_signature()` 의 이동 + 새 항의 **비영 비율** | 서명 이동 ∧ 비영 비율 ≥ 30 %(질의–후보 쌍 기준 · 개념 0개 66.9 % 를 감안한 하한) |
| **②** | **대칭** — 질의와 후보를 다르게 다루지 않는다 | 적용 함수가 `side` 를 인자로 받지 않음을 **단위 테스트로 고정** | 테스트 통과 · `side` 참조 0 |
| **③** | **누출 0** | `make leakage` 전 층 + **`side='cited'` 라벨이 순위 입력에 들어가지 않음**을 별도 검사로 강제 | 위반 0 |
| **④** | **결정성** | 같은 입력 2회 실행 · run 파일 sha256 대조 | 바이트 동일 |
| **⑤** | **비회귀(항 무효화 시)** | 새 항의 가중을 0 으로 두면 기존 P1 run 과 **바이트 동일** | 동일 — 아니면 배선이 다른 것을 함께 바꾼 것이다 |
| **⑥** | **하류 지표** | 새 사전등록 아래 별도 실험 | **이 문서의 성공기준이 아니다** — 통로를 연 것과 그 통로가 쓸모 있는 것은 다르다(§0.1 · DP1) |

**⑤ 가 이 목록의 안전장치다.** 가중 0 에서 기존 run 이 재현되지 않으면, 배선이 순위 함수의
다른 부분을 건드린 것이고 그러면 이후 어떤 비교도 자원 효과로 읽을 수 없다.

## 6. 비목표 — 이번에 하지 않는 것

1. **새 어휘·새 술어를 만들지 않는다**(§1-6). 쓰는 개념은 투영에 이미 있는 122종뿐이다.
2. **T-Box 를 바꾸지 않는다.** 공리 신설은 CR-005 계열이며 상류 소관이다.
3. **점수식의 기존 항을 손대지 않는다.** df 가중 도입은 **2×2 실험의 소관**이며(§1) 이 델타에
   섞으면 두 원인이 갈리지 않는다(DP4 · D-23 의 미구분 재현).
4. **가중치 격자를 재선택하지 않는다.** 새 항의 가중 결정은 3단계 설계에서 **dev 에서만**
   하고, `test` 는 열지 않는다.
5. **qrel·분할·봉인을 건드리지 않는다.** 주지표·ε·δ·분할 경계는 동결 그대로다.
6. **RAG·생성 층을 건드리지 않는다.**
7. **현 투고본의 수치·판정·표를 재산출하지 않는다** — `make tables --write` · `make figures`
   를 이 작업에서 돌리지 않는다(메모리 `disk-resource-is-oprime-manuscript-is-o-arm`).

## 7. 2단계(분석)에서 확인할 것 — 지금 정하지 않는다

이 문서는 **무엇을 만들 것인가**만 정한다. 아래는 승인 뒤 데이터를 열어 보고 정한다.

1. **결합 단위** — 한정요소 집합의 개념 겹침을 문서 단위로 접을 것인가, 독립항 단위로 볼 것인가,
   한정요소 대 한정요소 최대 정합으로 볼 것인가.
2. **기존 개념 Jaccard 와의 관계** — 새 항이 그것을 대체하는가 보완하는가. 두 항의 상관이
   높으면 항을 늘리는 것이 아니라 **바꾸는** 것이 옳다.
3. **`depends_on_claim` 사용 여부** — 종속 구조를 쓰면 독립항만 쓰는 것보다 잡음이 늘 수 있다.
4. **개념 0개 한정요소 66.9 % 의 처리** — 분모에 넣을 것인가 뺄 것인가. 이 선택이 지표를
   바꾸므로 **결과를 보기 전에** 정하고 동결한다.
5. **비용** — 40,187문서 × 한정요소의 쌍 계산이 현 재순위화 예산(POOL_K) 안에 드는가.
