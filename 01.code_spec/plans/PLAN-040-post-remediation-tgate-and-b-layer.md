> **상태: 조건 동결 (§2·§3·§5·§6) · 서명 미기입 (§4.2).**
> [CLAUDE.md §2.1](../../CLAUDE.md)이 규정한 **유일한 정지 게이트**이며, 이 커밋 이후 §7 실행은

> 먼저 얼리고 서명을 나중에 채우면**, 어느 회신이 오든 기준은 이미 고정돼 있다. 반대로 하면
> 사후 사전등록이다(§1-3).
>
> **선행:** PLAN-035(H2 1회차 · 기각) · PLAN-031(B층 수집 완료 200건 · **봉인 미개봉**) ·

## 2. 두 판독 — 하나의 스냅샷, 두 개의 질문

| | 판독 A · T-gate 재적용 | 판독 B · B층 H3 재확증 |
|---|---|---|
| 질문 | 이 델타를 **릴리스로 승인해도 되는가** | 검색 이득이 **새 표본에서 재현되는가** |
| 주장 | C3(H2 3회차) | C2(H3) |
| 표본 | **A층 test 198**(이미 개봉됨) | **B층 200**(미개봉 · 최종 1회) |
| 지위 | 사전등록된 승인 규칙의 **집행** | **확증** |
| 근거 | §2.1 — 개봉된 표본 위에서 허용되는 것은 승인 규칙 적용과 탐색적 재측정뿐 | §2.1 — 재확증은 신규 확증분할로만 |

**둘을 한 사전등록에 담는 이유는 스냅샷이 하나이기 때문이다.** 판독 A 가 승인을 거부해도
판독 B 는 실행한다 — B 는 "이 자원을 릴리스할까"가 아니라 "이 자원 위에서 검색 이득이
재현되는가"를 묻기 때문이다. **두 결과는 서로를 취소하지 않는다.**

## 3. 판독 A — T-gate 재적용 (H2 3회차)

### 3.1 두 팔 — 문서집합을 상수로 묶는다

**③ A-Box 코퍼스 델타가 섞이면 T1 비교는 성립하지 않는다**([CLAUDE.md §0](../../CLAUDE.md)
델타 유형표). CR-008 은 문서를 479건 늘리므로, 그대로 두면 이번 비교는 **자격이 없다.**
그래서 **B층 문서를 양 팔에 동일하게 넣어 상수로 만든다.**

| 팔 | 코퍼스(문서집합) | 개념·구조 자산 |
|---|---|---|
| **O′** | O″ 코퍼스와 **바이트 동일** | `2839afb` 자산 (스키마 1.0 `concept_mapping` · claim-features 없음) |
| **O″** | 같음 | `39855bb` + `84ea514` 자산 |

- **O′ 팔은 상류를 체크아웃해 만들지 않는다**(§0.1). 현재 디스크의 `data/external/sdkb/` 가
  이미 O′ 이고(PLAN-035 이후 상태), `make vendor` 를 돌리는 순간 그것이 O″ 로 덮인다 —
  **vendor 전에 O′ 스냅샷을 별도 경로로 복사해 둔다.** 원고 §6.2 확증 표는 여전히 **O 팔**의
  산출이므로 `make tables` 를 무심코 돌리지 않는다(메모리 `disk-resource-is-oprime-manuscript-is-o-arm`).
- **변인은 ①·② 델타뿐**이므로 `classify_delta` = `tbox`/`concept` ∈ `H2_ELIGIBLE_DELTA_TYPES`.
- **적격심사(E1–E7)는 PLAN-035 의 것을 그대로 승계한다.** 추가 1항 — **E8: 두 팔의
  `ir_corpus.parquet` 문서 id 집합이 동일**(문서 델타가 팔 사이로 새지 않았음의 증명).

### 3.2 판정식 — 재선택 없음

`Accept = (L0=L1=L2=L3=pass) ∧ (LB₉₅(ΔR₁₀₀) > −ε) ∧ (max_s drop_s < δ) ∧ (∀f∈{em,tf,core}: pass_f(new) ≥ pass_f(old))`

ε = **0.02** · δ = **0.05** · 주지표 **family-level Recall@100** · 비교 시스템 **P1** · 분할
**test** · 하위집단 축 **거절근거 · 공정군 · 언어(KR/외국)** · CQ 스위트 **pa·em·tf·core**.
**전부 기존 동결값이며 이 사전등록에서 새로 고르지 않는다.**

### 3.3 미리 자인하는 것 — **이번 T1 은 공허할 수 있다**

`concept_meta`(df)는 **자산에 있을 뿐 하류가 읽지 않는다.** 특이도 가중을 실제로 걸려면
점수식을 고쳐야 하고, 그것은 재측정이 아니라 **새 방법이므로 §2 전체를 탄다.**
`RejectionReason` 역시 검색 신호가 아니라 층화 재료다. 따라서 **개념링크가 변하지 않으면
ΔR₁₀₀ 은 0 에 가깝고, T1 은 D-19 때처럼 "통과했으나 아무것도 검정하지 않은" 상태가 된다.**

**그래서 실행 전에 도달 통로를 먼저 잰다(E9).** 두 팔의 `ir_corpus.parquet` **개념링크 열의
sha256 을 비교**해서 동일하면, 판정은 `Accept=1` 이 아니라 **"미검정(vacuous)"으로 기록한다.**
공허한 통과를 승인으로 적지 않는다 — D-19 에서 이미 한 번 치른 값이다.

## 4. 판독 B — B층 확증분할 H3 재확증

### 4.1 승계 — PLAN-031 §4·§5·§6 을 그대로 쓴다

주지표 family-level R@100 · **H3 판정은 R@100 과 nDCG@20 둘 다 개선해야 지지** ·
질의단위 paired bootstrap 10,000회 양측 · 절제 가족 Holm(m=8) · 후보 F10 마스크 후 상위 1,000 ·
**개봉 최종 1회** · 가중치·임계는 **기존 dev 에서만** 선택하고 신규 분할로 재선택하지 않는다.
**신규 분할의 출원연도·IPC·정답 언어 분포를 기존 test 와 대조해 개봉 전 공개**하고,
**기존 test 결과와 직접 비교하지 않는다**(B층은 자체 완결적 확증이다).

### 4.2 개봉 전 차단 게이트 — 통과 못하면 **개봉하지 않는다**

| | 게이트 | 합격선 | 값 |
|---|---|---|---|
| G1 | **B층 정답 도달성**(분모 **503** · NPL 11 별도 · 총계 514 병기) | **≥ 0.95** | `[vendor·조립 후 기입]` |
| G2 | 관할별 본문 확보율 | 합계로 뭉치지 않고 관할별로 보고 | `[기입]` |
| G3 | `make leakage` — 금지 간선 | **0** | `[기입]` |
| G4 | 스냅샷 서명 4파일 sha256 | 사전등록에 기입 후 실행 | `[기입]` |
| G5 | 봉인 qrel 해시 **불변** | B층 `qrel_b_sealed.parquet` = `127a138f1c1651676ea81b9ecf50aa53e0172ca4ee7ff0c5b8f26e9d171db4c3`(538행·질의 200) · A층 `qrel_test_sealed.parquet` = `984f8ef3…fda2c` | 대조 |

**G1 이 실패하면 §9.4 가 다시 발동한다** — 개봉하지 않고 원인을 보고한다. 상류 실측
482/503 = 0.9583 은 **상류 그래프에서의 값**이고, 하류 후보 코퍼스에서 다시 재는 것이 G1 이다.
**두 값이 다를 수 있는 자리가 있다** — PLAN-031 §10.3 이 지적한 **KR 키공간 불일치**(qrel 은
공개번호 · 코퍼스 KR 문서는 출원번호)는 CR-008 이 해소한 문제가 아니다. 그것이 남아 있으면
G1 은 상류 값보다 낮게 나온다. **낮게 나오면 낮은 대로 보고하고 멈춘다.**

## 6. 이 사전등록이 하지 않는 것 (비목표)

1. **df 가중을 넣지 않는다.** 점수식 변경은 새 방법이며 별도 사전등록(§2 전체)이다.
2. **`w_h`·τ·α·RRF·토큰화·Dense 모델을 건드리지 않는다.** 바뀌는 것은 자원과 코퍼스 증분뿐이다.
3. **A층 test 로 H3·H4·H5 를 재확증하지 않는다.** 이미 개봉된 표본이다(§2.1 안전장치).
4. **청구항 단위 조항 발행을 기다리지 않는다.** 출원 단위로 확정했다(HANDOFF-QUEUE §1.8 ①).
5. **C2′(RQ5) 전달 실험을 이 사전등록에 넣지 않는다.** 검색 층 결과가 확정된 뒤다.

## 7. 실행 순서 — 중간 승인 없이 관통한다

```
(0) 상류 회신 접수: US 2건 재시도 결과 + (해소 시) concept_mapping 재발행 sha256
(0-b) 현 data/external/sdkb/ (= O′) 를 별도 경로로 복사 · 서명 기록  ← 덮이기 전에
(1) vendor.py VENDOR_FILES += {abox_term_aliases.json, sdkb-abox-claim-features.ttl}
(2) make vendor          → §4.2 G4 서명 기입 → **커밋(= 사전등록 완성)**
(3) make corpus          → 문서 증분 프로파일(§4 의무) · B층 도달성 G1 · 두 팔 코퍼스 E8
(4) make index → make leakage(G3)
(5) make retrieve → eval → gate   ← 판독 A 의 T1·T2·T3
(6) B층 개봉 1회 → eval → ablation ← 판독 B 의 H3
(7) make figures
(8) 결과 보고 → 그 다음에 C0(대장·CR 회신 배치 처리)
```

**(2) 의 커밋 전에는 (3) 이후를 돌리지 않는다.** 순서를 뒤집으면 사후 사전등록이다.
**(5) 와 (6) 사이에 판정 기준을 고치지 않는다.**
