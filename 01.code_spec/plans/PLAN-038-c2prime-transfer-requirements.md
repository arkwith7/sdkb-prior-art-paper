## 0. 한 문장

**생성기를 완전히 고정하고 검색팔만 B3 ↔ P1 로 바꿔, 검색 층의 이득이 생성 층(근거를 붙여 답하는
단계)으로 **전달되는가**를 잰다. RAG 방법을 제안하지 않는다 — 같은 벤치마크의 두 번째 판독이다.**

## 2. 한 논문으로 유지하는 네 규칙의 이행 (§0.5)

| 규칙 | 이 설계에서의 이행 |
|---|---|
| ① 생성기는 상수, 검색팔만 변인 | 모델 ID·프롬프트·온도·시드·컨텍스트 K 동결. 바뀌는 것은 **B3 냐 P1 이냐** 하나뿐 |
| ② 같은 벤치마크의 두 번째 판독 | 같은 test 질의 · 같은 qrel · 같은 분할 · 같은 누출 통제 · **동결된 run 파일** 사용. **새 질의셋을 만들지 않는다** |
| ③ 기여에 올리지 않음 | 위 §1 |
| ④ "RAG 성능"이 아니라 "전달" | 문서·코드·표 제목에 `transfer` 를 쓴다 |

**선제 방어(§0.5).** 한계에 미리 적는다 — *"본 연구는 RAG 방법을 제안하지 않는다. 생성기를 상수로
고정하고 검색팔만 바꾼 전달 실험이며, RAG 방법 간 비교는 별개의 연구 질문이다."* 그러므로
GraphRAG·HyDE 등 RAG 계열 기준선을 **붙이지 않는다** — 붙이는 순간 논문이 둘로 갈라진다.

## 5. 반드시 사전에 동결할 것 — §1-11 다섯 금지의 이행

**이것이 이 사전등록의 본체다.** 생성 층을 넣는 순간 새 부정 경로가 열리고, 아래가 없으면 C2′ 는
**원리적으로 검증 불가**다.

| 금지 | 동결 대상 | 상태 |
|---|---|---|
| 프롬프트를 결과 보고 고치지 않는다 | 프롬프트 전문 · 모델 ID · 온도 · 시드 · 컨텍스트 K | **미결 1**(모델) · 나머지 3단계 |
| 판정자에게 정답을 보여주지 않는다 | **기본 채점 = 인용 식별자 대조(결정적)** · LLM 판정자는 보조 + 사람 표본 검증 | 설계 확정 |
| 비결정성을 숨기지 않는다 | 온도 0에서도 **반복 실행 분산 보고** — 반복 횟수 동결 | 3단계 |
| 모델 버전을 고정한다 | 모델이 바뀌면 재측정이 아니라 **새 실험** | 3단계 |
| 검색 지표로 생성 성능을 대체하지 않는다 | R@100 개선을 "RAG 가 좋아졌다"로 쓰지 않는다 | 결론 규칙 표에 행 추가 |

**미결 1 (2단계에서 확정) — 생성 모델.** 현재 저장소가 실제로 쓰는 Bedrock 모델은 임베딩
(`amazon.titan-embed-text-v2:0`)뿐이고 **생성 모델 경로는 없다**(`src/` 에 호출 코드 없음).
2단계에서 ① 실제 접근 가능한 모델 ② 198질의 × K문서 × 반복의 **비용·시간** ③ 한국어 장문
(질의 중앙값 527자 · 문서 2,255자) 처리 가능성을 확인한 뒤 3단계에서 동결한다.
**모델을 고르기 전에 프롬프트를 쓰지 않는다.**

**미결 2 (2단계에서 관찰) — 컨텍스트 K.** 문서가 길어(2,255자) K 를 크게 잡으면 컨텍스트가 넘친다.
K 는 **두 팔에 동일**해야 하며, 검색 이득이 나타나는 깊이(R@100 은 100위, 그러나 §6.3a 는 이득이
얕은 깊이에 없음을 보였다)와의 관계를 보고 정한다. **K 를 결과 보고 조정하면 §1-11 위반이다.**

## 7. 지위 문제 — 이것이 확증이 되려면 (가장 중요한 미결)

**개봉된 A층 test 에서 수행하면 §2.1 에 걸려 또 탐색적이다.** 그러면 T4 발효 조건 ②(임계를 결과
보기 전에 동결)는 만족해도 ①(1회 완주)의 지위가 약해진다. 선택지는 셋이고 **결과를 보기 전에**
골라야 한다.

| | 안 | 성질 |
|---|---|---|
| **가** | A층에서 수행 · **탐색적 판독 + 계측기 검증**으로 명시 | 지금 실행 가능 · 확증 아님 · T4 는 "1회 돌려 봤다"까지 확보 |
| **나** | B층 확증 분할 개봉과 **묶어** 수행 | 확증 가능 · **CR-008 선결**이라 상류 대기 |
| **다** | 가 → 나 **2단계**: A층에서 계측기·프롬프트·K 를 동결하고, B층에서 그 동결값으로 확증 | 비용 2배 · 그러나 **B층에서 프롬프트를 고르는 일이 없어진다** |

**권고는 다.** A층 실행의 목적을 "결과 산출"이 아니라 **"계측기 동결"** 로 규정하면, §1-11 의 첫
금지(프롬프트를 결과 보고 고치지 않는다)를 구조적으로 지킬 수 있다. A층에서 얻은 수치는 §6 탐색적
표에만 싣는다.

### ✅ 결정 (2026-08-03 · 사용자 승인) — **다 · 2단계**

| 층 | 목적 | 지위 | 산출물의 자리 |
|---|---|---|---|
| **A층** (지금) | **계측기 동결** — 프롬프트·K·온도·채점기를 확정한다 | **탐색적** | §6.8 탐색적 표 · "확증"이라 쓰지 않는다 |
| **B층** (CR-008 완주 후) | **확증** | 확증 | §6.8 본표 · §0.3 조건 1을 채우는 자리 |

**이 결정이 지금 무엇을 고정하는가.** A층 산출물은 **확증이 아니다** — 그러므로 A층 수치를 보고
프롬프트나 K 를 고치는 것은 허용되지 않는다(고치는 순간 B층 확증이 사후 조정이 된다). A층이
허용하는 유일한 되먹임은 **계측기가 작동하지 않는 경우의 수정**이다 — 파싱 실패·출력 형식 붕괴·
채점기 예외처럼 **판독값과 무관한 고장**. 판독값을 보고 하는 수정은 어느 것도 허용되지 않는다.
이 구분을 3단계 §12.4 에 검사 가능한 형태로 적는다.

## 8. 성공기준 (검정가능)

1. 두 팔의 **입력 차이가 검색 run 하나뿐**임을 코드가 강제한다(프롬프트·모델·K·시드 동일성 단위 테스트).
2. 채점이 **결정적**이다 — 같은 생성 출력에 대해 채점 2회 실행 시 바이트 동일.
3. **반복 실행 분산이 보고된다** — 0 이 아니어도 그대로 싣는다.
4. 생성 출력 원문이 **전량 보존**된다(재채점 가능 · raw 커밋 금지 §1-5 준수 → 해시와 집계만 커밋).
5. 누출 감사: 컨텍스트에 **질의 자신·같은 패밀리**가 들어가지 않는다(§1-4 · 기존 `CandidateMask` 재사용).
6. 결론 규칙 표에 "검색 지표로 생성 성능을 대체하지 않는다" 행이 추가된다.

## 11. 2단계 분석 (2026-08-02 · **생성 호출 0 · 코드 0**)

### 11.0 결론 먼저 — 셋

1. **두 팔은 얕은 깊이에서 실제로 다르다.** B3 와 P1 의 상위 10건 겹침은 평균 **0.163**(Jaccard)이고
   **198질의 전부에서 상위 10건 집합이 다르다.** 전달 실험이 "같은 컨텍스트를 두 번 넣는" 헛일이
   될 위험은 없다 — 이것이 2단계가 확인해야 했던 첫 번째 사실이다.
2. **그러나 P1 이 얕은 깊이에서 더 나은 것은 아니다.** 문서 단위 P@10 은 B3 0.0465 · P1 0.0439 로
   **B3 가 근소 우세**다. 전달 실험은 "이득이 전달되는가"가 아니라 **"얕은 깊이에서는 이득 자체가
   없다는 §6.3a 관측이 생성 층에서도 재현되는가"** 를 묻게 된다. 이는 §6 양방향 사전등록의 범위
   안이지만, **문구를 지금 고쳐 두어야 한다**(§11.4).
3. **모델 선택에 사전등록상 결정적인 제약이 하나 있다 — `temperature` 다.** 최신 모델
   (Claude Sonnet 5 · Claude Opus 5)은 **`temperature`·`top_p`·`top_k` 를 거부한다(400)**.
   §1-11 은 "온도·시드를 동결"하라고 요구하는데, 그 모델들에서는 **온도를 명시적으로 0 으로
   고정하는 것이 원리적으로 불가능**하다. Claude Haiku 4.5 는 받는다.

### 11.4 사전등록 문구 교정 — §6 주 판독의 재진술 (3단계 동결 대상)

현 §6 은 *"P1 팔의 인용 정확도가 B3 팔보다 높은가"* 를 주 판독으로 둔다. §11.2 를 보면 이 문장은
**얕은 깊이에서 P1 이 이길 이유가 없다는 것을 이미 아는 상태**에서 쓴 것이 되므로 그대로 두면
사후 조정처럼 읽힌다. 아래로 재진술한다 — **양방향은 그대로이고 기대의 방향만 명시**한다.

> **주 판독(재진술).** 검색 층에서 P1 의 이득은 **깊은 회수에 한정**되고 얕은 깊이에는 없다
> (§6.2·§6.3a). 따라서 상위 K 컨텍스트를 쓰는 전달 실험에서 **P1 이 B3 를 이길 것으로 기대하지
> 않는다.** 묻는 것은 **층 사이의 어긋남이 한 층 더 아래에서도 관측되는가**이다.
> ⓐ 이겼다 → 검색 지표가 못 본 가치가 생성 층에 있다 · ⓑ 비슷하다 → R@100 개선이 생성 층으로
> 전달되지 않는다(T4 필요) · ⓒ 졌다 → 어긋남이 세 번째로 관측된다(I1 강화).
> **세 결과가 모두 같은 논지로 수렴한다**(§0.5-4).

**함께 동결할 보고 규칙 둘.** ① 인용 정확도는 **전체**와 **근거 존재 질의 조건부** 두 가지로 보고한다
(§11.2 의 천장 때문). ② family 단위와 문서 단위를 섞지 않는다 — §11.2 는 문서 단위이며 주분석
지표(family R@100)와 **분모가 다르다**(CLAUDE §0 분모 규율).

### 11.5 출력 자리 — **§6.7 은 이미 차 있다**

§10 승인 3번이 제안한 "§6.7 신설"은 성립하지 않는다. 원고 `paper/논문_v0_9_SDKB_통합초안.md:1071`
의 **§6.7 은 "자원만 갈아 끼웠을 때 — 게이트가 실제로 거부한 사례"** 이고, 본문 7곳이 그 번호로
그 내용을 가리킨다(요약 · §2.3.1 · §7.5 · §8.1.2 등). 번호를 재사용하면 **그 7개 참조가 전부
어긋난다.**

대안은 **§6.8 신설**이다 — §6.7 이 "자원 층 → 검색 층의 어긋남", §6.8 이 "검색 층 → 생성 층의
어긋남"이 되어 **두 절이 나란히 §7.5 의 논지를 받친다.** 3단계 승인 대상.

3. **§11.7 비용표는 Bedrock 요율로 다시 만들 수 있게 됐다** — 권한이 확인됐으므로 3단계에서

### 12.2 K = 10 — 규칙과 산출 (성능 미참조)

**규칙(§11.3 · 동결).** *"질의와 K개 문서를 합친 컨텍스트의 95퍼센타일이 모델 컨텍스트 창의
25 % 를 넘지 않는 최대 K."* 창 200,000 토큰 → **예산 50,000 토큰.**

실측 입력: `ir_corpus_v09.parquet`(`claims_independent` 질의 · `text_main` 문서) ·
동결 run `O_pre_linker` 의 B3·P1 상위 K · 198질의 × 2팔 = 396 컨텍스트.
질의 길이 중앙 **554자**(198/198 매칭).

| K | 중앙 | p95(자) | p95(토큰) | 창 대비 | 예산 |
|---:|---:|---:|---:|---:|---|
| 5 | 13,004 | 25,014 | 25,216 | 12.6 % | OK |
| 8 | 20,920 | 37,828 | 38,133 | 19.1 % | OK |
| **10** | **25,811** | **45,333** | **45,699** | **22.8 %** | **OK** |
| 11 | — | 47,778 | 48,163 | 24.1 % | OK(경계) |
| 12 | 30,730 | 53,035 | 53,463 | 26.7 % | 초과 |
| 15 | 38,098 | 62,687 | 63,193 | 31.6 % | 초과 |
| 20 | 50,798 | 83,766 | 84,442 | 42.2 % | 초과 |

**🛑 §11.7 의 토큰 가정은 틀렸다 — 실측 자/토큰 = 0.9920 이다** (가정은 1.2~1.5).
보정 방법: `bedrock:CountTokens` 권한이 없어(§12.5) `InvokeModel` 응답의 `usage.input_tokens`
로 1회 보정했다 — K=20 p95 근처 컨텍스트 83,730자 → **84,406 토큰**. 한국어 특허 본문은
**대략 1자 = 1토큰**이며, 가정대로 1.2~1.5 를 쓰면 **컨텍스트를 20~50 % 과소평가**한다.

**경계 처리 규칙 — 이것도 결과 무관이다.** 규칙만 보면 최대 K 는 **11**이다(48,163 ≤ 50,000 ·
예산의 96.3 %). 그러나 토큰비는 **표본 1건 보정**이므로 오차를 무시할 수 없다. 그래서
**"토큰비에 ±5 % 오차를 얹어도 예산을 넘지 않는 최대 K"** 를 취한다 — K=11 은 +5 %에서
50,571 토큰으로 **넘고**, K=10 은 47,984 토큰으로 **넘지 않는다.** → **K = 10.**
이 보정은 길이만 보고 성능을 보지 않으므로 §1-11 을 지킨다.

### 12.3 프롬프트 전문 (동결 · 이후 수정 금지)

시스템 프롬프트와 사용자 템플릿을 **두 팔에 문자 단위로 동일하게** 넣는다. 팔에 따라
달라지는 것은 `{{DOCS}}` 에 들어가는 10건뿐이다(§0.5-1).

```
[SYSTEM]
당신은 특허 선행기술 조사를 돕는 보조자다. 주어진 후보 문헌만을 근거로 답한다.

규칙:
1. 후보 문헌에 없는 내용을 쓰지 않는다. 모르면 모른다고 쓴다.
2. 모든 주장에는 근거 문헌의 식별자를 [DOC_ID] 형식으로 붙인다.
3. 근거가 되는 문장을 후보 문헌에서 그대로 인용한다(요약하지 않는다).
4. 아래 JSON 형식으로만 출력한다. 다른 텍스트를 덧붙이지 않는다.

출력 형식:
{"cited": ["<DOC_ID>", ...],
 "evidence": [{"doc_id": "<DOC_ID>", "quote": "<문헌에서 그대로 옮긴 문장>",
               "why": "<이 문장이 왜 선행기술로서 관련되는가 · 2문장 이내>"}],
 "insufficient": <true|false>}

"cited" 에는 실제로 선행기술로 관련된다고 판단한 문헌만 넣는다. 하나도 없으면 빈 배열과
"insufficient": true 를 쓴다. 억지로 채우지 않는다.

[USER]
아래는 어떤 특허출원의 독립항이다.

<청구항>
{{QUERY_CLAIMS}}
</청구항>

아래는 검색된 후보 문헌 10건이다.

<후보문헌>
{{DOCS}}
</후보문헌>

이 출원의 신규성·진보성을 판단할 때 근거가 될 수 있는 선행기술 문헌을 위 후보 중에서만
고르고, 지정된 JSON 형식으로 답하라.
```

`{{DOCS}}` 의 각 건은 `[DOC_ID] <text_main>` 형태이며 **순위 순서**로 넣는다.
**팔 이름·시스템 이름·"온톨로지" 같은 단어는 프롬프트에 넣지 않는다** — 모델이 어느 팔인지
알면 그것이 변인이 된다.

### 12.4 A층에서 허용되는 유일한 수정 — "고장"의 정의

§7 결정에 따라 A층은 계측기 동결이 목적이므로, **판독값을 보고 하는 수정은 전부 금지**다.
허용되는 것은 아래 넷뿐이며, 발생 시 **수정 전후를 기록하고 A층을 전량 재실행**한다.

| 허용 | 판별 기준 |
|---|---|
| JSON 파싱 실패 | 출력이 스키마를 만족하지 않는 호출이 **≥ 5 %** |
| 출력 절단 | `stop_reason == "max_tokens"` 가 **≥ 5 %** |
| 채점기 예외 | 식별자 정규화 실패로 대조가 불가능 |
| API 오류 | throttling·5xx (재시도로 해결되면 수정 아님) |

**금지의 예 — 이렇게 쓰면 위반이다.** *"인용 정확도가 낮아서 프롬프트에 예시를 추가했다"* ·
*"P1 이 져서 K 를 20 으로 늘렸다"* · *"환각률이 높아서 규칙 5를 넣었다"*. 셋 다 판독값을
본 뒤의 수정이다.

   K=11 을 버린 결정은 **실측에서 그대로 맞았다**(K=11 환산 ≈ 51,900 > 50,000). 동결값을
   바꿀 이유가 없으므로 **K 는 10 그대로다.**
3. **자/토큰 = 0.972**(B3 0.9718 · P1 0.9741). §12.2 의 1건 보정값 0.9920 보다 약간 작고,
