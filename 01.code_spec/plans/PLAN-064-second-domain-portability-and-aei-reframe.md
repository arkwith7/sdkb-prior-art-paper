# PLAN-064 (v2) — 제2 공학 온톨로지 이식 시연(EP5)과 AEI 투고 프레이밍 재구성

> **v2 개정(외부 검토 반영).** EP5 설계 8항 · 프레이밍 2항 · 기존 원고 교정 6항을 편입했다. 개정 항목은 `[v2]` 표기.
> 판정·수치·봉인 변경 0 은 그대로다.

**대상.** ① 게이트 코드(`src/sdkb_paper/validate/*`)의 자원 비의존화 ② 제2 도메인 실험 1건(EP5) ③ 원고
§2·§3·§4·§5·§6·초록·표 12 ④ `verdicts.yaml` ⑤ `submission_check.py` ⑥ README ⑦ **영문 정본**(D단계).
**원칙.** 기존 판정·수치·봉인 **변경 0**. EP5 는 새 사전등록이며 SDKB 실험의 결과를 고치지 않는다.
**목표 상태.** "DP 의 이전 가능성은 주장"(표 12 ⑤ 결손)을 "형식 층과 교차 태스크 층은 제2 도메인에서
실측"으로 바꾸고, 그 사실이 AEI 심사위원에게 서론·초록·§6 에서 보이도록 원고를 재배치한다.

## 0. 결론 먼저 — 무엇을 주장할 수 있고 무엇을 주장하면 안 되는가

EP5 가 이식할 수 있는 것은 **L0–L3 + T3 + 결함주입(EP2 형)** 이다. T1·T2 는 도메인별 태스크
벤치마크(정답·후보풀)가 필요하므로 이식하지 않는다. 따라서 EP5 의 결과로 승격할 수 있는 원리는
**DP3(교차 태스크 감시)** 하나이고, DP1·DP2·DP4 는 등급 불변이다. 이를 결과 확인 이전에 §3 에
적고 `verdicts.yaml` 에 금지 문구로 박는다. "이전 가능성이 확인되었다"는 단정은 금지하고
"형식 층과 교차 태스크 층에 한정하여 제2 도메인에서 동일 절차로 판정하였다"만 허용한다.

EP5 이후에도 주장할 수 없는 것 다섯을 명문화한다 `[v2]`: ① 전체 T-gate 의 도메인 독립성 ② 제2 도메인의
태스크 성능 비열등성 ③ 제2 도메인의 하위집단 비회귀 ④ DP1·DP2·DP4 의 2도메인 실증 ⑤ 승인된 변경의
사후 안전성. 허용 문구는 *"cross-domain evaluation of the formal and cross-task layers"* 까지다.

EP5 의 판정은 **어느 쪽이든 싣는다.** T3 가 제2 도메인에서 교차 결함을 단독 검출하지 못하면 그
결과와 함께 DP3 의 "경험적 도전 조건"(§6.4)이 부분 성립했음을 적는다. 표를 채우려고 결함 강도나
CQ 를 사후에 조정하지 않는다.

## 2. EP5 실험 설계 (사전등록 초안 — 발효 전)

### 2.1 구성요소

| 구성 | 내용 |
|---|---|
| **A-Box 분리** `[v2]` | **개발 건물 1–2개**(CQ·expect-min 작성·조정 전용) / **홀드아웃 건물 1–2개**(결함주입·실제 델타 판정 전용). 두 집합의 모델 식별자·sha256 을 사전등록. CQ 가 특정 예제 건물에 맞춰졌다는 비판을 구성으로 차단 |
| **그래프 계보** `[v2]` | T-Box 를 **고정된 연속 릴리스 계보**로 둔다: 1.3.0 → 1.4.0 → 1.4.1 → 1.4.2 → 1.4.3 → 1.4.4 (착수 시 실재 확인 · 존재하는 릴리스만 사용). 홀드아웃 A-Box 를 각 T-Box 에 얹어 `D0…D5` 를 만들고 인접 쌍마다 L0–L3+T3 를 1회 적용 → **실제 델타 최대 5건**. 서로 독립 표본은 아니므로 "연속 릴리스 계보 n건"으로만 기술 |
| **이행 조건 2종** `[v2]` | 각 델타를 **두 고정 조건**으로 실행하고 둘 다 보고한다: (R) *raw migration* — A-Box 원본 그대로 새 T-Box 에서 실행 · (N) *officially normalized migration* — 공식 alias/deprecation 규칙 적용 후 실행. "실패 시 alias 해소 후 재판정"이라는 조건부 재량을 제거 |
| **L0** | PROVENANCE(sha256)·신선도 — 기존 모듈 재사용, 프로파일만 교체 |
| **L1** | Brick 내장 SHACL (graph shape) + 델타 shape(신규 클래스는 `brick:deprecation` 주석 필수 등 3–5 개) |
| **L2** | HermiT 일관성 — 기존 모듈 |

| **결함주입** `[v2]` | 두 묶음으로 나눈다. **(M) 메커니즘 확인 결함** — 술어 교집합 0 인 T3 전용 술어만 훼손(X1·X2), T3 의 독립 관찰 기능 확인용 · **(S) 현실적 공유 코어 결함** — Equipment–Point–Location 공유 어휘 변경(X3·X4), L3 와 T3 가 모두 관찰 가능하되 영향이 다른 경우. 각 묶음 2종 × 강도 3 × 반복 3 = 18, 합 **36 결함**. 정상 델타는 **30건 이상(권장 60)** — 0/9 의 95% 상한은 약 28% 라 "위양성 ≤5%" 를 뒷받침하지 못하며, 0/30 ≈ 9.5% · 0/60 ≈ 4.9%. 30건이면 "관측 위양성 0/30 · 5% 상한의 정밀 검증은 미달"로 쓴다. **DP3 의 주 근거는 (S) 와 실제 릴리스 델타가 진다**; (M) 은 보조 |

| **운용 비용** `[v2]` | 그래프 트리플 수 · shape·CQ 수 · L0–L3·T3 층별 실행시간 · 최대 메모리를 SDKB 와 Brick 나란히 표로. "scalable" 단정은 금지, 실행 가능성과 비용만 진술 |

### 2.2 CQ 작성 규율 (SPEC-004 준용)

- 모든 CQ 는 `# desc / # expect-min / # suite / # monotone / # target` 헤더를 갖는다(기존 파서 재사용).
- `expect-min` 은 D0 실행 결과를 **보기 전에** 도메인 문헌(Brick 공식 예제·FDD 규칙 문헌)에서 정한다.
  D0 에서 0 행인 CQ 는 지어내지 않고 제거하며 제거 수를 보고한다.
- 각 스위트가 참조하는 술어 집합을 `suite_predicates()` 로 뽑아 **(M) 묶음의 대상 술어만** fdd 와
  교집합 0 임을 자동 검사로 고정한다. `core` 스위트는 공유 어휘를 **의도적으로 참조**하며(그래야
  (S) 묶음이 의미를 갖는다), 그 사실을 CQ 헤더 `# shared: true` 로 표기한다 `[v2]`.
- CQ 작성·expect-min 조정은 **개발 건물에서만** 한다. 홀드아웃 건물에서 0 행인 CQ 는 제거하지 않고
  "홀드아웃 미충족" 으로 보고한다 `[v2]`.

### 2.3 교차 결함 4종 — 두 묶음 `[v2]`

| 묶음 | 결함 | 조작 | 왜 L1–L3(fdd) 를 통과하는가 | 기대 검출 | 비고 |
|---|---|---|---|---|---|
| (M) | **X1 · 계량 포인트 동일-카디널리티 오배선** | `brick:isPointOf` 의 대상을 **같은 타입**의 다른 Equipment 로 치환(Meter 계열 Point 만) | 객체 타입 유지 → `sh:class` 통과 · fdd 비참조 | `meter` — **단, 행 수가 불변일 수 있어 현 T3 v2(존재+행수)가 놓칠 가능성이 큼** | **T3 의 구성 타당도 경계 사례**로 사전 지정. 검출 실패는 결과가 아니라 경계의 실측. 보조로 결과 binding 의 checksum 변화를 **탐색적 지표**로 병기(판정 미편입) |
| (M) | **X2 · 공간 포함관계 역전** | `brick:hasPart`/`isPartOf` (Building–Floor–Room) 일부 역전 | 역관계 제약 부재 → L2 통과 · fdd 경로 미사용 | `space` | 행 수 변화 발생 — v2 로 검출 가능 |
| (S) | **X3 · 공유 관계 동치 오선언** | `brick:feeds` ≡ `brick:hasPart` 를 **`owl:equivalentProperty`** 로 선언 (`owl:sameAs` 금지 — 속성에 쓰면 OWL DL 밖 해석·HermiT 동작으로 L2 가 잡거나 의도가 흔들림) | HVAC 경로 후보가 늘어 fdd CQ 는 통과하거나 "개선" | `core` + `meter`/`space` 복수 스위트 | DP3 주 근거 |
| (S) | **X4 · 공유 어휘 Equipment–Location 재배선** | `brick:hasLocation` 의 대상을 다른 Location 으로 치환(타입 유지) | `sh:class` 통과 · fdd 는 Location 을 조인하지 않거나 행 수 불변 | `space`·`core` 의 분포 회귀 | DP3 주 근거 |

정상 델타 ≥30건: 라벨 보존 재명명 · 공식 deprecation 매핑 부분 적용 · 주석/단위 추가 · 동치 클래스 alias 추가
— `n01/n02` 형을 확장하고 seed 고정. 60건이 일정 안에 가능하면 60으로 올린다.

**T3 v3 는 이 PLAN 에서 설계하지 않는다.** X1 이 드러내는 행수-맹점은 §6.5 결손 표에 "⑨ T3 의
동일-카디널리티 오배선 맹점" 으로 추가하고 해소 측정(결과 집합 해시 비교)을 적는다. SDKB 결과는 소급 변경하지 않는다.

### 2.4 실제 릴리스 델타 계보 판정 `[v2]`

인접 릴리스 쌍 최대 5건 × 이행 조건 2종(R/N) = **최대 10 판정**을 각 1회 실행하고 전부 표에 싣는다.
결과 유형은 셋이다. (a) 전부 통과 → "형식·교차 층을 통과한 실제 델타 n건" (b) L1/L3 실패 →
deprecation 으로 주 태스크 질의 경로 소실 (c) T3 만 실패 → **교차 회귀의 실측**(가장 강한 결과).
R 조건에서 실패하고 N 조건에서 통과하면 그것은 "공식 이행 규칙이 회귀를 흡수한다"는 관측이며,
두 값을 모두 싣고 어느 한쪽을 취소하지 않는다. 재판정 규칙은 없다.

### 2.5 동결 대상

사전등록 문서 `PLAN-064-prereg.md` 에 다음을 적고 커밋 해시를 원고에 인용한다:
개발/홀드아웃 A-Box 식별자와 sha256 · 릴리스 계보 T-Box sha256 · CQ 20 개 전문과 expect-min(개발

### 5.3 구조 승격 (분량 중립)

- 영문 제목은 **현행 유지** `[v2]`: *A Task-Aware Release Gate for Evolving Shared Engineering Ontologies:
  A Design Science Study in Semiconductor Prior-Art Retrieval.* "Second-Domain Port" 류 표현은

  *cross-domain evaluation of the formal and cross-task layers* 로만 서술.
