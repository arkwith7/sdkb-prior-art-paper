## 0. 한 문장

**교정 전 스냅샷 O와 교정 후 스냅샷 O′를 완전히 동일한 파이프라인에 넣어 T1·T2·T3를 적용하고,
지금까지 "미검정"이던 H2(갱신 승인 안전성)를 이 연구 최초로 실제로 검정한다.**

## 0.1 왜 지금까지 H2를 검정하지 못했는가 (D-12)

G0·G1·G2의 T-Box는 완전히 동일하다 — 클래스 103 · ObjectProperty 97 · DatatypeProperty 81, 술어
추가 0 · 제거 0. 세 "세대"는 전부 특허 A-Box 추가(③유형)였고, ③은 H2 자격이 **없다**. 즉 자격 있는
델타가 우연히 없었던 것이 아니라 **한 번도 존재할 수 없었다.** 상류 CR-007이 그 최초의 델타다.

| 검사 | 통과 기준 | 실패 시 |

### 1.2 동결 대상은 커밋 해시가 아니라 **산출물 sha256**

있으므로, 이 사전등록이 붙잡는 것은 `PROVENANCE.json`의 **파일별 sha256**이다(부록 A에 기록).

## 2. 동결 항목 — 결과를 본 뒤 바꾸지 않는다

| 항목 | 동결값 | 근거 |
|---|---|---|
| ε (비열등 마진 · 성능이 떨어지지 않았다고 볼 한계) | **0.02** | CLAUDE.md §5 기존 동결값 **유지** |
| δ (하위집단 국소 회귀 한계) | **0.05** | 동상 |
| 주지표 | **family-level Recall@100** | 동상 |
| 하위집단 축 | 거절근거 · 공정군 · **언어(KR/외국)** | CLAUDE.md §5 T2 |
| CQ 스위트 | pa · em · tf · core (분할 불변) | CLAUDE.md §5 T3 |
| 신뢰구간 | 부트스트랩 95% · 질의 단위 재표집 · **시드 고정** | 기존 `analysis/bootstrap` 설정 그대로 |
| 봉인 qrel | 기존 test 198질의 · 해시 부록 A | 변경 없음 |
| 시점/패밀리 분할 경계 | **O 시점 그대로** | 재계산하지 않음 |
| 파이프라인 | **완전 동결** — 검색 설정 · 가중치(w_h 포함) · 토큰화 · Dense 모델 · RRF 파라미터 · 후보 마스킹 규칙 | 바뀌는 것은 **스냅샷 하나뿐** |

### 2.1 판정식 (사전등록된 승인 규칙의 적용)

```
Accept(O→O′) =  (L0 = L1 = L2 = L3 = pass)
              ∧ (LB₉₅(ΔR₁₀₀) > −ε)              # T1 · ε = 0.02
              ∧ (max_s drop_s < δ)               # T2 · δ = 0.05
              ∧ (∀f ∈ {em, tf, core}: pass_f(O′) ≥ pass_f(O))   # T3
```

**T1은 누출 감사 통과를 전제로만 유효하다.** `make leakage`의 금지 간선 수가 0이 아니면 T1 판정은
산출하지 않고 실패로 보고한다(CLAUDE.md §1-4).

**T3는 통계 검정이 아니라 결정론적 통과율 비교다.** 하락 시 즉시 실패이며, 예외는 waiver 토큰뿐이고
사용 시 횟수를 보고한다.

## 3. 가설과 방향 — 결과를 보기 전에 적는다

**H2 (갱신 승인 안전성).** 게이트를 통과한 자원 갱신은 선행기술 검색 성능을 떨어뜨리지 않고,
하위집단에서도 국소 회귀를 일으키지 않으며, 다른 태스크의 CQ를 뒷걸음치게 하지 않는다.

- **지지**: `Accept = true`
- **기각**: `Accept = false` — 그리고 이때 **어느 조건에서 깨졌는지(T1/T2/T3)가 곧 결과**다.
- **양측이 아니라 비열등성 검정이다.** O′가 O보다 *좋다*는 것을 주장하지 않는다. A층에서 성능 상승이
  관측되어도 그것은 **확증이 아니다** — 표본이 이미 개봉됐기 때문이다(PLAN-029 §2 주의).

### 3.1 사전에 선언하는 기대 — 낮다

CR-007은 **+122 트리플 · 인스턴스 +13**이다. 대장의 핵심 결함 **D-01**(개념 어휘 143개 · 문서당
1.55개 · 40,552 문서를 3,292 동치류로만 구분)은 이 규모로 해결되지 않는다. 따라서:

- **nDCG@20의 회복은 기대하지 않는다.** 회복되지 않아도 그것은 방법의 실패가 아니라 **자원 규모의
  귀결**이며, CR-001·002 병합 전까지는 달라지지 않을 것으로 본다.
- **A층의 성공 기준은 "수치가 좋아지는 것"이 아니라 "H2가 최초로 검정되는 것"이다.** `Accept = true`인
  무변화 결과도 완전한 H2 결과다 — 논문 §8.1의 "미검정" 한계 항목을 §6의 결과 항목으로 옮긴다.
- 이 문단은 **결과를 보기 전에 작성**됐다. 사후에 기대치를 낮춰 적은 것이 아니다(커밋 해시가 증거).

| 산출 | 지위 |

```
  └─ 🔍 §1.1 델타 자격 심사 C-1~C-4  ← 실패 시 여기서 중단·보고
```

**C0(결함 등재·CR 작성)는 이 실행이 끝난 뒤 배치로 처리한다.** 임계경로에 올리지 않는다.

### 5.1 보고 형식

결론 먼저 — `Accept` 값과 깨진 조건. 이어서 T1(ΔR₁₀₀ 점추정·95% CI 하한) · T2(축별 최대 하락) ·
T3(스위트별 통과율 O vs O′) · 누출 감사 결과. 그 다음 탐색적 수치. **기각·무효과는 먼저 알린다.**

## 6. 사용자 결정이 필요한 항목 🛑

**Q. CR-007 단독으로 A층을 개시하는가, CR-001·002·003 병합까지 기다리는가?**

PLAN-029 §2는 A층의 전제를 "상류 **P0 3건**(CR-001 개념 해소 · CR-002 계층 · CR-003 다국어) 완료
후"로 적었다. 현재 상류에 병합된 것은 **CR-007뿐**이다.

| 선택 | 얻는 것 | 잃는 것 |
|---|---|---|
| **A. 지금 개시 (권장)** | H2 검정 기계를 실제로 한 번 돌려 본다 — 지금까지 한 번도 실행된 적 없다. 자격 있는 델타가 최초로 존재하는 시점이다. 무변화 결과도 완전한 H2 결과다. 절차·스크립트의 결함을 P0 델타가 오기 전에 발견한다 | 수치가 거의 움직이지 않을 가능성이 높다(§3.1) |
| B. P0 3건까지 대기 | 한 번의 실행으로 더 큰 델타를 검정 | 상류 일정에 종속. 그동안 실험은 다시 정지하고 문서 작업만 남는다 — **이번 문제를 재생산한다** |

**권장은 A다.** 단, A를 택하면 **CR-001·002·003 병합 후 A층을 한 번 더 돌린다**(각각 별도 사전등록).
H2는 델타마다 반복 적용 가능한 승인 규칙이지 1회성 검정이 아니다.

## 7. 실행 결과 (2026-08-01 · 동결 커밋 `3664e9b` 이후)

### 7.1 결론 — **H2는 이번에도 검정되지 않았다. 이유는 새롭고, 구체적이다.**

델타 자격 심사는 전부 통과했고 **이 연구 최초의 T-Box 술어 델타**(`skos:broader` 선언, +1)까지
관측됐다. 그러나 **그 델타가 검색 파이프라인에 도달하지 않는다.**

`ir_corpus_v09.parquet`의 sha256이 vendor 전후 **완전히 동일**하다(`ec5ea51b626d3ff9`).
`qrel_examiner.parquet`도 동일(`10ab67f21cc1328d`). 즉 O′로 조립한 코퍼스는 O로 조립한 코퍼스와
**바이트 단위로 같다.** 따라서 색인·순위·지표가 모두 동일하며, **O 대 O′의 ΔR₁₀₀은 정의상 0**이다.
0으로 비열등성을 통과하는 것은 H2의 지지가 아니라 **공허한 통과(vacuous pass)**다.

**원인은 확인됐다 — 하류에 적용기(linker)가 없다.**

| 확인 | 결과 |
|---|---|
| `mappings/concept_mapping.json`이 vendor 되는가 | **아니오** — vendor 대상 17파일에 없음 |
| `src/`에 이를 소비하는 코드가 있는가 | **아니오** — `concept_mapping` 참조 0건 |
| 상류의 인계 문구 | CR-007 커밋: *"적용기(linker)는 하류가 구현한다 — 상류는 규칙과 사전까지다"* |

CR-007이 발행한 것은 **규칙과 사전**이고, 그것을 특허 본문에 적용해 개념 링크를 다시 붙이는
코드는 이 저장소가 아직 갖고 있지 않다. 그래서 T-Box와 개념 어휘는 자랐지만(그래프 +125 트리플)
**코퍼스의 개념 링크는 한 개도 바뀌지 않았다.**

### 7.2 게이트 실행 결과 — 그리고 이것을 H2로 읽지 않는 이유

`make gate SPLIT=test` 종합 판정은 `Accept(ΔG) = 1`이었다. **그러나 이것은 H2의 결과가 아니다.**

T-gate가 실제로 비교한 run은 `new = sys_P1_test.txt` · `old = sys_B3_rrf_test.txt`,
즉 **서로 다른 두 시스템**이다. CLAUDE.md가 명시적으로 경계를 그은 그 비교다 —
*"P1 대 B3 비교는 H2의 증거가 아니다 … H2는 변경 없는 동일 파이프라인에 O와 O′를 넣은 비교로만
잰다."* 재현된 T1 수치(구 0.4315 → 신 0.4849 · Δ +0.0534 · 95%CI [+0.0145, +0.0926])는
**기존 H3의 관측치이며, 이번 델타와 무관하다.**

| 항목 | 실측 | 지위 |
|---|---|---|
| L0–L3 | PASS (CQ em/tf/core 각 6/6·5/5·12/12) | 유효 |
| 누출 감사 | PASS · 금지간선 잔여 0 · 검사 run 7개 | 유효 (T1 전제) |
| T1 | Δ +0.0534 · LB₉₅ +0.0145 > −ε | **H3의 재현 · H2 아님** |
| T2 | max drop −0.0140 (pos_lang) < δ | **H3 계열 · H2 아님** |
| **T3** | em·tf·core 1.000 → 1.000 · 하락 0 | **유일하게 O′를 실제로 읽은 조건** |

**T3만이 이번 델타의 진짜 관측이다.** T3는 코퍼스가 아니라 그래프에 CQ를 직접 질의하므로,
+125 트리플·`skos:broader` 선언이 실제로 반영된 상태에서 실행됐다. 결과는 **다른 태스크의 CQ가
하나도 뒷걸음치지 않았다**는 것이다. 이는 H2의 세 조건 중 **T3 하나에 대한 유효한 증거**이고,
T1·T2는 여전히 미검정이다.

### 7.3 §3.1 사전 선언과의 대조

사전등록 §3.1은 "nDCG 회복을 기대하지 않는다 · 성공 기준은 H2가 최초로 검정되는 것"이라 적었다.
**전자는 맞았고 후자는 달성되지 않았다.** 다만 실패의 원인이 사전에 예상한 것(자원 규모 부족)과
다르다 — 자원은 자랐고, **자원이 파이프라인에 연결되지 않았다.** 이 구분은 대장에 등재한다(D-19).

### 7.4 이 결과가 요구하는 것 (C0)

1. **하류: 개념 적용기(linker) 구현** — `concept_mapping.json`을 vendor 대상에 넣고, 특허 본문에
   적용해 개념 링크를 재생성한다. 이것 없이는 CR-001·002가 병합돼도 **같은 일이 반복된다.**
2. **하류: T-gate에 O/O′ 모드 추가** — 현재 하네스는 시스템 대 시스템 비교만 지원한다.
   같은 시스템·두 스냅샷을 넣는 경로가 없으면 H2는 영원히 측정 불가다.
3. **상류: `skos:broader` 증분 보고 정정** — 커밋은 +18, 실측은 11 → 18(+7).

**2번이 선결이다.** 1번을 해도 T-gate가 O/O′를 받지 못하면 H2는 여전히 못 잰다.

## 부록 B — `make vendor`가 gitignore 문제를 해소하는 방식 (실측)

`Makefile:25-27`은 vendor 전에 **상류에서 재빌드를 강제**한다:

```make
vendor:
	$(MAKE) -C $(SDKB_HOME) owl convert abox abox-patents abox-vendors compliance
	uv run python -m sdkb_paper.ontology.vendor --sdkb-home $(SDKB_HOME)
```

따라서 §1.2에서 지적한 "gitignore된 빌드 산출물" 위험은 **절차상 이미 통제돼 있다** — 디스크에 남은
낡은 산출물이 아니라 커밋된 스크립트가 방금 생성한 산출물을 vendor한다. 다만 **재현의 근거는 여전히
커밋 해시가 아니라 sha256**이므로 위 표를 남긴다.
