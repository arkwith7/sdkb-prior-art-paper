# PLAN-048 · 실패 유형 분류표 — 1단계 요구정의 (트랙 C)

*작성 2026-08-09 · 상태: **1단계 요구정의 · 🛑 승인 대기** · 주장: **C4**(DP1·DP6) · 부수 C2·C0*

> **이 문서는 아직 설계도 구현도 아니다.** CLAUDE.md §2 의 1단계(요구정의)이며, 정지 게이트
> 앞에서 멈춘다. **사용자 승인 전에는 코드를 쓰지 않고 데이터도 열지 않는다** — 특히 봉인
> qrel 은 접근 자체가 원장에 남으므로(D-35) 요구정의 단계에서 건드리지 않는다.

---

## 1. 왜 이것인가 — C4 산출물 3종 중 유일한 결손

CLAUDE.md §7 이 요구하는 C4 산출물은 셋이고, 둘은 이미 원고에 있다.

| 산출물 | 원고 위치 | 상태 |
|---|---|---|
| 설계원리 표 (DP1–DP6) | §8.1 | 있음 |
| 경쟁 설명 분석표 | §8.2 | 있음 |
| **실패 유형 분류표** | **§8.3 — "아직 만들지 못한 산출물"** | **없음** |

원고 §8.3 은 이 결손을 숨기지 않고 **이유까지 적어 두었다** — *"하지 않은 이유는 자원이 아니라
방법이다 … 두 번째 코더 없이 이 절차를 밟을 수 없다."* 즉 **막힌 것은 데이터가 아니라 인력**이다.
이 요구정의의 핵심 결정도 거기에 있다(§6).

**AEI 요구 (3) 의 정성 축이 이 표다.** 현재 원고의 정성 근거는 §7.5 ③ 의 사례 하나(공유 개념이
5→9 로 늘었는데 같은 정답이 4위 → 67위로 밀린 질의)뿐이고, 사례 하나는 유형이 아니다.

## 2. 목적 (검정 가능한 형태로)

**온톨로지 팔(P1)이 텍스트 기준선(B3) 대비 순위를 악화시킨 질의를 코딩해, 악화의 유형과 유형별
빈도를 산출한다.** 답하려는 설계 질문은 둘이다.

- **DRQ3** — 자원 품질 개선이 검색 가치로 전달되는 과정에서 **어떤 실패 패턴이 생기는가**
- **DRQ4** — 온톨로지 신호는 **어떤 조건에서** 기여하지 못하는가

**이 표가 DP 를 새로 만들지 않는다.** DP1(층별 검증)·DP6(전달 검증)은 이미 정량 근거로 서 있고,
이 표는 *"왜 어긋났는가"* 의 **후보 메커니즘**을 유형으로 제시한다. §1-12 셋째 금지대로
**부정 결과를 설계원리로 세탁하지 않는다** — 유형은 관측이며, 승격은 별도 판단이다.

**신규로 만드는 데이터는 없다.** 만드는 것은 **표본 추출 결과와 코딩 시트** 둘뿐이다.

**봉인 취급 (§2.1 · D-35).** 두 봉인은 **이미 개봉됐다**(A층 · B층 각각 판정 1회 완료).
이 작업은 §2.1 이 허용하는 **탐색적 재측정**에 해당하고 **확증을 새로 만들지 않는다**.
그럼에도 접근은 **원장에 기록**하고 회차를 줄여 적지 않는다.

## 5. 코더 구성 — **로컬 LLM 2종 + 사람 표본 검증** (2026-08-09 사용자 지시로 개정)

### 5.1 먼저 가를 것 — 이 과제는 §5.5 의 과제가 아니다

사용자 제안의 근거는 둘이었다. **하나는 이 과제에 그대로 적용되고, 하나는 적용되지 않는다.**

| 사용자 근거 | 이 계획에서의 취급 |
|---|---|
| **T-Box 는 선행 유사 온톨로지를 반영한 큐레이션이므로 온톨로지 전문가 판정이 별도로 필요하지 않다** | **적용된다.** 이 표는 T-Box 의 타당성을 판정하지 않는다. 코딩 대상은 **이미 산출된 순위의 악화 사유**이고, 판단 재료는 개념 링크·어휘 중첩·언어·IPC 처럼 **관측 가능한 특징**이다 — 법적·기술적 전문 판단이 아니다 |
| **정답지가 이미 심사관 판단(거절특허 1,000건)이므로 추가 사람 판정이 덜 필요하다** | **부분적으로만 적용된다.** 이 과제에는 맞다 — 관련성 라벨을 **새로 만들지 않고** 기존 qrel 을 그대로 쓰기 때문이다. 그러나 §5.5 의 원래 과제(**qrel 에 없는** 상위 후보가 진짜 오탐인지)에는 **정의상 적용되지 않는다** — 그 후보들은 심사관이 판단한 적이 없다. 그래서 **§5.5 는 여전히 미수행으로 남는다**(§7 비목표) |

**그리고 한 가지는 사용자 표현을 그대로 쓰지 않는다.** 현 실험 결과는 심사관 인용 정답지를
*"반증"* 하지 않는다 — 반증된 것은 *"자원을 개선하면 검색이 좋아진다"* 이지 정답지의 타당성이
아니다. 이 구분을 흐리면 §6.2 의 판정 전체가 흔들린다.

**결론: LLM 코딩이 가능한 이유는 "정답지가 사람 판단이라서"가 아니라, 이 과제가 관련성 판정이
아니라 관측 특징의 유형 분류이기 때문이다.** 근거가 다르면 방어 문장도 다르다.

### 5.2 구성 — 세 코더 (LLM 2 · 사람 1)

| 코더 | 정체 | 대상 | 산출 |
|---|---|---|---|
| **C-L1** | `ollama gemma3:27b` | 악화 질의 **전수** | 유형 라벨 + 근거 문장 |
| **C-L2** | `ollama qwen3-coder:30b` | 악화 질의 **전수** | 동상 |
| **C-H** | **사용자(연구자)** | **층화 무작위 표본** (설계에서 크기 동결 · 규모 감각 40–60건) | 동상 · **LLM 출력을 보기 전에** 코딩 |

**세 코더 전부 가림 상태다** — 시스템명·팔 소속·순위 수치를 입력에서 제거한다(§5.5 승계).
**모델 계보를 일부러 다르게 잡는다**(Gemma 대 Qwen) — 같은 계보 둘은 오류를 공유해 일치도를
부풀린다. `deepseek-r1:14b` 는 예비.

### 5.3 신뢰도 지표 — **두 개를 따로 보고한다. 합치지 않는다**

| 지표 | 무엇인가 | 논문에서의 지위 |
|---|---|---|
| **κ(L1, L2)** | **모델 간 일치도** — 유형 정의가 기계적으로 적용 가능한지 | **재현성 진단**. 코더 간 신뢰도가 **아니다** |
| **κ(C-H, 합의 LLM 라벨)** | **사람–모델 일치도** — §1-11 둘째가 요구하는 *"사람 표본 검증"* | 이 표가 본문에 설 수 있는지의 **결정 지표** |

**두 번째 κ 를 "2인 독립 코딩의 κ" 라고 쓰지 않는다.** 절 제목과 표 머리글에 **"LLM 보조 코딩 +
사람 표본 검증"** 이라 명시한다 — §5.5 가 미수행임을 제목에 박은 것과 같은 방식이다.

### 5.4 성공기준 (사전에 못박는다 · 결과를 본 뒤 고치지 않는다)

1. **표본 규정** — 악화 질의를 사전 정의된 규칙으로 뽑는다(예: `rank_P1 > rank_B3` 인 정답이
   1건 이상 · 층별 전수 또는 층화 표본). 규칙은 **3단계 설계에서 동결**한다.
2. **가림** — 세 코더 모두 시스템명·순위·팔 소속을 볼 수 없다.
3. **유형 목록은 코딩 전에 확정**하고, 코딩 도중 새 유형이 필요하면 **되돌아가 전수 재코딩**한다
   (사후 유형 추가로 빈도를 만들지 않는다).
4. **κ 와 합의율을 함께 싣는다.** 판정은 **사람–모델 κ** 로 한다 —
   **κ(C-H) < 0.4 이면 본문에서 빼고 부록으로만** 싣는다(§1-12 넷째).
5. **불일치는 지우지 않는다** — L1·L2 원라벨, 사람 원라벨, 합의본을 **전부** 보존한다.
6. **LLM 은 계측기이므로 동결한다**(§1-11 넷째·첫째) — 모델 ID·태그·프롬프트 sha256·온도 0·
   시드·컨텍스트 구성을 **코딩 전에** 적고 결과를 본 뒤 고치지 않는다. C2′ 계측기 동결과 같은 규율.
7. **비결정성을 숨기지 않는다**(§1-11 셋째) — 온도 0 에서도 **반복 2회**를 돌려 자기일치율을
   보고한다. 자기일치율이 낮으면 그 사실이 결과다.
8. **순차 실행** — `LLM_WORKERS=1`. 이 장비에서 병렬은 VRAM 이 넘친다(24,463 MiB 중 모델+슬롯
   18,628 MiB).

**실패도 결과다.** κ<0.4 로 본문에서 빠지는 것은 이 계획의 실패가 아니라 **사전에 정한 판정**이며,
그때 §8.3 은 *"만들지 못했다"* 가 아니라 *"만들었으나 신뢰도가 문턱에 못 미쳐 부록에 둔다"* 가 된다.
**둘 다 정직한 결말이고, 둘 다 지금보다 낫다.**

### 5.5 이 구성이 규약을 위반하지 않는 이유 — 그리고 위반할 수 있는 지점

**위반하지 않는 근거 셋.** ① §1-11 은 LLM 판정자를 **금지하지 않고** 조건을 건다 —
*"보조로만 쓰고 쓸 때는 사람 표본 검증을 동반한다."* C-H 가 그 조건이다. ② §1-12 넷째가 금지하는
것은 *"정성 평가를 **정량 부족의 대체물**로 쓰는 것"* 인데, 이 표는 정량 결과(§6.2·§6.7·§6.8)를
**대체하지 않고 그 위에 얹는다** — 판정은 한 글자도 바뀌지 않는다. ③ 관련성 라벨을 **생성하지
않으므로** qrel 을 오염시키지 않는다.

**위반이 되는 지점 셋(넘지 않는다).** ⓐ κ 두 개를 뭉쳐 하나로 보고하는 것 ⓑ 사람 표본을
LLM 출력을 본 뒤에 코딩하는 것(정박 효과 — 순서를 코드로 강제한다) ⓒ κ 가 낮게 나온 뒤
유형 정의를 고쳐 다시 돌리는 것(§1-2). **ⓒ 방지책: 유형 정의와 프롬프트를 커밋한 뒤 실행한다.**

## 6. 🛑 승인이 필요한 것 — 사람 코더의 작업량

이 구성은 **사용자에게 실제 작업을 요구한다** — 가림 상태에서 40–60건을 직접 코딩하는 일이며,
건당 2–3분이면 **2–3시간** 규모다. 이것이 대체 불가능한 이유는 §1-11 둘째가 *"사람 표본 검증"*
을 요구하기 때문이고, 이 한 사람이 빠지면 남는 것은 **모델 둘의 일치도뿐이라 부록행이 확정**된다.

**승인이 필요한 것은 둘이다.** ⓐ 이 구성(LLM 2 + 사람 표본)으로 진행할 것인가 ⓑ 사람 표본
코딩을 사용자가 직접 맡을 것인가. **ⓑ 가 "아니오"면 2단계로 넘어가되 산출물의 목적지를 부록으로
사전 고정**하고 시작한다 — 시작한 뒤에 알게 되는 것이 아니라 미리 아는 편이 낫다.

## 7. 비목표 (이번 계획이 하지 않는 것)

- **새 프로토콜을 만들지 않는다** — 원고 §5.5 를 **재활용**한다(CLAUDE.md §7 명시).
- **§5.5 의 원래 과제(상위 미인용 후보의 관련성 판정)를 수행하지 않는다.** 빌려오는 것은
  *절차*(가림·2인·κ·불일치 보존)이고, *대상*은 다르다(미인용 후보 → **악화 질의**).
  두 과제를 섞으면 §5.5 가 수행된 것처럼 읽힌다 — 그 절의 제목은 그대로 둔다.
- **새 검정·새 확증을 만들지 않는다.** 이 표는 전량 **탐색적·정성**이며 H3·H5·T4 판정에
  한 글자도 영향을 주지 않는다.
- **검색 코드·점수식·게이트를 건드리지 않는다.** 건드리면 §2.1 이 아니라 §2 전체를 탄다.
- **유료 API 호출 0 · 비용 0.** 코딩은 **로컬 ollama 로만** 돌린다(§5.2).
- **LLM 에게 관련성을 판정시키지 않는다.** LLM 이 하는 일은 *"이 질의는 어느 실패 유형인가"*
  이고, *"이 후보가 선행기술로 적합한가"* 가 아니다. 후자는 §5.5 의 과제이며 **여전히 미수행**이다.

# 10. 3단계 설계 — **여기 적힌 것은 코딩 시작과 함께 동결된다** (2026-08-09)

## 10.1 설계의 뼈대 — 기계가 "어느 항"을, 코더가 "왜"를 답한다

P1 의 점수식은 **동결된 상수**로 이미 확정돼 있다(`results_table.py:45`).

```
score(q,d) = 0.25·text_norm + 0.75·( 0.25·concept + 0.00·path + 0.25·ipc + 0.50·fc@τ=0.7 )
```

- `concept` = 질의·문서 개념 집합의 **비가중 Jaccard** · `path` = **가중치 0 → 구조적 비가시**
- `ipc` = IPC 분류 유사도 · `fc` = 질의 청구항 특징 중 문서에 **코사인 ≥ 0.7 로 대응되는 비율**
- **fc 가 전체의 0.375 로 단일 최대 항이다** — 실패의 다수가 여기서 날 가능성이 높다.

**그래서 코딩을 둘로 가른다.**

| 층 | 누가 | 무엇을 | 성격 |
|---|---|---|---|
| **기계 분해** | 코드 | 밀려난 정답과 그 자리를 차지한 경쟁 문서 사이에서 **어느 항이 역전을 만들었는가**(항별 기여 차) | 결정적 · 코더에게 **보여준다** |
| **의미 코딩** | C-L1·C-L2·C-H | **왜 그 항이 그렇게 나왔는가** | 판단 · **κ 의 대상** |

**이 분리가 이 설계의 핵심이다.** 기계가 답할 수 있는 것을 사람·LLM 에게 묻지 않으므로 κ 는
*"판단이 필요한 부분"* 에만 걸린다. §7 의 수기 기입 금지도 이 구조에서 자동으로 지켜진다 —
숫자는 전부 코드 산출이고 손으로 넣는 것은 **라벨 하나**뿐이다.

## 10.2 코딩 단위와 표본 규칙 (**동결**)

- **코딩 단위 = (질의, 밀려난 정답 문헌) 쌍.** 질의 단위로 묶으면 한 질의 안의 서로 다른 실패가
  하나로 뭉개진다.
- **모집단 규칙 (동결):** `R@100 에서 P1 이 B3 보다 낮다` **∨** `P1 순위 − B3 순위 ≥ 20`.
  **임계 20 을 여기서 동결한다** — §9.2 관찰값을 그대로 쓰고 결과를 본 뒤 고치지 않는다.
- **규모 (§9.3 실측):** A층 64쌍 + B층 55쌍 = **119쌍** · 질의 95개.
- **LLM 은 119쌍 전수**, 사람은 **층화 무작위 40쌍**(층 = 층(A/B) × 역전 주도항 · 시드 20260809).
- **경쟁 문서**는 밀려난 정답을 앞지른 문서 중 **P1 상위 3건**을 붙인다(상수 3 동결).

## 10.3 유형 목록 (**코딩 전 동결 · 사후 추가 금지**)

코더는 **주 유형 하나**를 고르고, 필요하면 부 유형 하나를 덧붙인다(부 유형은 κ 계산에서 제외).

| 코드 | 유형 | 정의 (코더에게 주는 문장) |
|---|---|---|
| **F1** | **과잉일반 개념** | 경쟁 문서가 질의와 공유한 개념이 이 분야에서 너무 흔해 변별력이 없다 |
| **F2** | **개념 오부착** | 개념이 표층 문자열 때문에 잘못 붙었다(`ambiguous`·`rule_id`·`surface` 로 확인 가능) |
| **F3** | **정답 자원 결손** | 밀려난 정답에 개념이 없거나 질의와 공유가 0이라 온톨로지 항이 정답을 올려주지 못했다 |
| **F4** | **청구항 특징 오정렬** | 경쟁 문서의 청구항 특징이 임베딩상 질의와 가까우나 실제 기술 내용은 다르다(fc 주도) |
| **F5** | **분류 밀집** | 같은 IPC 분류의 문서가 많아 ipc 항이 변별하지 못했다 |
| **F6** | **텍스트 우위 희석** | 온톨로지 항은 정답에 유리했으나 텍스트 순위의 우위가 α=0.75 에 눌렸다 |
| **F7** | **판단 불가** | 주어진 재료로 유형을 정할 수 없다 |

**F7 을 없애지 않는다.** 강제 선택은 κ 를 인위적으로 올린다. F7 비율 자체가 결과다.

**새 유형이 필요해지면 되돌아가 전수 재코딩한다**(§5.4-3). 코딩 도중 유형을 추가하고 앞부분을
그대로 두는 것은 금지한다.

## 10.4 코딩 시트 — 코더가 보는 것과 **보지 못하는 것**

**보여준다:** 질의 독립항(발췌) · 밀려난 정답 본문(발췌) · 경쟁 문서 3건 본문(발췌) ·
양측 개념 목록과 `surface`/`rule_id`/`ambiguous` · IPC · 언어 · **기계 분해 결과(항별 기여 차)**.

**가린다(§5.4-2):** 시스템명·팔 이름(B3/P1) · 순위 수치 · 어느 쪽이 정답인지.
→ 문서는 `문서 A/B/C/D` 로 익명화하고 **제시 순서를 질의별로 셔플**한다(시드 고정).

**가림의 한계를 미리 적는다.** 기계 분해 결과는 *"어느 항이 역전을 만들었는지"* 를 말하므로
**어느 문서가 밀렸는지는 추론 가능하다.** 완전 가림은 이 과제에서 불가능하며, 가리는 것은
**팔 소속과 정답 여부**다. 이 한계는 결과 표에 각주로 적는다 — 숨기지 않는다.

   분모가 0 에 가까워진 사례다. **양의 델타 합(밀어 올린 힘의 총량)** 으로 바꿔 [0, 1] 로 묶었다.
   테스트가 이 경계를 고정한다.
2. **가림 검사의 거짓 양성.** 시트에서 팔 이름 `P1` 을 부분문자열로 찾자 **IPC 코드
   `B23P11-00`** 이 걸렸다. 토큰 경계 검사로 바꿨다. **검사를 느슨하게 한 것이 아니라
   정확하게 한 것**이며, `B3_rrf`·`rank_*`·`r100_loss`·`lost_doc` 은 그대로 문자열 검사다.

## 11.4a 계측기 고장 하나 — **커밋 전에 잡았다** (설계 §10.8 의 순서가 한 일)

**증상.** 첫 스모크(gemma3:27b · 3단위 × 2반복)에서 **파싱 성공 0/6**. 원문을 보니 JSON 이 아니라
**한국어 분석 산문**이었다 — C2′ §17.2 는 *펜스 뒤* 산문이었고 여기는 **JSON 자체가 없었다.**

**수리 셋.** ① 출력 스키마를 **디코딩 단계에서 강제**(ollama `format` 에 JSON Schema · enum F1–F7)
② 지시를 **사례 뒤에 한 번 더** 붙임(17,191자 입력에서 앞쪽 지시가 묻혔다) ③ 실패 시 **원문
400자를 저장**(첫 구현이 원문을 버려 원인을 못 봤다 — 진단 불가는 그 자체로 결함이다).

**수리 후 실측.** 두 모델 모두 파싱 성공. 그런데 **근거 문장이 분해를 오독했다** — gemma 는
지시를 어기고 영어로 답했고, 두 모델 다 영어 필드명(`delta`·`ipc`)을 엉뚱하게 서술했다.
그래서 시트에 **한국어 `요약` 문장**을 넣었다(예: *"문서 1 이 문서 4 보다 앞선 것은 [IPC 분류
유사도 +0.0440] 때문이고 … 가장 크게 밀어 올린 것은 IPC 분류 유사도(밀어 올린 힘의 100 %)다"*)
+ 프롬프트에 *"`evidence` 는 반드시 한국어"* 를 명시했다.

**이 수정이 §5.5 ⓒ(κ 를 보고 정의를 고치는 것) 위반이 아닌 이유.** 셋 다 **코딩 시작 전**이고,
고친 것은 **유형 정의가 아니라 계측기**이며, 판단 근거는 **라벨 분포가 아니라 파싱 실패와
지시 불이행**이다. 설계 §10.8 이 *"커밋이 코딩보다 먼저"* 로 순서를 잡은 것이 이 자유를 만들었다 —
**커밋 뒤였다면 같은 수정이 위반이 된다.**

**프롬프트 sha256 이 바뀌었다: `91318dde54379097…` → `c372dff1530046d6…`.** 동결값은 후자이며,
표에 실리는 것도 후자다. 봉인 원장 13행 → **14행**(시트 재생성).
