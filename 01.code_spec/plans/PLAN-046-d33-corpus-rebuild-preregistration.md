---

## 0. 이 문서가 하는 일 한 문장

**CR-014 가 상류에 세운 공개일 200/200 을 코퍼스가 아직 읽지 않아 후보 6건이 "공개되기 전에"
후보로 서 있다(D-33 · §1-4 시점유효 위반). 그것을 재조립 1회로 닫는다.**

**여기서 열리는 것은 없다.** 봉인 `984f8ef3…`(A층 test) · `127a138f…`(B층) 는 이 계획 전체에서
닫혀 있고, H3·H4·H5 판정은 한 개도 산출하지 않는다.

---

## 1. 왜 §2.1 인가 — 그리고 왜 §2 전체가 아닌가

| 조건 | 실측 | 판정 |
|---|---|---|
| 검색 설정·가중치·토큰화·Dense 모델·분할 경계 변경 | **없음** | §2.1 적용 |
| 코드 변경 | **없음** — `assemble.py:86` 이 `ont:publicationDate` 를 **이미 OPTIONAL 로 읽는다** | §2.1 적용 |
| 스냅샷 서명 변경 | **있음** — 상류 `212fe62`(CR-014) 로 vendor 완료 · `PROVENANCE.json` 갱신됨 | §2.1 **발동 조건 충족** |

**바뀐 것은 자원이고, 코드는 한 줄도 손대지 않는다.** 그러므로 정지점은 이 문서 하나다.

검색 지표를 산출하더라도 그것은 **탐색적**이고 원고에 싣지 않는다.
**D-32 ⓐ 채택의 대가를 승계한다 — 이 코퍼스로 A층 §6 을 재확증하지 않는다.**

## 4. 실행 (무정지 연속 · 중간 승인 없음)

```
make corpus → make split → make index → make leakage → make gate
```

- `make vendor`·`make baseline` 은 **다시 돌리지 않는다** — 이미 `212fe62` 상태다(§2.1 은
  스냅샷 서명이 바뀐 뒤의 하류 재측정을 말하고, 서명은 이미 바뀌어 커밋돼 있다).
- `make retrieve`·`make eval` 은 **돌리지 않는다.** 이 실행의 목적은 자원 상태 교정이고,
  검색 판정은 판독 B 사전등록(PLAN-040 §4 · PLAN-038 §16.6-2) 아래 **개봉 1회**로만 낸다.
  여기서 돌리면 개봉된 표본 위의 재확증이 되어 §2.1 말미 안전장치를 어긴다.
- `make figures` 도 돌리지 않는다 — 원고 그림은 구 스냅샷 관측이고 소급 수정하지 않는다(§1-3).

## 5. 판정식

**성공 = P1–P4 전부 예측대로 ∧ I1–I8 전부 불변 ∧ `make gate` Accept 유지 ∧ pytest 통과.**

하나라도 어긋나면 **성공으로 쓰지 않는다.** 특히 I3(본문 불변)가 깨지면 이 재조립은 D-33 이
아니라 **새 사실**을 만든 것이므로 즉시 멈추고 대장에 등재한다.

---

## 6. 이 계획이 끝나는 지점

**D-33 종결 + 대장 갱신 + 데이터 프로파일 재발행(§4 의무)까지다.**
그다음은 **개봉**이며, 그것은 이 계획이 아니라 PLAN-031·PLAN-040·PLAN-038 의 일이다.
