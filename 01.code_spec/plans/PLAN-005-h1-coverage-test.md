## 2. 분석 ✅ (2026-07-13 수행 — 코드를 쓰기 전에 관찰한 사실)

### 2.1 관측 단위와 링크 층위

`ont:realizesProcess` 링크를 **직접 연결된 노드 기준**으로 집계했다 (roll-up 없음):

| | G₀ | G₁ |
|---|---|---|
| Process 링크 수 | 1,292 | 7,594 |
| SubProcess 링크 수 | 265 | 4,045 |
| 커버된 Process | 8 / 11 | 9 / 11 |
| 커버된 SubProcess | 8 / 38 | 15 / 38 |
| **커버 합계** | **16 / 49** | **24 / 49** |

CQ01/CQ03 의 16 → 24 와 일치한다. 룰(`code_to_concept.csv`)이 process 층과 subprocess 층
양쪽을 타깃하므로(85 process 룰 · 40 device 룰), 두 층위 모두 실측 링크를 갖는다.

### 2.2 복원 이전 집합(20)은 커밋 이력에서 재현 가능하다

그래프 안에는 복원된 단계를 식별하는 표지가 **없다** — 복원분도 원래분도 똑같이
`dcterms:source = semikong`, `bibliographicCitation = Table 7` 이다 (사실 복원이었으니 당연하다).

대신 **복원 이전의 vendor 스냅샷이 git 에 있다**: 커밋 `eaf8406`
(`data/external/sdkb/`, SDKB `c49dea0`). 여기서 뽑으면 Process 8 + SubProcess 12 = **20개**이고,
그 20개 IRI 는 현재 49개의 **진부분집합**이다 (차집합 0 — IRI 불변 확인).

→ 복원 이전 집합을 **손으로 고르지 않는다.** `eaf8406` 스냅샷에서 추출해
`mappings/process_scope_legacy20.csv` 로 동결하고, 출처 커밋 해시를 함께 적는다.
사후에 유리한 20개를 고르는 여지를 없애는 것이 목적이다.

### 2.3 기존 `analysis/coverage.py` 는 낡았다

docstring 이 "process 8 / subprocess 12", "before 는 특허 0건" 이라고 적혀 있다 —
**G₀ 재정의(특허 1,000건) 이전의 코드**다. SPARQL 자체는 유효하나 전제가 틀렸다. 갱신 대상.

## 3. 설계 — 결과를 보기 전에 확정한다  🛑

| 항목 | 확정값 | 근거 |
|---|---|---|
| 관측 단위 | 공정 단계 s (Process ∪ SubProcess) | H1 의 정의. 특허가 아니라 단계가 표본 |
| C(s) | s 에 `ont:realizesProcess` 로 직접 연결된 **고유 특허 수** | roll-up 없음 (부모로 올리면 중복 계상) |
| 검정 | **Wilcoxon 부호순위, 단측(greater)**, 쌍 표본 (before, after) | CLAUDE.md §0 · 논문 §3.4.3 |
| 0-차 처리 | `zero_method="wilcox"` (동점 쌍 제외) — 제외된 쌍 수를 보고 | scipy 기본. 제외 수를 숨기지 않는다 |
| 효과크기 | rank-biserial r = W₊ / (W₊+W₋) 기반 | 표본 49 로 작아 p 만으로 부족 |
| α | 0.05 (단측) | 사전 고정 |
| 표본 집합 | **① 확장 49 · ② 복원 이전 20** 병기 | PLAN-001 §3.5 · 논문 §5.3(f) |
| 부가 보고 | 층위별(Process 11 / SubProcess 38) 분리 재검정 | 중첩 비독립성에 대한 강건성 (§4.5) |
| 결정성 | 난수 없음. SPARQL → DataFrame → scipy. 같은 그래프 → 같은 수치 | |

### 5.1 설계 수정 (사용자 결정 2026-07-13 — 결과를 본 뒤 고쳤음을 밝힌다)

두 가지를 고쳤다. **검정 절차(단측 · α · 표본 집합 · zero_method)는 사전 확정대로 두었고,
바꾼 것은 보고 방식뿐이다** — 결과가 바뀌지 않았음을 명시한다.

| 무엇 | 왜 |
|---|---|
| 효과크기에서 **rank-biserial r 제거** → 증가 단계 비율 + 증가 단계 중앙값 증가폭 | 병합이 단조 증가라 Δ<0 이 **구조적으로 불가능**하다. r 은 항상 +1 — 설계의 귀결이지 관측이 아니다. 보고하면 독자를 오도한다 (§5.3(g)) |
| H1 문구를 "중앙값 > 0" → **"비영 차이의 유사중앙값 > 0"** | 확장 49 의 전체 중앙값이 0(동점 28/49)인데 검정은 기각한다. 동점 제외의 귀결이지 모순이 아니다. 두 수치를 함께 싣는다 (§3.1 · §4.3) |
