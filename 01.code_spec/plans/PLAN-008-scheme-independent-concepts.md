## 1. 진단 — 우리는 개념을 코드 위에 정의했다

H2 는 "코드 단위 체계가 신기술을 늦게 인식한다"는 가설이다. 그런데 우리의 **개념**(온톨로지)
정의가 바로 그 코드 체계로 쓰여 있었다.

`emerging_concepts.csv` (PLAN-004 동결):
```
HBM(base) = (H10B80 ∨ H10W90) ∧ (H10W20/20 ∨ H10W20/211 ∨ H10W20/023)
```
전부 **H10 스킴 코드**다. 그런데 PLAN-007 이 밝혔듯 **H10 스킴은 2021년 이후 신설**이다.
개념이 코드에 기생하면 **개념이 코드보다 앞설 수 없다.** H2 는 검정되기 전에 이미 졌다.

### 실측 (2026-07-13 · 하이닉스 2010–2015 출원 6,020건)

HBM 을 만들던 그 시기, 그 특허들은 **말뭉치 안에 있었다**:

| 관측 | 건수 |
|---|---:|
| 명세에 **관통전극/TSV** 를 쓴 특허 | 148 |
| 명세에 **"적층"** 을 쓴 특허 | 646 |
| **둘 다** 쓴 특허 (= HBM 의 구성 그 자체) | **54** |
| 명세에 **"HBM"** 을 쓴 특허 (전 말뭉치·전 기간) | **4** |
| 적층 코드 `H01L25/065` | 11 |
| TSV 코드 `H01L23/481` | **0** |
| **우리 `device/hbm` 개념이 잡은 하이닉스 특허 (2010–2015)** | **0** |

특허는 HBM 을 **이름으로 부르지 않고**(4건), 당시 코드로도 잡히지 않으며(TSV 코드 0건),
**구조로 말한다**("적층 반도체 패키지", "멀티칩 구조를 가지는 반도체 집적 회로").
그리고 우리 개념은 그 층위를 보지 못했다.

> **이것이 상식과 측정의 갭이다.** 하이닉스는 HBM 을 2014년 사업보고서에 썼는데 우리 개념
> 시계열은 2018년에야 탐지했다. 특허가 늦은 게 아니라 **우리 정의가 늦었다.**

## 2. 설계 — 개념을 분류체계와 무관한 어휘로 쓴다

**JEDEC JESD235 는 HBM 을 "TSV 로 연결된 적층 DRAM 다이"로 정의한다** — 코드가 아니라
**구조**로 정의한다. 온톨로지도 그 층위에서 써야 한다. 그것이 온톨로지가 코드 리스트보다
나아야 하는 이유이고, 이 논문의 논지 자체다.

- **정의의 근거는 외부 원천에서만** 가져온다 (JEDEC 표준 원문 · CPC 스킴 제목).
  우리 데이터 분포에서 고르지 않는다 (CLAUDE.md §1.2).
- **표현 어휘는 시점 불변인 것만** 쓴다: 명세 텍스트(국문·영문 구조 용어) + **당시에 존재하던
  코드**(PLAN-007 이 결정적 규칙으로 뽑은 선행 코드 — `H01L25/0657` 등).
  신설 H10 코드는 개념 정의에서 **뺀다** (그것이 기생의 원인이다).
- 신호 규칙·판정 규칙·관측창은 **PLAN-006 그대로** 둔다. 임계값을 만지지 않는다.

## 3. 외부 준거 — DART 공시 (특허로 특허를 검증하지 않는다)

정기보고서 138건(삼성 65 · 하이닉스 73 · 2010–2025)을 OpenDART `document.xml` 로 전량 확보해
관찰했다. **공시는 제출 시점의 기록이고 소급 수정되지 않는다** — 특허 분류를 무너뜨린 결함이 없다.

| 기술 | 삼성 최초 언급 | 하이닉스 최초 언급 | 외부 사실 |
|---|---|---|---|
| 3D NAND | **2013** | 2014 | 삼성 V-NAND 양산 2013 — 일치 |
| HBM | 2017 | **2014** | 하이닉스가 원조(JEDEC 2013) — 회사별 차이가 사실과 일치 |
| TSV | 2016 | **2012** | |
| GAA | **2020** | 없음 | 하이닉스는 로직 사업 없음 — 없는 것이 맞다 |
| FOWLP | **2019** | 없음 | 삼성 PLP 2019 |
| EUV | **2018** | 2021 | |
| MRAM | 없음 | 2011~ 연 5회 **일정** | ⚠ 상용구 — 부상 신호가 아니다 |
| FinFET | 2017 산발 | 없음 | ⚠ 파운드리 세부는 공시에 드물다 |

- **매출은 준거가 못 된다** (실측): 최고 해상도가 삼성 "메모리" 한 줄 · 하이닉스 "DRAM,
  NAND Flash 등" 한 줄. HBM 매출 항목이 **없다**.
- **준거로 쓸 수 있는 사례**: HBM · 3D NAND · TSV · GAA · FOWLP (+EUV 는 사례 밖).
  **사전 배제**: MRAM(상용구·무언급) · FinFET(산발). 준거가 없으면 없다고 쓴다.
- 준거 신호 규칙(예: 연 언급 ≥N 회 **이고** 보고서 2건 이상)과 정정공시 처리(원제출본만)를
  **시계열을 보기 전에 동결**한다.

## 4. ⚠️ 정직성 규율 (이 계획의 핵심)

1. **사전등록 실패를 지우지 않는다.** A·B·C·C′(전부 미지지)는 커밋에 있고 논문 §4.4 에 싣는다.
   PLAN-008 은 **재정의 후 재검정**이며, 그 사실을 §4.4 · §5.3 에 명시한다.
2. **우리는 이미 데이터를 봤다** (하이닉스 54건). 그 사실을 논문에 적는다 — 그것이 정직한
   사전등록이다. 정의는 그 54건이 아니라 **JEDEC 표준**에서 나와야 한다.
3. **재정의해도 기각될 수 있다.** DART 준거 대비 특허가 앞선다는 보장은 없다 — 하이닉스 HBM
   공시(2014)가 우리 개념 탐지(2018)보다 빨랐다. 기각되면 기각으로 쓴다.
