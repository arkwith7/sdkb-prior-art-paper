### 2.2 신규 평가 집합(가칭 `test_c`) — 모집단과 확보 방법

- **모집단:** 한국 특허 출원 중 (i) 기존 1,000 + test_b 200 과 **출원·패밀리 불교차** (ii) 기존 질의와 같은
  반도체 IPC 틀(B층 동결 21코드 재사용) (iii) 거절이유통지에 **심사관 인용 문헌 ≥1** (iv) 출원일이 지식 원천
  (train 경계 2016-11-21 이전) **이후** — 권장 창: 2018-03 ~ 2020-12(test_b 창 2018-01-02~02-16 제외).
- **확보:** 기존 `collect/b_layer/` 경로(KIPRIS `getAdvancedSearch` → `getBibliographyDetailInfoSearch` →
  `priorArtDocumentsInfo`). 인용 필드는 원장에서 제거하고 봉인 qrel 로만 보낸다(B층 선례). PLAN-031 양식의 포함기준·
  호출 예산을 수집 전에 동결.
- **도달 가능성 사전 점검(B층 실패의 교훈):** 인용 문헌의 서지·청구항·초록 확보율을 **qrel 개봉 없이** 식별자
  해소율로 먼저 잰다. 문턱(예: 해소율 ≥ 0.8)을 수집 전 동결하고, 미달이면 판독을 열지 않는다.
- **후보 코퍼스:** 상류 동결 코퍼스(41,031 · `d8562693`) + 신규 인용 문헌 + **같은 IPC·같은 공개기간 방해문서**
  (인용 여부와 무관한 규칙 표집). 동결 코퍼스가 구성상 정답을 포함한다는 한계(상류 §3.1′-9)를 그대로 상속하므로
  **방해문서를 규칙으로 늘려 정답 밀도를 낮춘다** · 라이브 KIPRIS 표본 확인을 병행(범위 차이 보고, 성능 아님).
- **표본 크기(사전 산정 · 탐색값 기반):** 상류 T4 v1 dev 의 d−b 95% CI 반폭 0.037(n=197)에서 질의별 차의 SD ≈ 0.27.
  차 0.05 를 양측 α=.05 · 검정력 0.8 로 보려면 n ≈ 230. 반복 3회 평균으로 SD 가 줄 수 있으나 보수적으로
  **N = 250 출원(정답 ≥1)** 을 목표로 한다. 이 SD 는 다른 대비(d−b)의 값이므로 **추정**이다.

### 2.3 판단 지식의 원천과 형태

- **원천:** 상류 논증층의 **train 판단 3,664**(블록·논거 범위만 · 좌표·관계 미사용 — FAIL 범위 회피) + train 심사관 인용.

### 2.4 A⓪(혼합 순위 기준선)의 색인 코퍼스와 예산 동치 — **미해결 🛑 (O-26)**

Boolean 팔(A①–A④)은 KIPRIS 를 **실시간으로** 검색하고, 순위 팔 A⓪(BM25 nori + Dense + RRF · 기존 `retrieval/` 스택)은 **고정
색인 코퍼스**가 있어야 한다. 둘을 같은 200건 예산에 올리려면 두 결정이 필요하다.

| 결정 | 선택지 | 비고 |
|---|---|---|
| **코퍼스** | ⓐ 기존 동결 코퍼스 + `test_c` 신규 인용 + 규칙 방해문서(§2.2) 위에서 **다섯 팔 전부** 실행 ⓑ 같은 IPC·공개기간 창으로 **신규 고정 코퍼스** 수집 ⓒ Boolean 팔은 라이브 KIPRIS · A⓪ 는 동결 코퍼스(탐색 지위) | 아래 2.4.1 |
| **예산 동치** | 두 종류 팔 모두 "**검토 문헌 수 ≤ 200(패밀리 병합)**" 으로 정의. A⓪ 는 순위 상위 200, Boolean 팔은 계획 순서 합집합 200 | §3.3 의 "순위화 후 절단 금지" 는 **Boolean 팔 내부 규칙**이다(Boolean 집합에 순위를 매겨 자르지 않는다). A⓪ 는 순위 팔이므로 상위 절단이 정의다. **같은 상한이 같은 검토시간이나 같은 계산 비용을 뜻하지 않는다**(2.4.2) |

#### 2.4.1 선택지별 장단점과 권고 (O-26 권고안 · 2026-10-17)

사실관계 먼저. 상류 T4 v1 의 Boolean 팔은 **라이브 KIPRIS 가 아니라 KIPRIS 문법 에뮬레이터**(상류 `scripts/kipris_emulator.py` · 제목·초록·
청구항 필드 · IPC 접두 일치 + 판 대응 확장 · 집합만 산출)로 **동결 코퍼스 41,031 위에서** 실행되었다(상류 `t4_freeze_v1.json` ·
UPSTREAM-CLOSEOUT §7). 라이브 KIPRIS 는 연산자 의미 일치를 확인하는 표본 점검에만 썼고, 라이브 자유 검색은 상세 설명까지 검색해
건수가 로컬의 수십 배였다(청구항 한정만으로도 중앙값 13.8배 · 상류 live-check). 그러므로 **"Boolean 팔 = 라이브, A⓪ = 동결" 이라는
비대칭은 설계상 필연이 아니다.**

| 선택지 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **ⓐ 다섯 팔 모두 같은 동결 `test_c` 후보 코퍼스** (기존 코퍼스 + 신규 인용 + 규칙 방해문서 · Boolean 은 에뮬레이터 · A⓪ 는 하류 색인) | 모집단 · 검색 텍스트 · 시점 마스크 · 패밀리 병합 · 정답 분모가 **다섯 팔에 동일** · 재현 가능(DB 갱신 영향 없음) · 상류 하네스 재사용 · A⓪ 추가 비용 ≈ 0 | **정답 포함형** 코퍼스(인용을 넣어 만든 건초더미) — 모든 팔에 같은 방향의 편향 · 라이브 회수로 옮겨 적을 수 없음(상류 paper-notes 3) · 에뮬레이터는 부분 문자열 매칭이라 라이브 형태소 정규화와 다름 | **권고** |
| ⓑ 신규 고정 코퍼스(21 IPC × 공개기간 창 전수) | 모집단이 설계된 창 전체 — 정답 포함형 편향 완화 | 21 IPC 2005–2025 모집단 **737,834건(중복 포함)** · 상세 조회 상한(검색 300 / 상세 500 · `config.py`)으로 전수 불가 → 표집하면 다시 **인용을 보강해야 도달성이 선다**(B층 test_b 선례: 인용 514 중 코퍼스 적중 6) → 결국 ⓐ 와 같은 구조에 비용만 더함 | 보류 — 비용·기간 미산출 · 코퍼스 증분 설계는 별도 계획 |
| ⓒ Boolean 라이브 · A⓪ 동결 | 라이브 실무 조건에 가장 가까움 | 두 종류 팔의 **모집단이 다르다** → A②−A⓪ 해석 불가 · 라이브는 갱신으로 비재현 · 건수 13.8배라 예산 200 이 잡음으로 채워짐 · 상세 조회 상한으로 채점용 텍스트 확보도 제약 | 기각(본실험) · 라이브는 **범위 차이 감사**(표본 검색식 24개식)로만 |

**공통으로 맞추는 것(ⓐ 아래).** 모집단 = 같은 코퍼스 · 검색 텍스트 = 제목·초록·청구항(A⓪ 색인 `text_main` 은 초록+청구항이므로 **제목
포함 여부를 한쪽에 맞춘다** · 결정 항목) · 시점 = 공개일 < 평가 출원의 출원일 마스크(F10) 를 다섯 팔에 동일 적용 · 패밀리 = 병합 후 1문헌 ·
정답 = 분모 A(코퍼스 안에서 해소된 비NPL 고유 인용) · 다섯 팔 **동일 분모**.

**정답을 보고 코퍼스를 고르지 않는다.** 코퍼스 구성(기존 코퍼스 + 신규 인용 삽입 + IPC·공개기간 층화 규칙 방해문서 N건)은 **qrel 개봉 전에
규칙으로 동결**하고 sha 를 사전등록에 적는다. 정답 의존 단계는 "인용 삽입" 하나뿐이며 이것은 현 설계가 이미 공개한 정답 포함형 성질이다.
방해문서 수·층화 규칙을 결과를 본 뒤 바꾸지 않는다.

**미확정 사실 1건.** 하류 `ir_corpus_v09.parquet` 는 MANIFEST 에 **40,552행 · `ec5ea51b`** 로, 상류 동결 코퍼스는 **41,031 후보 · `d8562693`**
(프로파일에는 41,223행 · 같은 sha)로 기록돼 있다. 같은 원천에서 온 다른 판이다. **어느 파일이 `test_c` 의 기반인지는 사전등록에서 sha 로 못박는다** — 지금 고르지 않는다.

#### 2.4.2 "같은 200건" 의 뜻 — 다른 후보 구성 방식

A⓪ 의 상위 200 은 **텍스트 유사도 순위**의 절단이고, Boolean 팔의 200 은 **검색식 단위 집합의 계획 순서 합집합**이다. 같은 것은 "검토자가
읽을 문헌 수의 상한" 뿐이다. 다음을 동일하다고 해석하지 않는다 — (i) 검토시간(문헌 길이·언어 분포가 팔마다 다를 수 있다 → 언어·길이 분포를 함께
보고) (ii) 계산 비용(A⓪ 은 LLM 호출 0 · Boolean 팔은 호출 12 + 토큰) (iii) 후보의 성격(순위 팔은 "비슷한 문서", Boolean 팔은 "조건을 만족하는
문서"). 예산은 **검토 상한의 통제**이지 비용 동등화가 아니다.

#### 2.4.3 각 비교에서 해석할 수 있는 것

| 비교 | 함께 달라지는 것 | 해석할 수 있는 것 | 해석하지 않는 것 |
|---|---|---|---|
| **A④ − A②** (주) | 판단 지식 **내용** + **온톨로지 제공 방식** | "판단 지식을 온톨로지 도구로 제공한 조건" 의 합성 효과 | "지식 내용만의 효과"(그것은 A③−A②) · "온톨로지만의 효과"(그것은 A④−A③) |
| A③ − A② | 판단 지식 내용(표 제공) | 지식 내용의 효과(제공 방식 고정) | — |
| A④ − A③ (부) | 제공 방식(표 → 도구) · 지식 집합 sha 동일 | 제공 방식의 효과 · 동등성 ±Δ | — |
| A② − A① (참조) | 지시문(요소 분해) **+** Agent 루프(단일 호출 → 턴 24) | "요소별 Agent 절차" 대 "단일 호출 검색식" 의 차이 | 지시문 효과와 루프 효과의 **분리**(함께 바뀐다) |
| A② − A⓪ (참조) | 모델 · 절차 · 후보 구성 방식(집합 대 순위) 전부 | 최신 AI Agent 가 기존 혼합 검색의 **기준 수준**에 이르는가 | 어느 요인 때문인지 — **인과효과로 쓰지 않는다** |

**결정 항목 8(신규).** 주 대비를 A④−A② 로 둘지 A③−A② 로 둘지는 "무엇을 중심 주장으로 할 것인가" 의 선택이다 — 전자는 "온톨로지로 제공한
판단 지식", 후자는 "판단 지식 자체". 사전등록 동결 전에 정한다(§3.10-8). 어느 쪽이든 나머지 대비는 보조로 전량 보고한다.

A⓪ 는 LLM 호출이 없으므로 생성 비용 0 · 결정적이다. O-26 이 결정되기 전에는 사전등록을 동결하지 않는다.

### 3.1 비교군

| 팔 | 입력 | 지시 / 방식 | 지식 | 역할(PLAN-095 §0 층위) |
|---|---|---|---|---|
| **A⓪** | 청구항·초록 | **혼합 검색(BM25 nori + Dense + RRF) 상위 200** · LLM 없음 | 없음 | **기존 검색기술의 기준 수준**(참조 · §2.4 미해결) |
| A① | 청구항·초록 | 일반 검색식 작성(상류 b 골격) · 단일 호출 | 없음 | 참조(LLM 단독) |

A②–A④ 의 system·user 골격은 **지식 블록 하나만 다르다**(프롬프트 sha 동결 · 상류 b·d 선례). **추론형 모델 효과 · Agent 효과 ·
지식 효과를 한꺼번에 바꾸지 않는다** — **A②–A④ 안에서는** 모델·추론 설정·프롬프트 골격·**공통 검색 도구**(KIPRIS 문법 검색 · 호출 12)·턴 상한이 같고, 다른 것은 **판단 지식의 유무(A②↔A③·A④)와 지식 제공 도구의 유형(A③ 프롬프트 블록 ↔ A④ 지식 조회 도구 · 호출 6)** 뿐이다(§3.2). A① 은 단일 호출이라 **실행 절차 자체가 다르다** — A①−A② 는 절차 차이를 포함한다(§2.4.3). A② 가 "Agent" 인 이유는
검색 실행 결과를 보고 다음 행동을 고르는 루프(턴 24)이기 때문이고, A① 은 단일 호출이므로 Agent 가 아니다(PLAN-095 §1).

### 3.4′ 작동 기제 — 로그 관측 지표가 먼저, 사람 코딩은 보조 (RQ-B · 2026-10-17 2차 개정)

**1) 로그에서 바로 세는 행동 지표(자동 · 전 질의 · 전 팔).** 검색식 · 도구 호출 · 채택 결과 로그만으로 정의되며 사람 해석이 들어가지 않는다.
정의와 계산식은 사전등록에 동결한다.

| 지표 | 정의(초안) | 읽는 것 |
|---|---|---|
| 요소별 검색 수행 | 계획이 선언한 요소 수 · 실제 실행된 요소별 검색식 수 · 그 비 | 요소 분해가 실행으로 이어졌는가 |
| 요소 범위 | 청구항 요소(상류 한정요소 투영) 가운데 검색식이 다룬 비율 | 어떤 요소가 빠졌는가 |
| 검색식 수정 | 결과 관찰 뒤 변경된 검색식 수 · 수정 단계 수 · 수정 유형(항 추가/삭제 · 필드 변경 · IPC 변경 — 문자열 차이로 계수) | 루프가 실제로 쓰였는가 |
| 대체 표현 | 검색식의 OR 항 수 · 외국어 항 수 · 지식 항목에서 온 항 수(A③·A④ 는 지식 블록과 대조해 계수) | 지식이 표현으로 들어갔는가 |
| 검색 관점 | IPC 한정 사용 수 · 필드 한정 사용 수 · 지식 항목의 관점 축 사용 수 | 관점 확장이 있었는가 |
| 회수 문헌과의 연결 | 각 정답 문헌을 **처음 회수한 검색식**의 요소 · 수정 단계 · 지식 항목 출처 | 근거가 어느 행동에서 왔는가 |
| 도구 소비(A④) | 지식 도구 호출 수 · 응답이 검색식에 반영된 비율 | 제공 방식이 실제로 소비됐는가 |

②(행동) 와 ③(회수·비용) 의 관계는 **상관·기술**로만 보고한다(TM-POSITIONING §3).

**2) 사람 해석이 필요한 분류(원인 코딩 · 미회수 이유 등).** 주요 결과로 쓰려면 **2인 독립 코딩 · κ · 합의율 · 팔 이름 맹검**이 필요하다(§1-12).
평가자를 확보하지 못하면 그 해석은 **탐색적 사례**로 제한하고 본문 결과로 올리지 않는다. **자동 분류(LLM 평정 포함)의 결과를 사람 간 일치도의
대체물로 쓰지 않는다** — 상류 24쌍 원인 표본이 단일 LLM 평정이었던 것이 그 선례이며 "비율 아님" 으로만 인용된다.

### 3.5 분할·시점·패밀리·노출 이력

- 지식 원천: train(출원 < 2016-11-21) · 평가: `test_c`(출원 2018-03~2020-12 권장) — **시점 분리 + 패밀리 불교차**.
- 후보 마스크: 공개일 < 평가 출원의 출원일(기존 F10).
- 개발: 프롬프트·도구는 **train + v1 dev** 에서만 조정(dev 는 이미 노출되었으므로 개발용으로 써도 새 오염은 없다).
- `test_c` qrel 은 봉인, **1회 개봉** · 개봉은 `open_sealed` 경유로 원장 기록. pytest 가 봉인 qrel 을 읽지 않도록
  고정 픽스처를 쓴다(O-14·D-54 재발 방지).
