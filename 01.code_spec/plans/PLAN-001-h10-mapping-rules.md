## 1. 요구정의  🛑

```
목적      : 삼성 특허를 온톨로지 개념(Process ∪ Device)에 매핑할 수 있도록 룰 테이블의
            H10 계열 공백을 메운다. 룰이 없으면 삼성 특허가 L1(델타) 엄격 shape 에서
            탈락하고 H1 의 커버리지 증가가 과소 추정된다.
입력      : mappings/ipc_to_process.csv (현재 39개 접두어)
            IPC/CPC 공식 분류표 (코드별 정의)
            SIRP 의 IPC 분포 (매핑률을 미리 재는 시험대)
출력      : 확장된 룰 테이블. 컬럼: code_prefix, concept_iri, level, scheme,
            code_title, rationale, confidence, status
            + 커버리지 리포트 (make mapping)
성공 기준 : 각 신규 룰이 **코드 정의에 근거한 rationale** 을 갖는다.
            SIRP 를 시험대로 한 매핑률이 개선된다 (현재 447/1,000 = 45%).
비목표    : 매핑률을 높이기 위한 근거 없는 룰 추가. 텍스트 임베딩 기반 매핑(별도 단계).
```

### 왜 지금인가 (실측)

`mappings/ipc_to_process.csv` 의 39개 접두어에 **H10 계열이 하나도 없다.**
그런데 SIRP 의 IPC 분포는 이렇다 (`enrich_kipris_biblio.py` 산출):

```
C23C 786 · H01L 564 · H10P 562 · H10D 332 · H10B 328 · H01J 172
H10W 143 · H10K 124 · G11C 69 · G03F 42
```

H10 은 2023년 IPC 개편에서 H01L 의 **소자** 부분을 대체해 신설된 계열이다.
논문 §3.2 도 수집 대상으로 "H01L, H10 계열"을 명시한다 — 즉 **삼성 특허에서 그대로 터진다.**

현행 룰의 SIRP 매핑률: **447 / 1,000 (45%)**

## 2. 분석  🛑 (아직 수행하지 않음)

수행할 것:
- H10B / H10D / H10K / H10P / H10W 각각이 **무엇을 지시하는 분류인지** 공식 정의로 확인한다.
- 각 코드가 **공정을 지시하는가, 소자를 지시하는가**를 판별한다.
- C23C(786건!)·H01J·G11C 등 룰이 없거나 부분적인 다른 계열도 함께 점검한다.
- 확장 후 SIRP 매핑률을 재측정한다 (시험대).

### ⚠ 사전 경고 (이미 확인된 사실)

`G11C`(기억장치 회로) · `H10B`(메모리 소자) · `H10D`(반도체 소자)는 **소자 분류이지 공정 분류가
아니다.** 이들을 `realizesProcess` 로 보내면 그것은 룰 보강이 아니라 **날조**다(CLAUDE.md §1.2).

SIRP 에서 공정 링크가 없는 118건의 내역이 이를 뒷받침한다:
Device 만 77 · Skill/Material 만 17 · 도메인 링크 전무 24.
→ **소자 분류 코드는 `concernsDevice` 축으로 보내는 것이 옳다.** 개념 축은 이미 Process ∪ Device 로
확정되어 있다(SPEC-002).

즉 이 작업의 산출물은 "IPC → **공정**" 이 아니라 **"IPC → 개념(공정 또는 디바이스)"** 룰 테이블이
되어야 할 가능성이 높다. 그렇다면 파일명·컬럼·`ontology/mapping.py` 의 계약이 바뀐다 — 3단계에서
확정한다.
