## 0. 왜 이 문서가 필요한가

**실측(PLAN-069 §2).** T-Box 7파일 1,577 트리플에서 `subClassOf`·`domain`·`range` 를 넘는 OWL
공리는 **3개**이고 **선행기술에 관한 것은 0개**다. 그런데 T-Box 는 그 축을 **"중심축"** 이라
선언하고(`sdkb-patent.ttl:507`) 계산을 자기 밖으로 위임한다. §29①·§29② 는 `skos:notation`
문자열 둘로만 존재하므로, **어떤 추론기도 "29①은 동일성·단일 문헌, 29②는 조합 가능"을 구별할
수 없다.**

**그리고 T-Box 는 그 공리들의 이름을 이미 알고 있다.**

| 어휘 | 주석이 이미 말하는 것 | 위치 |
|---|---|---|
| `ont:featureSeq` | *"Preserves recitation order, which matters for **all-elements comparison**"* | `patent.ttl:563` |
| `ont:featureConcept` | *"**언어중립 대비의 축**"* | `patent.ttl:591` |
| `ont:dependsOnClaim` | *"완전 한정요소집합 = 부모 ∪ 종속 추가(**질의/추론으로 계산**). **진보성(§29②) 판단의 added-feature 는 여기에 있다**"* | `patent.ttl:549` |
| `ont:overlappingFeature` | *"겹친다고 도출된 한정요소(**라벨 아님** — 개념 오버랩의 **제안**)"* | `patent.ttl:620` |

**즉 명세는 주석으로 존재하고 공리로 존재하지 않는다.** 이 문서는 그 주석을 형식으로 옮긴다.

## 1. 공리 다섯

### X1 · 전요소 개시 (all-elements)

> 선행문헌 *d* 가 독립항 *c* 의 **모든 한정요소를 개시**하면, *d* 는 *c* 에 대한 §29① 대비
> 후보다.

- **형식화:** `features(c) = { fc | c hasFeature f, f featureConcept fc }` ·
  `disclosed(d) = { dc | d ⟨6종 개념 술어⟩ dc }` · 판정은 **`features(c) ⊆ disclosed(d)`**.
- **필요 어휘 — 전부 실재.** `hasClaim` · `isIndependent` · `hasFeature` · `featureConcept` ·
  6종 개념 술어. **새 술어 0.**
- **필요한 것은 공리가 아니라 전달이다.** 벤더 스냅샷의 `hasFeature` 인스턴스가 **0건**이므로
  (PLAN-069 §2.3) 이 판정은 현재 **정의는 되지만 계산되지 않는다.** → CR-A.
- **⚠ 사전 자인 — 현 구현으로는 X1 이 개념 겹침으로 퇴화한다.** `featureConcept` 가 문서 개념과
  **같은 6축**으로 정규화돼 있으므로(PLAN-069 §2.5), 포섭 판정은 개념 집합 포함관계가 되고
  이는 Jaccard 와 같은 정보를 쓴다. **A4 = +0.0070 · *p* = .271 이 그 귀결이다.**
  X1 이 새 정보를 갖게 하려면 **CR-C(한정요소 자기 어휘)가 선행**한다.
- **반증 조건:** 포섭이 성립하는 (c, d) 쌍의 분포가 심사관 인용과 **독립**이면 X1 은 깨진다.
  즉 포섭 성립률이 인용 쌍과 비인용 쌍에서 같으면 이 공리는 선행기술을 가르지 못한다.

### X2 · 등가 개시 (equivalents)

> 한정요소는 **등가 수단**으로 개시될 수 있다. 곧 X1 의 `⊆` 는 문자열 동일이 아니라
> **등가류 위에서** 판정되어야 한다.

- **형식화:** 개념 등가류 `[fc] = { x | fc skos:exactMatch x } ∪ { x | fc skos:broader* x }`
  를 취하고 X1 을 `[features(c)] ⊆ [disclosed(d)]` 로 완화한다.
- **필요 어휘 — 실재.** `skos:exactMatch`(SemicONTO 정렬에 이미 사용) · `skos:broader`.
  **새 술어 0.** 필요한 것은 **공리 선언**(`skos:broader` 의 전이 취급)과 **A-Box 보강**이다.
- **⚠ 현 자원 실측:** `skos:broader` **18 트리플 · 최대 깊이 1**(스냅샷 `0a7ff153`).
  깊이 1 의 계층에서 `broader*` 는 사실상 직계 부모 하나뿐이므로 **완화 폭이 거의 없다.**
  이것이 D-02 이며 `w_h = 0` 의 원인이다. → CR(계층 부여)이 선행한다.
- **반증 조건:** 등가류를 넣어도 X1 의 성립 쌍이 늘지 않으면 X2 는 깨진다.

### X3 · 종속항 합성 (composition)

> 종속항의 **완전 한정요소집합**은 부모의 집합과 자신의 추가 집합의 합이다.

- **형식화:** `dependsOnClaim` 을 **`owl:TransitiveProperty`** 로 선언하고
  `fullFeatures(c) = features(c) ∪ ⋃_{c dependsOnClaim* p} features(p)`.
- **필요 어휘 — 실재.** `dependsOnClaim`(450,542 트리플 · 상류). **새 술어 0 · 공리 1개 추가.**
- **T-Box 주석이 이미 이 계산을 지목한다**(`patent.ttl:549`). 이 문서는 그것을 형식으로 옮길 뿐이다.
- **반증 조건:** 합성 집합이 부모 집합과 **도달성에서 구별되지 않으면** X3 는 깨진다.
  (독립항만으로 이미 도달하는 경우 종속항 합성은 정보를 더하지 않는다.)

### X4 · 조합 인용 (§29② combination)

> §29① 은 **단일 문헌의 동일성**을 묻고, §29② 는 **추가 한정요소가 복수 문헌의 조합으로**
> 도달 가능한가를 묻는다. 둘은 다른 판정이다.

- **형식화:** 같은 `aboutClaim` 을 갖는 `PriorArtJudgment` 가 **둘 이상**이고 그 `onGround` 가
  `Rejection_Inventiveness` 이면 조합 인용이다. `addedFeatures(c) = fullFeatures(c) − features(parent(c))`
  가 X4 의 대비 단위다.
- **필요 어휘 — 실재.** `PriorArtJudgment` · `aboutClaim` · `overPriorArt` · `onGround` ·
  `Rejection_Novelty`(KIPO-29-1) · `Rejection_Inventiveness`(KIPO-29-2). **새 술어 0.**
- **공리로 넣을 것:** `Rejection_Novelty` 와 `Rejection_Inventiveness` 의 **판정 단위 구분** —
  전자는 단일 `overPriorArt`, 후자는 복수를 허용한다. `owl:Restriction` 의 카디널리티로 표현
  가능하나 **개체(individual)에는 걸 수 없으므로**, 판정 클래스를 나누거나 SHACL 형상으로
  강제한다. **어느 쪽인지는 상류 3단계 설계에서 정한다 — 여기서 정하지 않는다.**
- **⚠ 벤더 스냅샷의 `PriorArtJudgment` 인스턴스는 0건**이다. → CR-A.
- **반증 조건:** 조합 근거(복수 문헌)와 단일 근거가 **도달성에서 구별되지 않으면** X4 는 깨진다.

### X5 · 대비 적격 (technical field · problem) — **새 술어가 필요한 유일한 자리**

> 동일 기술분야이거나 동일 과제를 다루는 문헌만이 대비 적격이다.

- **기술분야 축은 실재한다.** `ClassificationSymbol` · `broaderClassification`
  (**이미 `owl:TransitiveProperty`**). 따라서 *"같은 IPC 상위 노드 아래"* 는 오늘 계산 가능하다.
- **과제 축은 실재하지 않는다.** `ont:Problem` 은 *"A technical problem posed by a
  materials/parts/equipment SME(소부장 실문제)"* 로 정의돼 있어(`core.ttl:765`) **발명이 해결하려는
  과제가 아니며**, Patent 을 주어로 하는 어떤 술어의 치역에도 없다.
- **🛑 정지 — 새 술어가 필요하므로 코드 전에 사람에게 묻는다(§1-6).** 후보는
  *"특허가 해결하려는 과제"* 를 잇는 술어와 그 치역 클래스이며, **이 문서는 필요를 적을 뿐
  이름을 정하지 않는다.**
- **분해해 진행할 수 있다.** X5 를 **X5a(기술분야 · 오늘 가능)** 와 **X5b(과제 · 승인 대기)**
  로 나누고, X5a 만으로 먼저 잰다.
- **반증 조건:** 적격 조건을 걸어도 후보가 좁아지지 않거나, 좁아지되 인용 쌍을 함께 잃으면
  X5 는 깨진다.

## 2. 구현 의존성 — 무엇이 무엇보다 먼저인가

```
CR-A (중심축 전달: hasFeature·PriorArtJudgment 인스턴스)
   ├─ X1 계산 가능
   ├─ X3 계산 가능  (+ dependsOnClaim 전이 선언)
   └─ X4 계산 가능
CR-C (한정요소 자기 어휘)  → X1 이 개념 겹침에서 분리된다   ← X1 의 정보량 조건
CR (계층 부여 · D-02)      → X2 의 완화 폭이 생긴다
X5a (기술분야)             → 오늘 가능 · 선행 조건 없음
X5b (과제 축)              → 🛑 새 술어 승인 필요
```

**곧 오늘 당장 계산 가능한 것은 X5a 하나이고, 나머지 넷은 전부 CR-A 뒤에 온다.**
**그리고 CR-A 없이 나온 어떤 수치도 X1–X4 의 값이 아니다** — 이것을 실행 전에 적는다(§1-2).

## 3. 측정 — `AxiomPathRecall` (사양 · 판정은 PLAN-070 에서)

인용 간선(`hasPriorArt` · `hasPriorArtExaminer` · `overPriorArt` · `NoveltyScore`)을
**마스킹한 상태**에서, 공리 경로로 정답 문헌에 도달하는 비율.

```
AxiomPathRecall = |{ (q,d) ∈ qrel : d 가 X* 경로로 q 에 연결된다 }| / |적격 qrel|
```

- **순위가 아니라 도달성**이므로 BM25·Dense 와 경쟁하지 않는다. 두 팔은 **통제 대조군**이다
  (PLAN-069 §5.2).
- 경로별로 분해해 보고한다 — X1 · X2 · X3 · X4 · X5a · 복수 근거.
- **공리 삽입 전/후를 같은 지표로** 잰다. 그 대조가 방법론의 실증이다.
- **낮게 나와도 버려지지 않는다** — 그 값은 자원 명세가 되어 C0(상류 환류)로 나간다.
  **미지지 판정과 달리 결손표의 행이 아니라 다음 CR 의 사양이 된다.** 이것이 이 재설계의 이득이다.

**누출 규율은 그대로다(§1-4).** `leakage_check` 가 통과하지 않으면 이 수치는 무효다.
특히 X4 는 `PriorArtJudgment` 를 **입력으로 쓰므로** 판정 노드 자체가 정답 파생임을 자인한다 —
**X4 는 인용을 복원할 수 있는 경로이므로 도달성 측정에서 `overPriorArt` 를 반드시 제거한다.**
제거 후 X4 가 쓰는 것은 `aboutClaim` · `onGround` · `addedFeatures` 뿐이다.

## 4. 보장하는 것 / 보장하지 않는 것

**보장하는 것**
- 위 술어는 X5b 를 제외하고 **전부 실재**한다(어휘 발명 0 · §1-6).
- 각 공리에 **반증 조건**이 있다(§0.6 조건 4).
- 각 공리의 **선행 조건**이 §2 에 명시돼 있다.

**보장하지 않는 것**
- **공리화가 성능을 개선한다는 것.** 이 문서는 사양이고 판정은 PLAN-070 에서 난다.
- **X1 이 새 정보를 준다는 것.** 현 구현에서는 개념 겹침으로 퇴화한다(§1 X1 ⚠).
- **법적 판정.** §29①·§29② 의 **대비 단위**를 형식화할 뿐 침해·무효의 최종 판단은 하지 않는다
  (§0.4 등급 3 · SPEC-005 §3.7 부분 폐기 주석 참조).
- **X5b 의 어휘.** 새 술어는 사람의 승인 전까지 존재하지 않는다.
