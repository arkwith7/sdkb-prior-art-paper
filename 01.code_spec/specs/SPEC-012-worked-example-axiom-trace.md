> **작성 순서를 밝힌다(§0.6 조건 5).** 공리 X1–X5 의 형식화는 [SPEC-011](SPEC-011-prior-art-axioms.md)
> 에 **먼저** 적혔고, 이 사례의 추적은 **그 뒤에** 수행했다. 그러나 이 사례로 X 를 고치지는
> 않았다 — 고쳤다면 그것은 사후 역산이다(§1-12).

## 1. 왜 이 사례인가 — 선정 근거

**선정 기준 넷을 모두 충족하는 사례를 데이터에서 골랐다.**

| 기준 | 이 사례의 값 |
|---|---|
| 거절근거가 **단일하고 명확**하다 | **§29②(진보성) 단독** · 신규성 거절 **0건** (`rejection_basis.csv`) |
| 인용문헌이 **복수**이고 **언어가 섞여** 있다 | 3건 — 한국어 2 · 영어 1 |
| 청구항 한정요소가 **양쪽 모두** 존재한다 | 질의 22행/10청구항 · 인용문헌 51·22·98행 |
| 분할이 **개봉 위험이 없다** | **train** |

**실물 기록.**

```
doc_id      kr_1020160014323
제목        플라즈마 식각 방법 및 이를 이용한 반도체 소자의 제조 방법
출원인      삼성전자 · 출원 2016-02-04 · 공개 2017-08-16 · 거절결정(일반)
거절근거    29-2- / Rejection_Inventiveness / 1차 의견제출통지서 2022-11-18
            has_novelty=0 · has_inventiveness=1 · n_claims_inventiveness=2
심사관 인용 other_1020090031624 (ko) · other_1020140110392 (ko) · us_US20100213162 (en)
```

**이 사례가 특별히 유용한 이유는 거절근거가 §29② 단독이라는 점이다.** §29① 은 **단일 문헌의
동일성**을 묻고 §29② 는 **복수 문헌의 조합**을 묻는다. 두 판정은 공리로 구별되어야 하며
(SPEC-011 X1 대 X4), 이 사례는 **심사관이 실제로 어느 쪽을 택했는지**를 정답으로 갖고 있다.

## 2. T-Box — 이 사례를 표현하는 어휘

**아래는 전부 `data/external/sdkb/*.ttl` 의 실물이다.** 이 문서는 어휘를 만들지 않는다(§1-6).

### 2.1 서지·거절 축 (`sdkb-patent.ttl`)

| 어휘 | 종류 | 이 사례에서의 역할 |
|---|---|---|
| `ont:Patent` · `ont:RejectedPatent` | Class | 질의 노드의 타입 |
| `ont:applicationNumber` · `ont:filingDate` · `ont:publicationDate` | DatatypeProperty | 시점 유효 후보 판정(`D_q`)의 입력 |
| `ont:assignedTo` → `ont:Organization` | ObjectProperty | 출원인(삼성전자) |
| `ont:hasIPC` → `ont:IPCSymbol` | ObjectProperty | 분류 축 |
| `ont:broaderClassification` | **`owl:TransitiveProperty`** | **T-Box 의 세 공리 중 하나** — IPC 계층 상승 |
| `ont:rejectedFor` → `ont:RejectionType` | ObjectProperty | `ont:Rejection_Inventiveness` |
| `ont:Rejection_Novelty` (`KIPO-29-1`) · `ont:Rejection_Inventiveness` (`KIPO-29-2`) | **SKOS 개체** | **판정의 이름일 뿐 공리가 아니다**(§4.1) |
| `ont:hasPriorArt` / `ont:hasPriorArtExaminer` | ObjectProperty | **정답 간선 — 검색 시 제거된다**(§1-4) |

### 2.2 기술 내용 축 — 개념 6종 (`sdkb-patent.ttl` · `sdkb-core.ttl`)

`ont:realizesProcess` · `ont:involvesProcess` · `ont:concernsDevice` · `ont:involvesMaterial` ·
`ont:concernsSkill` · `ont:exhibitsFailureMode`.

> **여섯 전부 무타입·무가중·무극성 이진 링크다.** 어떤 고장모드를 **유발**하는 특허와
> **해결**하는 특허가 그래프에서 구별되지 않는다. 이것이 §4 의 예측과 §5 의 실측을 가르는 조건이다.

### 2.3 청구항 축 — T-Box 가 "중심축"이라 부르는 자리 (`sdkb-patent.ttl:507-628`)

`ont:Claim` · `ont:ClaimFeature` · `ont:PriorArtJudgment` · `ont:hasClaim` · `ont:isIndependent` ·
`ont:dependsOnClaim` · `ont:hasFeature` · `ont:featureSeq` · `ont:featureConcept` ·
`ont:hasJudgment` · `ont:aboutClaim` · `ont:overPriorArt` · `ont:onGround` · `ont:overlappingFeature`.

**주석이 이미 공리의 이름을 말한다.**

| 어휘 | 주석 |
|---|---|
| `ont:featureSeq` | *"Preserves recitation order, which matters for **all-elements comparison**"* |
| `ont:featureConcept` | *"**언어중립 대비의 축**"* |
| `ont:dependsOnClaim` | *"완전 한정요소집합 = 부모 ∪ 종속 추가(**질의/추론으로 계산**). **진보성(§29②) 판단의 added-feature 는 여기에 있다**"* |

> **그러나 이 축은 벤더 스냅샷에 인스턴스가 0건이다**(`hasClaim`·`hasFeature`·`PriorArtJudgment`
> 전부 0). 상류 그래프에는 있고 하류에는 **투영 parquet 으로만** 도착했다(D-07 §1.13 ·
> `claim_features.parquet` 1,306,191행). **§5 의 한정요소 계산은 그래프가 아니라 이 parquet 에서
> 했다** — 곧 **그래프 경로로는 오늘 계산할 수 없다.**

## 4. 사전설계 — 공리가 예측하는 것

**SPEC-011 의 X1–X5 를 이 사례에 적용한다. 예측을 먼저 적고 §5 에서 대조한다.**

### 4.1 X1(전요소 개시 · §29①) — **예측: 모든 인용문헌에서 불성립**

대상 독립항 `rej_1020160014323_c1` 의 한정요소 개념(`claim_features.parquet` 실측):

```
c1 = { chamber_conditioning, etch, plasma_diagnostics, plasma_etch }        (|c1| = 4)
c8 = c1 ∪ { sio2 }                                                          (|c8| = 5)
```

| 인용문헌 | 개시 | 미개시 | X1 |
|---|---|---|---|
| `other_1020090031624` | 3/4 | `chamber_conditioning` | **불성립** |
| `other_1020140110392` | 2/4 | `etch` · `plasma_etch` | **불성립** |
| `us_US20100213162` | 2/4 | `chamber_conditioning` · `plasma_etch` | **불성립** |

> **예측:** 단일 문헌이 c1 을 전부 개시하지 못하므로 **§29①(신규성) 거절은 성립하지 않는다.**

### 4.2 X4(조합 인용 · §29②) — **예측: 성립**

```
D1 ∪ D2 ⊇ c1        미개시 = 없음
```

> **예측:** 두 문헌의 조합이 c1 을 완전히 덮으므로 **§29②(진보성) 거절이 성립한다.**

### 4.3 예측과 심사관 판정의 대조

| | 공리의 예측 | 심사관의 실제 판정 |
|---|---|---|
| §29① 신규성 | **불성립** | `has_novelty = 0` ✓ |
| §29② 진보성 | **성립** | `has_inventiveness = 1` · 2청구항 ✓ |

**두 예측이 모두 맞았다.** 이것이 이 문서의 핵심 관측이며, 동시에 그 한계도 분명하다 —
**질의 한 건**이고, 판정은 이미 공개된 값이므로 **예측력의 검정이 아니라 정합성의 확인**이다.
검정은 §8 의 프로토콜에서만 성립한다.

### 4.4 X3·X5 의 지위

- **X3(종속항 합성):** 이 사례의 대비 단위는 독립항 둘이므로 합성이 발동하지 않는다. **미발동**.
- **X5a(기술분야):** 질의 IPC `H01J_37-32`(플라즈마 처리 장치)가 D1·D2 와 공유된다.
  D3 는 `C23F1-00` 계열로 **공유하지 않는다** — 즉 X5a 를 적격 조건으로 걸면 **D3 를 잃는다.**
  이것이 X5 의 반증 조건이 말하는 위험이며, 이 사례에서 실제로 관측된다.
- **X5b(과제 축):** 어휘가 없다. 🛑 **사람의 승인 전까지 구현하지 않는다**(§1-6).

## 5. 현 자원에서의 실측 — 오늘 실제로 어디까지 가는가

**동결된 순위 코드(`systems.build_b5` · `build_b4`)로 산출했다. qrel 미열람 · 결정적 ·
자원 세대 `0a7ff153` · 코퍼스는 O′ 팔.**

### 5.1 순위 — 온톨로지 팔은 정답을 상위 100위에 넣지 못한다

| 팔 | `other_...031624` | `other_...110392` | `us_US20100213162` |
|---|---:|---:|---:|
| **B5 개념 단독** | 233위 | 137위 | 757위 |
| **B4 분류(IPC) 단독** | **14위** | 509위 | 미회수 |

> **관측 1.** 개념 단독 팔의 이 질의 Recall@100 은 **0** 이다.
> **관측 2.** **분류 단독이 개념 단독을 앞선다**(14위 대 233위). IPC 는 `broaderClassification`
> 이 **전이 공리를 가진 깊은 계층**인 반면, 개념 축은 `skos:broader` 18 트리플·최대 깊이 1 이다.
> **공리와 계층을 가진 축이 그렇지 않은 축을 이겼다** — 이 논문의 논지와 같은 방향이다.

### 5.2 원인 — 일반 개념의 동점 블록

| 질의 개념 | df (전체 41,223) |
|---|---:|
| `etch` | 9,228 (22.4%) |
| `dielectric` | 6,822 |
| `process_chamber` | 6,549 |
| `plasma_processing` | 4,452 |
| `plasma_etch` | 3,409 |
| `plasma_diagnostics` | 993 |
| `chamber_conditioning` | 447 |

- **개념 후보 집합 19,268건 = 코퍼스의 46.7%.** 곧 `ontology_rerank.py:9` 의 *"역색인으로 후보를
  좁힌다(전 코퍼스 완전탐색 회피)"* 는 **이 질의에서 성립하지 않는다** — 절반을 남긴다.
- 마스크 후 점수 > 0 인 문서 **7,487건**.
- 정답들의 비가중 Jaccard 점수와 **동점 블록 크기**:
  `0.4444`/36건 · `0.4000`/40건 · `0.2857`/**97건**.
- 최고점 `0.7500` 은 동점 3건뿐 — **상위는 변별되고 중위가 뭉갠다.**

> **원인은 자원의 결함도 점수식의 결함도 아니라 그 둘의 결합이다.** 특이도 가중이 없는
> Jaccard 위에서 df 22% 의 개념이 분자·분모에 함께 들어가면, 정답은 수십 건의 동점 덩어리
> 안에 묻힌다. **이것이 D-23 이 "미구분"이라 적은 자리이며, 이 사례는 그 기제를 보여준다.**

### 5.3 한정요소 축으로 바꾸면 후보 공간이 13배 좁아진다

`claim_features.parquet` 의 한정요소 개시도(질의 c1 의 4개 기준 · 시점 마스크 적용):

| 개시도 | 문서 수 | 코퍼스 비중 | 심사관 인용 포함 |
|---|---:|---:|---:|
| **≥ 4/4** (X1 완전) | **34** | 0.08% | 0 / 3 |
| **≥ 3/4** | 271 | 0.67% | 1 / 3 |
| **≥ 2/4** | **1,493** | **3.72%** | **3 / 3** |
| ≥ 1/4 | 6,012 | 14.96% | 3 / 3 |
| *(대조)* 개념 Jaccard 후보 | *19,268* | *46.7%* | *3 / 3 · 순위 137·233·757* |

> **관측 3.** 심사관 인용 **3건 전부**가 **1,493건(3.72%)** 안에 들어온다. 같은 3건을 담기 위해
> 문서 수준 개념 Jaccard 는 **19,268건(46.7%)** 을 쓰고도 상위 100위 밖에 둔다. **약 13배의
> 후보 공간 차이**다.
> **관측 4.** X1 완전 개시(34건)에는 정답이 **하나도 없다.** 이것은 X1 의 실패가 아니라
> **X1 이 옳게 작동한 결과**다 — 심사관도 §29① 을 적용하지 않았다(§4.3).

**곧 이 사례에서 유용한 것은 "완전 개시"가 아니라 "개시도"다.** X1 은 **이진 판정**으로
설계되었으나 검색에는 **등급**이 필요하다. 이 관측을 SPEC-011 에 되먹이지 않는다 —
되먹이면 사후 역산이다(§1-12). **§8 의 프로토콜에 검정 대상으로 올린다.**

### 5.4 이 절이 주장하지 않는 것

- **코퍼스 수준의 어떤 것도 주장하지 않는다.** n = 1 이다.
- **1,493건은 후보 집합이지 순위가 아니다.** 그 안의 순위 함수는 정의되지 않았으므로
  Recall@100 과 직접 비교할 수 없다. 비교 가능한 것은 **정답 셋을 담는 데 필요한 후보 크기**뿐이다.
- **분모가 다르다.** 개시도 사다리의 분모는 청구항 특징을 가진 **40,187건**이고, 개념 팔의
  분모는 **41,223건**이다.
- **`sio2`(c8 의 추가 한정요소)는 어떤 인용문헌도 개시하지 않는다.** 거절된 청구항이 c1·c8
  인지는 이 데이터로 확정되지 않으므로 **c8 에 대해서는 판단하지 않는다.**

## 6. 자원 세대 대조 — O 팔과 O′ 팔이 이 사례에서 갈리는 자리

**그래프가 아는 개념은 넷이고 코퍼스가 가진 개념은 일곱이다.** 차이 셋은 표면형 사전이 본문에
적용되어 생겼다(`concept_link.py` · **O′ 팔**).

| | 개념 | 중앙 df |
|---|---|---:|
| **그래프 유래 4** (O 팔) | chamber_conditioning 447 · plasma_diagnostics 993 · plasma_etch 3,409 · etch 9,228 | **2,201** |
| **사전이 추가한 3** (O′ 팔) | plasma_processing 4,452 · process_chamber 6,549 · dielectric 6,822 | **6,549** |

> **관측 5.** 자원 보강이 더한 셋은 **그래프가 이미 갖고 있던 넷보다 3배 일반적**이다
> (중앙 df 6,549 대 2,201 · 각각 코퍼스의 10.8%·15.9%·16.5%). **비가중 Jaccard 에서 일반 개념의
> 추가는 분모를 키우고 동점 블록을 넓힌다.** D-23 이 코퍼스 전체에서 관측한 것과 같은 방향이
> 이 사례에서도 보인다.
>
> **⚠ 팔을 섞지 않는다.** §5 의 모든 순위는 **O′ 팔**의 값이며 **원고 §6 의 O 팔 수치와 같은
> 표에 싣지 않는다**(메모리 `disk-resource-is-oprime-manuscript-is-o-arm` · PLAN-069 DoD 13).

## 8. 구축 후 검증 프로토콜 — **PLAN-070 에서 동결한다**

> **이 절은 사양이며 아직 실행하지 않았다.** 아래를 **결과를 보기 전에** 동결하지 않으면

### 8.1 선행 조건 (충족 전에는 실행하지 않는다)

| | 조건 | 현 상태 |
|---|---|---|

### 8.2 동결할 것

- **판정식** — `AxiomPathRecall` 의 정의와 경로 분해(X1·X2·X3·X4·X5a·복수 근거)
- **개시도 등급의 임계** — §5.3 이 시사한 `≥k/|c|` 의 k. **이 사례를 보고 정하지 않는다.**
  **개발 분할에서만** 선택하고 test 로 재선택하지 않는다
- **대조군의 불변 조건** — O→O′ 에서 BM25·Dense run 이 **바이트 동일**일 것(현 실측 PASS)
- **분모** — 청구항 특징 보유 문서 수와 코퍼스 문서 수를 **구분해** 보고할 것
- **양방향 해석** — 개선되면 무엇을 주장하고, 개선되지 않으면 무엇을 C0 로 보낼지

### 8.3 실행 순서

```
① CR-A·CR-C 착지 → make vendor → 코퍼스 재조립
② make leakage (위반 0 확인 — 아니면 중단)
③ 공리 삽입 전 기준선: AxiomPathRecall(O)  · dev 분할
④ 공리 삽입 후:        AxiomPathRecall(O″) · dev 분할
⑤ 경로별 분해 보고 · 대조군 불변 확인
⑥ test 는 사전등록이 허용한 1회만
```

### 8.4 판정이 어느 쪽이든 쓸 자리가 있다

- **도달성이 오르면** — 판단 공리의 온톨로지 구현이 태스크에 도달함을 보인 것이다(C1 작동 층).
- **오르지 않으면** — 그 값이 **자원 명세**가 되어 C0 로 나간다. 어느 경로가 비었는지가
  다음 CR 의 사양이다. **미지지 판정과 달리 결손표의 행이 아니라 요구사항이 된다.**

## 10. 보장하는 것 / 보장하지 않는 것

**보장하는 것**
- 모든 수치는 **실행된 코드의 출력**이다(§1-1). 산출 경로는 `systems.build_b5`·`build_b4` ·

- 공리의 **작성 시점이 사례 추적보다 앞선다**(SPEC-011 → 이 문서 · §0.6 조건 5).

- **원고 §6 과의 비교 가능성.** 이 문서는 **O′ 팔**이고 원고 §6 은 **O 팔**이다(§6 ⚠).

- **X5b 의 어휘.** 새 술어는 사람의 승인 전까지 존재하지 않는다.
