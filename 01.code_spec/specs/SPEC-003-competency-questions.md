## CQ 8개와 그 근거

CQ 는 **기술예측 태스크가 온톨로지에 요구하는 질문**에서 도출한다(Grüninger & Fox, 1995).
§2.4 가 규정한 3가지 태스크 요구 — 전 공정 균형 커버리지 · 시간 속성 · 개념 단위 집계 — 가 출처다.

| CQ | 질문 | 어느 요구에서 나왔는가 | G₀ (before) |
|---|---|---|---:|
| CQ01 | 공정 단계별 특허 수 | 커버리지 | **16** |
| CQ02 | 특정 시점 이후 출원 특허 | 시간 속성 | 362 |
| CQ03 | 특허가 없는 공정 단계 | 커버리지 공백 (H1 핵심) | **4** |
| CQ04 | 개념(공정 ∪ 디바이스)별 연도별 출원수 | 개념 단위 집계 — H2 시계열의 최소 단위 | 286 |
| CQ05 | IPC 코드 단위 연도별 집계 | **H2 의 대조군** — 없으면 H2 를 검정할 수 없다 | 1,959 |
| CQ06 | 최근 5년 출원 전무한 개념 | 커버리지 공백 (개념 51개 기준) | **29** |
| CQ07 | 디바이스 특허가 실현하는 공정 | 개념 축 교차 (제품↔기술) | 46 |
| CQ08 | 출원인별 공정 포트폴리오 | "전 공정 포트폴리오 보유"(§1.1)의 전제 | 317 |

*근거: `make cq` → `paper/figures/cq_report_graph_v0.md`*

## 보장하는 것

**G₀ 의 CQ 서명이 고정된다.** 8개가 모두 응답하고, CQ01=16 · CQ03=4 · CQ06=29 이다.
이 서명이 깨지면 특허가 유실됐거나 특허↔공정 링크가 끊어진 것이다 — 둘 다 H1 을 조용히 무효화한다.
→ `test_baseline_cq_signature`

**`mini_graph` 가 8개 CQ 를 전부 exercise 한다.** 합성 특허 3건에 Device·Organization·IPCSymbol
축을 넣어, 어떤 CQ 도 vacuous 하게 통과하지 않는다. 여기서는 **100% 를 요구하는 진짜 게이트**다.

**그래프별 리포트가 분리된다.** `cq_report_<graph>.md` — G₀ 와 G₁ 의 열이 서로 덮어쓰지 않아야
§4.2 의 보강 전후 비교표를 만들 수 있다.

---

## 보장하지 않는 것

- **응답의 옳음.** `cq_runner` 는 결과 **행 수**만 센다. 응답 내용이 옳은지는 검사하지 않는다.
- **CQ 집합의 완전성.** 8개가 기술예측 태스크를 남김없이 덮는다는 보장은 없다.

---

## ⚠ §4.2 의 지표를 바꿔야 한다 (핵심 발견)

**G₀ 가 8개 CQ 에 전부 응답한다(100%).** G₀ 에 이미 특허 1,000건·출원인 351개가 있기 때문이다.

따라서 논문 §3.4.2 가 쓰려던 지표 —
> "G₀ 에서 응답 불가였던 CQ 중 G₁ 에서 응답 가능해진 비율"

은 **분모가 0이라 정의되지 않는다.** 이진 지표(응답 가능/불가)는 판별력이 없다.

**대신 응답 완전성(결과 행 수)의 G₀ → G₁ 변화로 잰다.** 핵심 수치:
- **CQ06**: 최근 5년 출원 전무 개념 **29 / 51** → 삼성 보강 후 줄어드는가
- **CQ01 / CQ03**: 커버된 공정 **16** → 늘어나는가 / 공백 **4** → 줄어드는가
- **CQ04**: 시계열을 가진 개념 수 → 늘어나는가

원고 §3.4.2 를 이 형태로 고쳐야 한다.

---

## 왜 이렇게 했는가

**CQ 를 G₀ 가 실패하도록 역설계하지 않았다.** 그렇게 하면 §3.4.2 의 지표를 조작하는 것이다
(CLAUDE.md §1.2). CQ 는 태스크 요구에서 도출했고, G₀ 가 전부 답한다는 것은 **발견이지 설계 실패가
아니다.**

**출원인 결측을 "G₁ 이 고칠 결함"으로 남겨두지 않았다.** 출원인이 없으면 CQ08 이 G₀ 에서
실패하므로 이진 지표의 분모를 1 로 만들 수 있었다. 그러나 **결과를 얻기 위해 데이터 결함을
보존하는 것은 조작이다.** 발견 즉시 고쳤고(SDKB `c49dea0`), 그 결과 CQ08 이 G₀ 에서도 응답하게 된
것을 그대로 보고한다.

**신호(Signal) 인스턴스를 만들지 않았다.** foresight TBox 의 `ont:Signal` 은 `signalsFactor` 로
STEEPVE 요인에만 연결되고 기술 개념(Process/Device)에는 붙지 않는다. H2 의 신흥 신호는 그래프
인스턴스가 아니라 `analysis/timeseries.py` 가 계산하는 값이므로, CQ 는 **그 계산을 가능하게 하는
질의**(CQ04·CQ05)로 충분하다.
