# PLAN-061 — 추가 델타 T-gate 적용의 자격 심사 (PLAN-060 단계 C · §2.1 경로)

**대상.** 자원 스냅샷(`data/external/sdkb/`)과 상류 `~/Dev/sdkb` · T-gate 판정 산출 배선
(`src/sdkb_paper/validate/t_gate.py`). **원고는 건드리지 않는다** — 본문·표·그림·`verdicts.yaml`
변경 0.

## 0. 결론 먼저 — 자격 있는 델타가 0건이므로 **게이트를 돌리지 않는다**

PLAN-060 단계 C 는 *"자격 있는 실제 델타(유형 ① T-Box · ② 개념층) 1–2건에 T-gate 를 추가
적용한다"* 였고, 그 앞에 **자격 심사**를 두었다. 심사 결과는 다음과 같다.

**스냅샷과 상류 워킹트리는 벤더 대상 22파일 전량이 바이트 단위로 동일하다.** 즉 §2.1 의 발동
조건인 *"파일 sha256 변경"* 자체가 성립하지 않는다. 델타가 없으므로 T1·T2·T3 를 돌리면 그
판정은 측정된 결과가 아니라 **구성상 0** 이 되고(D-43 · `resource_visibility = invisible`),
그것을 표에 싣는 것은 근거가 아니라 분량이다. **표를 채우려고 세대를 만들지 않는다**
(CLAUDE.md §7 말미).

**따라서 이 문서는 사전등록이 아니라 심사 기록에서 멈춘다.** 동결해야 할 값(§4)은 미리 적어
두되, 스냅샷 서명 자리가 비어 있으므로 **사전등록으로 발효하지 않는다.**

**선행 조치는 완료했다**(§5) — 판정 산출 파일이 고정 경로 하나를 공유하던 배선을 고쳤다.

## 1. 목적과 비목적

**목적.** ⓐ 자격 있는 델타의 유무를 실측으로 판정하고 근거를 남긴다 ⓑ 같은 손실이 반복되지
않도록 판정 산출의 덮어쓰기를 구조로 막는다 ⓒ 델타가 생겼을 때 즉시 발효할 수 있도록 동결
대상을 명세한다.

**비목적.**
- **델타를 만들지 않는다.** 상류 CR 을 앞당겨 반영하거나 세대를 조립해 자격을 만들지 않는다.
- **새 실험 0 · 수치 재산출 0 · 봉인 개봉 0 · 판정 변경 0.**
- 벤더 대상 목록을 넓히지 않는다 — 그것은 자원 교체가 아니라 **코드 변경**이므로 §2.1 이
  아니라 §2 전체를 탄다(§3 ⑤ 참조).

델타 유형은 CLAUDE.md §0 의 표를 그대로 쓴다(① T-Box · ② 개념층 · ③ A-Box 코퍼스).

일 때만 유효한데, ③·④ 는 자원이 아니라 **읽는 쪽(소비 코드·벤더 목록)**이 바뀐다. 그 경로로
태우면 *"재실험이라는 이름으로 로직 변경을 무검증 통과"* 시키는 것이 된다(§2.1 안전장치).

## 4. 델타가 도래하면 동결할 것 (아직 발효하지 않는다)

스냅샷 서명 자리가 비어 있어 **사전등록으로 발효하지 않는다.** 채워야 할 칸은 다음과 같다.

| 항목 | 값 |
|---|---|
| 스냅샷 파일별 sha256 · 상류 커밋 | **[델타 도래 시 기입]** |
| ε · δ | 0.02 · 0.05 (동결 · 이동 없음) |
| 주지표 | family-level Recall@100 |
| 시점/패밀리 분할 경계 · low-overlap 정의 | 기존 동결값 |
| 봉인 qrel 해시 | examiner `10ab67f21cc1…` · test sealed `984f8ef3dfd3…` |
| 판정식 | `Accept = (L0–L3) ∧ (LB₉₅(ΔR₁₀₀) > −ε) ∧ (max_s drop_s < δ) ∧ (T3 비회귀)` |
| 확증/탐색 구분 | T1·T2·T3 는 **승인 판정** · 그 밖의 수치는 대장 회신용 **참고** |
| 자원 가시성 | `resource_visibility.note` 가 `invisible` 이면 결과를 "통과"로 적지 않는다(§2.1 2′) |

**개봉 규율은 그대로다.** 이미 개봉한 test 분할 위에서는 승인 규칙의 적용과 탐색적 재측정까지이며,
**우월성의 재확증은 신규 확증분할로만** 한다.

## 5. 선행 조치 — 판정 산출의 덮어쓰기를 구조로 막았다 (완료)

**무엇이 사라졌는가.** EP3(통제된 자원 교체)의 T-gate 판정 JSON 이 2026-08-15 의 시스템 비교
실행에 덮였다. 두 실행이 **같은 고정 경로**(`data/processed/tgate_report.json`)에 썼고
`data/processed` 는 gitignore 라(`.gitignore:9`) 복구 경로가 없다. −0.0293·+0.0401 은 이제 동결
사전등록(PLAN-035 §B)과 `paper/figures/data/concept_values.json` 에만 있다.

**무엇을 고쳤는가 — 판정 로직이 아니라 경로다.**

| | 변경 | 근거 |
|---|---|---|
| 1 | 기본 산출 경로에 **실행 정체성**을 넣는다 — `tgate_report__{mode}__{runset/system}__{split}.json` (`t_gate.report_path`) | 이름이 다르면 두 실행은 서로를 지우지 못한다 |
| 2 | 같은 이름이 이미 있으면 **게이트를 돌리기 전에** 멈춘다(`t_gate.guard_overwrite` · `--force` 로만 덮는다) | 다 돌린 뒤 거부하면 계산을 버리게 되고, 그러면 다음 사람이 `--force` 를 습관으로 붙인다 |
| 3 | `config.TGATE_REPORT` 는 **구 고정 경로**로 격하 — 쓰기 대상이 아니다 | 위험한 이름을 남겨 두면 다시 쓰인다 |

**판정은 한 글자도 바뀌지 않는다.** `run_tgate()` · `accept()` · T1·T2·T3 · 종료코드
(0 승인 · 1 불통과 · 2 미검정) 전부 불변이며, 바뀐 것은 결과를 **어디에 쓰는가**뿐이다.
회귀 검사는 `tests/test_tgate.py` 신설 3건(실행 분리 · 라벨 정규화 · 침묵 덮어쓰기 거부).
