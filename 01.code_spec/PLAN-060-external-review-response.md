## 5. 요건 5 · 역방향 점검 — 규약을 먼저 고친다

충돌 **둘**. 원고보다 `CLAUDE.md` 를 먼저 개정한다.

### 5.1 §0.5 규칙 3 — "기여는 둘로 유지"

현행 파생본은 **서론이 이미 셋**(산출물·방법·설계지식)이고 **결론만 둘**이다. 즉 규약과 원고가
이미 어긋나 있다. 규칙 3 의 원래 취지는 *C2′ 를 기여로 올리지 말라* 였으므로 그 취지를 유지한 채
**셋으로 개정**한다 — ① 산출물(SDKB) ② 방법(T-gate) ③ 설계지식(DP) · **C2′ 는 여전히 기여가
아니다.**

### 5.2 §0.6 — DP 승격 기준의 2단계 이분법

현행 자는 **사전 설계 여부와 실증 지지 여부를 구분하지 못한다** — DP2(설계 선행 + 실제 거부로
지지)와 DP1(확인 선행)이 같은 "확립"으로 묶인다. 검토가 지적한 과잉 일반화의 원인이 여기다.
**다섯 조건은 한 글자도 바꾸지 않고 등급만 셋으로 나눈다.**

| 등급 | 조건 |
|---|---|
| **사전 설계 · 실증 지지** | 다섯 충족 + 설계 시점이 확인 시점보다 앞선다 |
| **경험적 지지** | 다섯 충족 + 확인이 선행 (§1-12 대로 표기) |
| **제안** | 하나라도 미달 |
