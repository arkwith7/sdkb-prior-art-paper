# 한국어 학술 논문 문체 규격 v2 (2026-08-16 · 사용자 승인)

> **v1 → v2 개정 이유 (2026-08-16 · 외부 검토).** v1 은 어체 전환에 성공했으나 **산문만**
> 규정했다. 그 결과 위반이 세 곳으로 몰렸다 — ① **표 셀**(규격에 표 규정이 없어 통째로
> 사각지대였다) ② **소제목**(헤딩 규칙이 없어 서사체 제목이 남았다) ③ **용어 이중 번역**
> (`task` 가 "태스크"와 "과제"로 갈렸다). 여기에 축약형(`됐다`·`했다`)과 표 번호의 중복·결번이
> 더해졌다. v2 가 신설하는 다섯은 **H1 · T6 · T7 · V5 · V6** 이며, v1 의 규칙은 한 항목도
> 삭제·완화하지 않는다.
>
> **개정의 방법도 함께 정한다.** 잔존 위반이 패턴으로 좁혀졌으므로 **재작성 반복이 아니라
> 정규식 린트로** 잡는다. LLM 재변환은 매번 회귀 위험(내용 손상·번호 중복)을 동반하지만
> 린트는 결정적이다. 실제로 v1 적용 중 **문장 분할이 주술 호응을 깨뜨린 사례와 표 번호가
> 중복된 사례**가 각각 발생했고, V6 과 아래 "회귀 점검"이 그 재발을 막는다.

> **적용 범위는 "내용 보존 + 어체 변환"이다.** 이 규격은 **문장을 어떻게 쓰는가**만 정한다.
> 수치·판정·기여 목록·장 구성·논리 전개는 이 규격으로 바꾸지 않는다. 규격을 적용한 결과로
> 판정 문구가 흔들리면 그것은 문체 개선이 아니라 CLAUDE.md §1-2 위반이며, `make verdicts`가
> 차단한다. 규격 적용 커밋은 **`make verdicts` · `make sig-check` · `make submission-check`가
> 전부 통과한 상태에서만** 성립한다.
>
> **강제 대상 (기계 검사 `make style-check`)** — 투고 파생본 계열:
> `paper/manuscript/stage3_source.md`(산문 소스) · `paper/submission/**/*.md`(조립 산출물).
> **대상 아님** — 작업 정본 `paper/archive/논문_v0_9_SDKB_통합초안.md`와 `paper/supplementary/`.
> 이 둘은 **감사 기록**이므로 과거 문장을 소급해 다듬지 않는다(`submission_check.py`가 정본을
> 대상에서 제외하는 것과 같은 이유). 다만 **정본에 새로 쓰는 문단은 이 규격을 따른다.**

## 구조 규칙 (가독성의 원천)

**S1 · 문단 구조.** 각 문단은 [주제문 → 근거·전개 → 소결]로 구성한다. 문단의 첫 문장만 이어
읽어도 절 전체의 논리가 따라가지도록 한다.

**S2 · 한 문장 = 한 명제.** 접속 절은 최대 2개(원인–결과, 대조 등)까지만 허용한다.

**S3 · 문장 길이 상한 90자**(공백 포함). 초과 시 분할한다. — *기계 검사 대상*
길이는 **한국어 산문의 부담**만 센다. 서지 인용 `(Lupu & Hanbury, 2013)`과 원어 병기
`(competency question, CQ)`처럼 괄호 안이 영문·숫자 위주인 삽입구는 길이에서 제외한다.
V1이 요구하는 원어 병기가 S3 위반을 만들면 두 규칙이 서로를 무효화하기 때문이다.

**S4 · 전개 순서는 일반 → 구체.** 넓은 배경 → 대상 문제 → 기존 한계 → 연구 공백 → 본 연구의
접근 순으로 전개한다.

## 어체 규칙 (학술 레지스터)

**T1 · 서술어는 격식 문어체.** `~하였다 / ~한다 / ~할 수 있다 / ~로 나타났다 / ~가 요구된다 /
~를 제안한다`를 쓴다. 단언형 단문의 연쇄와 도치문은 쓰지 않는다.

**T2 · 은유·구어 표현 금지.** 학술 동사로 치환한다. — *기계 검사 대상*

| 금지 | 치환 |
|---|---|
| 망가뜨린다 · 깨뜨린다 | 훼손한다 · 저해한다 |
| 건진다 · 건져 올린다 | 회수한다 |
| 잰다 · 재 본다 | 측정한다 · 평가한다 |
| 아프다 · 뼈아프다 | 심각하다 · 중대하다 |
| 뒷걸음친다 | 저하된다 |
| 갈아 끼운다 | 교체한다 |
| 좋아진다 · 나빠진다 | 향상된다 · 저하된다 |
| 새어 나간다 | 유출된다 · 전파된다 |
| 꽂아 넣는다 | 적용한다 · 결합한다 |
| 넘겨 짚는다 | 과잉 일반화한다 |
| 붙잡아 둔다 | 제약한다 · 근거로 고정한다 |
| 쓸모 | 유용성 |
| 지어낸다 | (사실과 다른 내용을) 생성한다 |
| 헐거워진다 | 완화된다 |
| 천장 (performance ceiling) | 상한 · 재순위화 상한(reranking ceiling) |
| 해상도 | 뜻마다 가른다 — 개념 밀도 · 관찰 수준 · 매칭 단위 · 검사 세밀도 |
| 사다리 (도달성 사다리) | 관찰 수준별 도달성 |
| 손대지 않았다 | 변경하지 않았다 |
| 정박 평가 | 인용을 기준으로 한 평가 · 인용에 근거한 평가 |
| 판독 | 평가 · 분석 · 결과 확인 |
| 계측기 | 평가 절차 · 측정 도구 · 평가 체계 |
| 충전 정도 | 인스턴스 데이터가 채워진 정도 |
| 검출 표면 | 검출 가능한 제약 · 검사 범위 |
| 결과가 갈렸다 | 결과가 서로 달랐다 · 결과가 일치하지 않았다 |

**T3 · 문단 간 연결은 표준 학술 연결어만.** `그러나 / 따라서 / 이러한 / 특히 / 반면 / 더욱이 /
요컨대`를 쓴다. `그래서 · 그런데 · 하지만`은 쓰지 않는다. — *기계 검사 대상*

**T4 · 주어를 생략하지 않는다.** 연구 주체는 **"본 연구는 / 본 논문은"** 으로 통일한다.

**T5 · 볼드는 정의된 핵심 용어의 최초 등장에만.** 주장 문장에는 볼드를 쓰지 않는다. 주장은
논거로 강조한다. — *기계 검사 대상(볼드 안에 종결어미가 있으면 위반)*

**T6 · 어휘 규칙은 산문 밖에도 적용한다 (v2 신설).** T2 의 은유·구어 금지, T7 의 축약형 금지,
V5 의 용어 단일화는 **표 셀 · 그림 캡션 · 소제목**에서도 그대로 성립한다. — *기계 검사 대상*
다만 **표 셀의 개조식(명사형 종결)은 허용한다** — 표는 문장이 아니라 항목이므로 S3(길이) ·
T5(볼드) · T3(문두 접속어)는 적용하지 않는다. 금지되는 것은 종결형이 아니라 **구어 동사**이다.

| 표에서 흔한 위반 | 치환 |
|---|---|
| 말로 풀면 · 어긋나면 무엇이 일어나는가 | 조건의 내용 · 미충족 시의 처리 |
| 일부러 심은 결함을 잡아내는가 | 의도적으로 주입한 결함을 검출하는가 |
| 멀쩡한 변경 | 정상 변경 |
| 자원만 갈아 끼웠을 때 | 자원만 교체하였을 때 |
| 고르는 잣대 | 비교·선택의 기준 |
| 통과율이 뒷걸음치면 거부 | 통과율이 저하되면 거부 |

**T7 · 축약형 금지 (v2 신설).** `됐다 → 되었다` · `했다 → 하였다` · `봤다 → 보았다` ·
`줬다 → 주었다`. 활용형에도 동일하게 적용한다(`수행했으나 → 수행하였으나` · `고정했을 때 →
고정하였을 때`). — *기계 검사 대상*
**예외는 인용이다.** 사전등록 문서와 §0.8 판정 문구 사전의 **원문**에 있는 축약형은 고치지
않는다. 원문 충실성이 어체보다 앞서기 때문이다. 행 단위로는 `<!-- style-ok: 사유 -->` 로,
반복 등장하는 판정 문구는 검사기의 `VERDICT_LITERALS` 로 면제한다.

## 용어 규칙 (이해 용이성의 원천 — 풀어쓰기는 여기서 한다)

**V1 · 최초 등장 1회만 정의.** `한글 풀이(영문 원어, 약어)` 형식으로 적는다. 예: 교차 태스크
회귀(cross-task regression), 즉 한 태스크를 위한 변경이 다른 태스크의 질의 경로를 훼손하는 현상.
— *기계 검사 대상(부분 · v3 신설 · PLAN-066)*: `paper/glossary-terms.yaml` 에 등재된 용어에 한해
**정의가 첫 사용보다 앞서는가(G1)** · **약어가 정의보다 먼저 단독 등장하지 않는가(G2)** 를
`make glossary-check` 가 본다. 기점은 §1 이다 — 초록·약어표는 자기완결 단위이며 **약어표는 색인이지
정의가 아니다.** 정의문의 품질·예시 유무는 사람이 지킨다.

**V1-a · 용어의 부류 셋과 처리 규칙 (v3 신설).** ㈎ 이 논문이 만든 개념어(실제 델타·평가 에피소드·
깊은 회수 등)는 정의 없이 쓰지 않는다 — 정의는 "일상어 풀이 → 이 논문에서의 뜻 → 왜 이 구분이
필요한가" 세 문장 이내. ㈏ 정보검색·통계의 표준 용어(qrel·MRR·McNemar·Holm 등)는 정의가 아니라
**"왜 이 지표인가"** 를 적고, 표준 정의는 각주·S5 로 보낸다. ㈐ 코드·자원 식별자(`em`·`tf`·F12·B5·
A8 등)는 산문에서 쓰지 않고 이름으로 풀어 쓴다 — 식별자는 표·캡션·수식에만(G4 · 경고).
지표 일곱을 한 문장에 나열하지 않는다 — "묻는 질문 → 지표" 대응 표 하나로 바꾼다.

**V2 · 정의 이후에는 동일 용어만.** 동의어 교체를 금지한다(일/태스크 혼용 금지 → 태스크로 통일).
— *기계 검사 대상(부분 · v3)*: `glossary-terms.yaml` 의 `synonyms_forbidden`·`forbid_patterns` 를
`make glossary-check` 가 본다(G5). 실측된 다의어 한 건 — `CI` 가 신뢰구간(95% CI)과 지속 통합 두
뜻으로 쓰였다. 지속 통합의 뜻으로는 약어를 쓰지 않고 "지속 통합 파이프라인"으로 풀어 쓴다.

**역방향도 같은 규칙이다 — 한 낱말을 여러 뜻으로 쓰지 않는다.** 은유 명사에서 특히 잘 나며,
그 낱말이 표·제목에 먼저 등장하면 독자는 정의를 만나기 전에 뜻을 추측하게 된다. 실제로
`해상도`가 이 원고에서 **네 뜻**으로 쓰였다 — 자원의 개념 밀도 · 도달성의 관찰 수준 ·
매칭 함수의 단위 · CQ 검사의 세밀도. 처방은 낱말을 고르는 것이 아니라 **뜻마다 다른 용어를
부여하는 것**이다.

**V3 · 지표·게이트 명칭은 번역·의역하지 않는다.** `L0–L3` · `T1–T4` · `Recall@100` · `nDCG@20` ·
`EP1–EP4` · `A1–A8` · `B0–B5` · `P0–P2` · `qrel` · `SHACL` · `T-Box`/`A-Box`가 여기 해당한다.

**V4 · 이해를 돕는 장치는 문장 단순화가 아니라** (a) 정의문, (b) 구체 예시 1개, (c) 절 첫머리의
로드맵 문장으로 제공한다.

**V5 · `task` 의 번역은 "태스크" 로 단일화한다 (v2 신설).** — *기계 검사 대상*
같은 원어를 두 낱말로 옮기면 독자는 서로 다른 대상으로 읽는다. 실제로 v1 판에서 `교차 태스크
회귀`와 `과제 의미 회귀`가 같은 `task-Xxx regression` 계열이면서 다른 낱말로 갈렸다.
**예외는 아래 넷뿐이며, 이는 번역 관행이 확립되었거나 애초에 `task` 가 아닌 낱말이다.**

| 예외 | 사유 |
|---|---|
| 과제 기반 평가(task-based evaluation) | 확립된 번역 관행 — 선행연구를 지칭하는 고유 용어 |
| 후속 과제 · 다음 과제 | future work — `task` 가 아니다 |
| 연구 과제 | research project — `task` 가 아니다 |
| 별개의 과제 | 일반명사 용법 |

**V6 · 표·그림 번호는 등장 순서로 1부터 연번 (v2 신설).** 중복·결번을 금지한다.
— *기계 검사 대상(캡션 행의 번호가 등장 순서와 일치해야 한다)*
번호는 **캡션 행**(`**표 N. …**`)이 정본이고 본문 참조는 그것을 따른다. 장 구성이 접히거나
절이 이동하면 번호가 어긋나므로, 재조립 후에는 반드시 `make style-check` 로 확인한다.

**V7 · `E` 라벨은 본문에서 평가환경 하나만 가리킨다 (2026-08-29 신설).** 적격심사 항을
`E1`–`E7` 로 부르지 않으며, 서술형으로 "적격심사 일곱 항" 이라 쓴다.
— *기계 검사 대상(`E2`–`E9` 등장 · 같은 행의 `E` 라벨 + "적격심사" 동시 등장)*
본문 약어표는 `E1` 을 **평가환경**으로 등재하는데 사전등록 문서는 같은 `E1`–`E7` 을
**적격심사 일곱 항**으로 쓴다. 두 층이 한 문단에서 만나면 같은 기호가 두 가지를 가리키며,
그런 사고는 `S`-시리즈와 교훈 `L` 에서 이미 두 번 일어났다. 사전등록 문서의 라벨은 추적성을
위해 그대로 두고, 막는 것은 **본문이 그 라벨을 끌어다 쓰는 것**이다(CLAUDE.md §0.9 규칙 5).
면제가 필요한 행에는 `<!-- style-ok -->` 를 단다.

## 관통 예시 규칙 (PLAN-087 신설)

**X1 · 예시는 1부터 연번이며 증거 지위를 머리말에 표시한다.** 허용 표식은 `합성 설명` ·
`합성 실행` · `탐색 사례` · `사전등록 집계`이다. 같은 사례를 여러 절에서 다시 가리킬 때에는
새 번호를 부여하지 않고 “예시 1”처럼 기존 번호를 참조한다.

**X2 · 합성 예시는 실제 판정을 대신하지 않는다.** 합성 실행은 CQ 행 수와 동결 판정식의
작동만 설명한다. 합성 예시 머리말에는 승인·거부·채택·기각·확증·부분 지지와 같은 실제 판정
낱말을 쓰지 않는다. 실제 판정은 사전등록 집계 표식을 둔 본문·표·그림에서만 보고한다.

## 소제목 규칙 (v2 신설)

**H1 · 소제목은 명사구형으로 작성한다.** 서술형·의문형·서사형 제목을 쓰지 않는다.
— *기계 검사 대상(제목이 종결어미로 끝나면 위반)*
부제(`—` 뒤)에도 동일하게 적용한다. 제목은 절의 내용을 **지시**하는 이름이지 절의 결론을
**진술**하는 문장이 아니다. 결론은 본문의 첫 문장이 진술한다(S1).

| 서술형 (금지) | 명사구형 |
|---|---|
| 음성 대조군이 무너진 자리 | 음성 대조군의 기각과 교차 태스크 의존성 |
| 층마다 지표가 어긋난다 | 층간 지표 불일치 |
| 만들었고, 결과는 부록에 둔다 | 계측기의 실패와 부록 이관 |
| 대리 지표는 언제 대신할 수 없게 되는가 | 자원 지표가 태스크 성능을 대표하기 위한 조건 |
| 그 후속이 실제로 수행됐다 — 그리고 게이트는 거부했다 | 후속 실검정의 수행과 게이트의 거부 |

## 이 저장소에서의 예외 (규격보다 우선한다)

1. **판정 서술은 CLAUDE.md §0.8 문구 사전과 `paper/verdicts.yaml`이 우선한다.** 두 문서가 허용한
   문구는 어체를 이유로 고치지 않는다. 문체 규격과 충돌하면 **판정 문구를 남기고 주변 문장을
   고친다.**
2. **표 셀의 문구는 산문 소스에서 고치지 않는다.** 표는 동결 전문에서 문자 단위로 복사되며
   (`scripts/build_submission_stage3.py`), 셀 치환은 같은 스크립트의 `CELL_FIXES`로만 한다
   (CLAUDE.md §2.3). **T6 이 표 셀을 검사 대상으로 넣었어도 이 경로는 바뀌지 않는다** —
   위반을 파생본에서 직접 고치면 수치를 손으로 옮겨 적는 일이 되살아난다(§1-1). 어체 치환도
   `CELL_FIXES` 의 수치 불변 검사를 그대로 통과해야 한다.
3. **수식·코드·식별자·서지 항목은 검사 대상이 아니다.**
4. **금지 표현의 언급(mention)은 사용(use)이 아니다.** 규격이 금지한 낱말을 *"이 표현은 쓰지
   않는다"* 형태로 인용하는 것은 위반이 아니며, 검사기는 따옴표·백틱 안을 세지 않는다.
5. **행 단위 면제**가 필요하면 그 행 끝에 `<!-- style-ok: 사유 -->`를 붙인다. 사유 없는 면제는
   두지 않는다.

## 검사기가 보는 것과 보지 못하는 것

`scripts/style_check.py`(= `make style-check`)는 **S3 · T2 · T3 · T5 · T6 · T7 · H1 · V5 · V6 · V7 · X1 · X2**
을 기계로 본다. `scripts/check_glossary.py`(= `make glossary-check`)는 **V1·V2 의 등재 용어 부분**
(정의 선행 G1 · 약어 선행 G2 · 동의어·다의어 G5 · 식별자 산문 G4 경고)을 본다.
**S1 · S2 · S4 · T1 · T4 · V3 · V4 와 V1·V2 의 나머지는 사람이 지킨다.** 검사기 통과는 규격 준수의
필요조건이지 충분조건이 아니다 — `make verdicts`가 판정 강도의 표류를 막듯, 이 검사기는
**어체의 표류**만 막는다.

## 회귀 점검 — 어체 변환이 내용을 손상시키지 않았는가 (v2 신설)

어체 변환은 **문장을 분할하고 서술어를 교체하는 작업**이므로 고유한 손상 유형을 갖는다.
v1 적용에서 실제로 두 건이 발생했다 — 문장 분할이 주어–술어 호응을 깨뜨린 사례와, 절 이동
과정에서 표 번호가 중복된 사례이다. 변환 커밋마다 아래 넷을 확인한다.

1. **주술 호응** — 분할한 두 문장 각각에 주어와 술어가 있는가. 뒷문장이 앞문장의 목적어를
   주어 없이 이어받으면 비문이다. 그런 자리는 분할이 아니라 **병합**으로 고친다.
2. **번호 정합** — 표·그림 번호와 본문 참조(V6). `make style-check`가 캡션을 검사한다.
3. **수치·인용·판정 문구 불변** — `make verdicts` · `make sig-check` · `make submission-check`.
   어체 변환은 이 셋을 하나도 움직이지 않는다. 움직였다면 그것은 문체 작업이 아니다.
4. **면제 주석의 사유** — 새로 붙인 `<!-- style-ok -->`에 사유가 적혀 있는가. 사유 없는 면제는
   규칙을 끈 것이지 예외를 둔 것이 아니다.
