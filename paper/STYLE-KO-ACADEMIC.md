# 한국어 학술 논문 문체 규격 v1 (2026-08-16 · 사용자 승인)

> **적용 범위는 "내용 보존 + 어체 변환"이다.** 이 규격은 **문장을 어떻게 쓰는가**만 정한다.
> 수치·판정·기여 목록·장 구성·논리 전개는 이 규격으로 바꾸지 않는다. 규격을 적용한 결과로
> 판정 문구가 흔들리면 그것은 문체 개선이 아니라 CLAUDE.md §1-2 위반이며, `make verdicts`가
> 차단한다. 규격 적용 커밋은 **`make verdicts` · `make sig-check` · `make submission-check`가
> 전부 통과한 상태에서만** 성립한다.
>
> **강제 대상 (기계 검사 `make style-check`)** — 투고 파생본 계열:
> `paper/manuscript/stage3_source.md`(산문 소스) · `paper/submission/**/*.md`(조립 산출물).
> **대상 아님** — 작업 정본 `paper/논문_v0_9_SDKB_통합초안.md`와 `paper/supplementary/`.
> 이 둘은 **감사 기록**이므로 과거 문장을 소급해 다듬지 않는다(`submission_check.py`가 정본을
> 대상에서 제외하는 것과 같은 이유). 다만 **정본에 새로 쓰는 문단은 이 규격을 따른다.**

## 구조 규칙 (가독성의 원천)

**S1 · 문단 구조.** 각 문단은 [주제문 → 근거·전개 → 소결]로 구성한다. 문단의 첫 문장만 이어
읽어도 절 전체의 논리가 따라가지도록 한다.

**S2 · 한 문장 = 한 명제.** 접속 절은 최대 2개(원인–결과, 대조 등)까지만 허용한다.

**S3 · 문장 길이 상한 90자**(공백 포함). 초과 시 분할한다. — *기계 검사 대상*
길이는 **한국어 산문의 부담**만 센다. 서지 인용 `(Lupu & Hanbury, 2013)`과 원어 병기
`(competency question, CQ)`처럼 괄호 안이 영문·숫자 위주인 삽입구는 길이에서 제외한다.
V1이 요구하는 원어 병기가 S3 위반을 만들면 두 규칙이 서로를 무효화하기 때문이다.

**S4 · 전개 순서는 일반 → 구체.** 넓은 배경 → 대상 문제 → 기존 한계 → 연구 공백 → 본 연구의
접근 순으로 전개한다.

## 어체 규칙 (학술 레지스터)

**T1 · 서술어는 격식 문어체.** `~하였다 / ~한다 / ~할 수 있다 / ~로 나타났다 / ~가 요구된다 /
~를 제안한다`를 쓴다. 단언형 단문의 연쇄와 도치문은 쓰지 않는다.

**T2 · 은유·구어 표현 금지.** 학술 동사로 치환한다. — *기계 검사 대상*

| 금지 | 치환 |
|---|---|
| 망가뜨린다 · 깨뜨린다 | 훼손한다 · 저해한다 |
| 건진다 · 건져 올린다 | 회수한다 |
| 잰다 · 재 본다 | 측정한다 · 평가한다 |
| 아프다 · 뼈아프다 | 심각하다 · 중대하다 |
| 뒷걸음친다 | 저하된다 |
| 갈아 끼운다 | 교체한다 |
| 좋아진다 · 나빠진다 | 향상된다 · 저하된다 |
| 새어 나간다 | 유출된다 · 전파된다 |
| 꽂아 넣는다 | 적용한다 · 결합한다 |
| 넘겨 짚는다 | 과잉 일반화한다 |
| 붙잡아 둔다 | 제약한다 · 근거로 고정한다 |
| 쓸모 | 유용성 |
| 지어낸다 | (사실과 다른 내용을) 생성한다 |
| 헐거워진다 | 완화된다 |

**T3 · 문단 간 연결은 표준 학술 연결어만.** `그러나 / 따라서 / 이러한 / 특히 / 반면 / 더욱이 /
요컨대`를 쓴다. `그래서 · 그런데 · 하지만`은 쓰지 않는다. — *기계 검사 대상*

**T4 · 주어를 생략하지 않는다.** 연구 주체는 **"본 연구는 / 본 논문은"** 으로 통일한다.

**T5 · 볼드는 정의된 핵심 용어의 최초 등장에만.** 주장 문장에는 볼드를 쓰지 않는다. 주장은
논거로 강조한다. — *기계 검사 대상(볼드 안에 종결어미가 있으면 위반)*

## 용어 규칙 (이해 용이성의 원천 — 풀어쓰기는 여기서 한다)

**V1 · 최초 등장 1회만 정의.** `한글 풀이(영문 원어, 약어)` 형식으로 적는다. 예: 교차 태스크
회귀(cross-task regression), 즉 한 태스크를 위한 변경이 다른 태스크의 질의 경로를 훼손하는 현상.

**V2 · 정의 이후에는 동일 용어만.** 동의어 교체를 금지한다(일/태스크 혼용 금지 → 태스크로 통일).

**V3 · 지표·게이트 명칭은 번역·의역하지 않는다.** `L0–L3` · `T1–T4` · `Recall@100` · `nDCG@20` ·
`EP1–EP4` · `A1–A8` · `B0–B5` · `P0–P2` · `qrel` · `SHACL` · `T-Box`/`A-Box`가 여기 해당한다.

**V4 · 이해를 돕는 장치는 문장 단순화가 아니라** (a) 정의문, (b) 구체 예시 1개, (c) 절 첫머리의
로드맵 문장으로 제공한다.

## 이 저장소에서의 예외 (규격보다 우선한다)

1. **판정 서술은 CLAUDE.md §0.8 문구 사전과 `paper/verdicts.yaml`이 우선한다.** 두 문서가 허용한
   문구는 어체를 이유로 고치지 않는다. 문체 규격과 충돌하면 **판정 문구를 남기고 주변 문장을
   고친다.**
2. **표 셀의 문구는 산문 소스에서 고치지 않는다.** 표는 동결 전문에서 문자 단위로 복사되며
   (`scripts/build_submission_stage3.py`), 셀 치환은 같은 스크립트의 `CELL_FIXES`로만 한다
   (CLAUDE.md §2.3).
3. **수식·코드·식별자·서지 항목은 검사 대상이 아니다.**
4. **금지 표현의 언급(mention)은 사용(use)이 아니다.** 규격이 금지한 낱말을 *"이 표현은 쓰지
   않는다"* 형태로 인용하는 것은 위반이 아니며, 검사기는 따옴표·백틱 안을 세지 않는다.
5. **행 단위 면제**가 필요하면 그 행 끝에 `<!-- style-ok: 사유 -->`를 붙인다. 사유 없는 면제는
   두지 않는다.

## 검사기가 보는 것과 보지 못하는 것

`scripts/style_check.py`(= `make style-check`)는 **S3 · T2 · T3 · T5** 만 기계로 본다.
**S1 · S2 · S4 · T1 · T4 · V1–V4는 사람이 지킨다.** 검사기 통과는 규격 준수의 필요조건이지
충분조건이 아니다 — `make verdicts`가 판정 강도의 표류를 막듯, 이 검사기는 **어체의 표류**만
막는다.
